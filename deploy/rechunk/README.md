# bge-m3 토큰 기반 문맥 청킹

현재 v003를 수정하지 않고 v3.1 전체 195문서에서 시험하는 독립 구현이다. 기존 파싱·비전 채택 결과·문서 보강을 재사용하며 검색 규칙이나 정답표를 읽어 청크를 만들지 않는다.

## 규칙

- **길이:** 설치된 bge-m3의 동일한 `tokenizer.json`으로 계산한다. 본문 + 문서명·메타데이터·제목·위치·필요한 표 머리글 + 특수 토큰의 합이 최대 600토큰이다. 목표 하한은 400이며 의미가 다른 내용을 붙여 하한을 채우지 않는다.
- **공통 단위:** 검증된 공통 블록의 원문 범위를 사용한다. 문단·표 행·로그 한 줄을 우선 유지한다. 기존 1,200자 경계만을 이유로 끊지 않는다. 실제 자료에서 단일 블록을 추가 분할한 건수는 0이다.
- **슬라이드·PDF:** 같은 페이지의 제목·본문·표·총액을 연결한다. 연속 페이지의 동일 제목 또는 `계속` 제목을 연결할 수 있다. 제목에 `사업 이해/현황/제안 목표/제안 아키텍처`가 명시되면 기술 구역으로, `추진 일정/투입 인력/제안 금액`은 수행 계획 구역으로 연결한다. 표지·목차, 회사 소개는 구분한다. 이 규칙은 제목의 구조적 단서이며 LLM의 의미 판단이나 질문 ID별 규칙이 아니다. 불분명한 제목은 페이지 경계를 유지한다.
- **계약서·설계서 등:** 명시된 장·절·조항 경계를 유지한다. 제목이나 초안 배너만 있는 구역은 다음 내용에 붙인다. 독립된 계약 조항끼리는 400토큰을 채우려고 합치지 않는다.
- **표·스프레드시트:** 시트 경계를 유지하고 설명·표 행을 함께 담는다. 행을 통째로 이동하고, 표가 다음 청크로 이어질 때 머리글을 문맥에 넣는다. 하나의 표 행만으로 한도를 넘으면 정확한 원문 위치를 유지해 분할하고 예외로 기록한다.
- **로그:** 날짜·시간 기준 5분 구간 경계를 유지하고 온전한 줄을 묶는다. 시간 없는 후속 줄은 직전 시간 구간에 속한다. 5분을 넘는 전체 작업이 반드시 하나의 청크에 들어가는 것은 아니다.
- **RTF 진단 덤프·설정 파일·일반 텍스트:** 기존 구조에서 식별된 제목·구역을 보존하면서 줄·문단 단위로 토큰 한도까지 묶는다. 아주 긴 단일 블록은 문장/줄, 공백 순으로 분할하며 원문 오프셋을 보존한다. 복잡한 설정 언어의 전체 의존 관계를 의미적으로 증명하는 파서는 아니다.
- **이미지:** 채택된 공통 블록에 이미 있는 추출 내용만 재사용한다. 제목과 이어지는 내용은 연결하되 서로 다른 문서의 이미지 내용을 합치지 않는다.
- **중첩:** 고정 120자 중첩을 쓰지 않는다. 제목·문서 정보·필요한 표 머리글을 문맥으로 반복한다. 단순 중복 본문을 추가하지 않는다. 원래 비전/네이티브 결과에 이미 있던 중복을 이번 단계에서 임의로 삭제하지 않는다.
- **기존 보강:** 의미 보강 31개는 기존 원문 발췌·요약 청크와 입력 그대로 유지한다. 짧다고 새 요약을 만들지 않는다.

`chunker.py`의 `Chunker.run(record, blocks)`가 일반 청킹 진입점이다. `record`는 출처·규칙 메타데이터·원문 범위가 있는 기존 청크 레코드, `blocks`는 문서별 공통 블록 사전이다. 새 자료에도 적용할 수 있으나 모든 형식의 의미 경계를 자동으로 이해한다고 보장하지 않는다.

## 파일과 검사

- `prepare.py`: 195문서 재청킹, 모든 기존 원문 범위 보존·본문 재구성·출처 위치·토큰 한도 검사. 실제 모델 토크나이저로 기존 3,754개 입력의 토큰 수를 재현한다.
- `test_chunker.py`: PDF/PPT 페이지 연결, 표·총액, 제목 배너, 계약 조항, 스크린샷, 시트, 로그 행, 긴 Unicode 블록 오프셋 검사.
- 기존 `outputs/indexing-v31-001/embed_bge.py`: Orin의 bge-m3 / CLS / L2 / FP16 설정을 그대로 사용한다. 텍스트·모델 해시가 동일한 벡터만 재사용한다.
- `export.py`: 기존 문서 메타데이터·문서군·버전·분석기 설정을 고정하고 새 청크 링크만 갱신한다. 로컬·Orin 토큰 수 전수 일치를 요구한다.
- `load_index.py`: 전용 `rag-search-documents-v004-rechunk` / `rag-search-chunks-v004-rechunk`만 생성한다. 저장 레코드 전수 비교, 기존 v001/v002/v003 건수 보존 확인. 기존 문서 덮어쓰기·삭제 없음.
- 기존 `deploy/search/evaluate_dataset.py`: 정답이 없는 150개 질문 입력만 검색 서버에 보낸다. 기존·후보는 같은 search-1.7.4 / B+R1 / 질문 분석 ON 2.5초 / 원문 대조 OFF로 비교한다.
- `compare.py`: 평가가 완료된 뒤에만 정답과 대조하고 CSV·JSON·Markdown·HTML을 만든다. 순위가 떨어져도 검색 규칙을 자동으로 바꾸지 않는다.

작업 산출물: `outputs/rechunk-v31-001/`. 이전 두 문서 시범 `outputs/rechunk-d001-d002-001/`도 보존했다. 완료된 준비·내보내기·평가는 덮어쓰기를 거부한다. 재실험은 새 출력 경로와 색인 이름을 지정한 별도 버전으로 한다.
