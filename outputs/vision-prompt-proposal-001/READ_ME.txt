비전 파싱 프롬프트 수정 제안 — 2026-10-19

상태: 제안 초안. 기존 실행 지시·스키마·응답·검증기·검색 색인을 바꾸지 않았다.
추가 유료 호출, 모델 재호출: 0건. 수정안의 효과는 아직 측정하지 않았다.

original-system-prompt.txt: 실제 실행 manifest에 저장한 system 지시 전문.
original-response-schema.json: 실제로 함께 요청한 JSON 양식.
original-user-context-example.json: D-001 2쪽에 함께 보낸 원문 위치와 네이티브 문맥.
  실제 요청에는 해당 페이지 이미지도 들어간다. 이 파일에는 이미지 본체는 넣지 않았다.
proposed-system-prompt.txt: 다음 시험을 위한 수정안. 기존 양식을 유지한다.
verification.json: 동결 코드의 지시와 manifest 일치, 대표 3요청의 재구성 해시 일치 확인.

이해할 점
1. 기존에도 표/노드 중복 금지와 원문/설명 분리 지시는 있었다. 모델이 항상 지킨 것은 아니다.
2. 기존 1번의 '페이지 전체를 texts에'라는 넓은 지시와 6번의 노드 제외 조건은 함께 해석해야 했다.
   혼동 가능성을 줄이기 위해 수정안에서는 처음부터 위치별 저장 칸을 나눈다.
   이것이 실제 실패 원인이라고 확정한 것은 아니다.
3. 표/구성도 통째 반복을 막는 기준, 실제 별개 위치의 같은 내용은 보존하는 예외를 명시한다.
4. 그림 설명을 없애지 않는다. 사진/차트의 의미와 관계는 설명에 남기되 원문 목록을 다시 쓰지 않는다.
5. known/blank/unreadable과 complete/partial의 관계를 명시한다.
6. 기존 문서 ID 생성 금지 문장을 명확히 한다. 스키마상 필요한 노드 내부 ID는 생성해야 한다.
7. 엄격한 JSON 양식은 필드·자료형을 정하는 역할이며, 중복·오독·의미 정확도를 보장하지 않는다.

수정안은 기존보다 길다. 장황한 지시가 오히려 따르기 어려워질 가능성도 있으므로 효과를 보장하지 않는다.
실제 문서의 정답이나 D-001 같은 문서별 예외는 프롬프트에 넣지 않았다.

추후 유료 시험을 요청받았을 때의 비교 방법
- 같은 이미지·문맥·모델·제공자·JSON 양식·생성 설정에서 프롬프트만 바꿔 비교한다.
- 반복이 줄었는지와 함께 원문·표·연결·시각적 의미가 더 빠지지 않았는지 확인한다.
- 정상 사례도 포함한다. 같은 글자가 서로 다른 위치에 실제로 있는 경우를 잘못 지우지 않아야 한다.
- 이미 실패를 본 자료에서 지시를 개선한 것이므로 개발용 비교다. 이후 별도 자료 검증이 필요하다.
- 생성 설정 변경 실험은 프롬프트 변경과 구분한다. 한꺼번에 바꾸면 무엇이 영향을 줬는지 알기 어렵다.
- 검증기 통과 수만으로 개선을 판단하지 않는다. 저장된 이전 응답은 새 프롬프트의 효과를 시험할 수 없다.
