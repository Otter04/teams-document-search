# v2 원본 변경·정답 변경·재사용 검토

2026-10-22. 원본 파일·기존 색인 산출물·v2를 읽기 전용으로 비교했다. 기존 인덱싱 산출물이 기록한 SHA256과 이전 원본110개가 모두 일치함을 먼저 확인했다. 생성기 실행, 추가 인덱싱, 모델 API 호출, 정답 수정은 하지 않았다.

## 1. 77개 파일은 무엇이 달랐나

| 구분 | 파일 수 | 비교 결과 |
|---|---:|---|
| 완전히 동일 | 33 | 원본 SHA256까지 동일 |
| PPTX 저장 포장 정보만 변경 | 21 | 압축 해제한 모든 파일·슬라이드·이미지·관계·노트가 바이트 단위로 동일 |
| XLSX 내부 시각만 변경 | 23 | docProps/core.xml의 created/modified만 변경. 셀·수식·병합·서식·이미지 등 나머지 구성요소 동일 |
| PDF 내부 정보만 변경 | 7 | 추출 문자·페이지 내용 스트림·전 페이지144dpi 픽셀 동일. 생성 시각·문서ID·체크섬 등 내부 정보 차이 |
| 본문이 실제 변경 | 26 | DOCX13 + PDF13. 모두 계약번호 줄에 계약구분 추가 |

**즉, 달랐던77개 = 내부 정보만 변경51개 + 본문 변경26개. 전체110개 중 내용 동일84개다.**

PDF20개는73페이지 쌍을 전부 렌더링해 비교했다. 본문 변경 PDF13개는 각각1페이지만 달랐고 나머지 페이지는 픽셀까지 동일했다. 이 중 스캔2개는 텍스트 추출이 비어 있어 화면 대조로 확인했다. PPTX/XLSX는 전체 압축 구성요소 비교이므로 단순 텍스트만 같다고 판정한 것이 아니다.

## 4. 기존 결과를 재사용할 수 있는가

**가능하다. 전체110개를 다시 모델에 넣을 필요는 없다. 다만 그대로 복사하는 것이 아니라, 재사용 출처와 새 파일의 연결을 검증해야 한다.**

| 기존 산출물 | 재사용 판단 | 이후 필요한 작업 |
|---|---|---|
| 내용 동일84문서 | 본문 파싱·검수된 의미 결과 재사용 가능 | 새 원본 해시와 위치·근거 연결 확인, 관측 수정일 갱신 검토 |
| 본문 변경26계약서 | 바뀌지 않은 부분은 재사용 가능 | 계약구분 한 줄을 반영하고 관련 블록·필드·청크 갱신 |
| LLM 의미 보강17문서 | 17개 모두 내용 동일 문서에 해당 | 원문 근거 참조를 새 식별자에 연결하고 입력 일치 확인 |
| 비전121장 | 119장 원문·구조 결과 재사용 후보 | D-044·D-102 첫 페이지2장만 추가 문구와 위치를 교정·검수. 원응답은 보존 |
| 임베딩1,089개 | 내용 동일84문서에 속한725개는 재사용 후보 | 최종 입력 문자열+모델 해시가 동일할 때 벡터 재사용 |
| 변경26문서에 속한364개 벡터 | 전부 재생성해야 한다는 뜻은 아님 | 새 청크 입력을 기존 입력과 비교해 달라진 것만 재생성 |

비전2장의 새 문구는 이번에 이미 직접 읽어 확인했다. 이를 근거로 별도 수정본을 만들면 전체 비전 재호출 없이도 대응할 수 있다. **현재 수정본을 색인에 적용한 것은 아니다.** 기존17개 LLM 보강과 기존 비전 결과의 생성 모델·실행 이력은 원래 기록을 유지한다. 재사용한 결과를 새 Orin 호출 결과로 기록하면 안 된다.

현재 블록ID·이미지ID에는 원본 해시가 들어가므로77개 파일의 새 해시만 바꾸고 기존 근거 참조를 그대로 두는 것은 안전하지 않다. 구·신 원본의 동등성 기록과 ID 연결표를 만든 뒤 모든 참조를 검증해야 한다. 복사본 묶기·문서 버전 그룹도 새 파일 해시에 맞춰 재확인한다.

### 수정일은 별도 처리

로컬 파일시스템 수정시각은110개 모두 달랐다. 또한 XLSX 내부 created/modified와 PDF CreationDate는 문서가 재생성될 때 바뀌는 값이다. 이들을 표지일·작성일·계약일로 대신하면 안 된다. v2에서 실제 관측한 파일 수정시각은 출처와 함께 수집하되, 재생성/복사 시각이 본문 수정의 증거는 아니라는 사실을 구분한다. 현재 색인의 날짜를 이번 감사에서 바꾸지 않았다.

## 5. 추가 자료 인덱싱 전 준비할 것

추가48파일 중 첨부 라벨이 색인 대상으로 지정한 것은45개이고, 펌웨어BIN·압축TGZ·도구ZIP3개는 제외 대상이다. 기존110 + 추가45 = 향후155문서가 목표다.

| 새45개 중 | 개수 | 현재 상태 |
|---|---:|---|
| 기존 파서 분기 지원형식 | 19 | PPTX9·PDF3·DOCX1·LOG3·XLSX3. 형식 지원일 뿐 파싱 성공을 미리 보장하지 않음 |
| 신규/별도 입력 연결 필요 | 26 | HWPX6·INI4·RTF2·확장자 없음2·JPG8·PNG4 |

추가 사진12장뿐 아니라 교육PPT 안의 캡처·그림도 비전 처리 범위로 확인해야 한다. 기존 비전 모델·검증기는 재사용하되 새 이미지의 추출 결과 자체는 새로 만들어야 한다. 매뉴얼·납품·장비설정·사진·선번목록 유형과 출처 위치를 기존 공통 블록/메타데이터 체계에 연결해야 한다.

사용자가 나중에 실행을 요청하면 권장 순서는 다음과 같다.

1. 현재110개 색인·99개 평가·원본 응답을 보존하고, 이번 대조 결과를 기준으로 변경26개와 추가45개 처리 범위를 고정한다.
2. 새 형식 처리와 새 문서종류 메타데이터 규칙을 보완한다.
3. 내용 동일84개와 의미 보강17개·비전119장을 재사용하고, 계약서 변경부와 새 자료만 처리한다.
4. 최종 임베딩 입력이 같은 벡터는 재사용하고, 변경/신규 입력만 bge-m3로 생성한다.
5. 별도 버전의 Elasticsearch 색인을 준비해155문서와 근거 연결을 검증하고, 기존99개 및확장125개를 구분해 평가한다.

**현재는 위 인덱싱을 실행하지 않았다.** 기존 서버·색인·모델 설정과 평가 정답은 변경하지 않았다. 이번 결과는 재사용 가능성 감사이며 v2 검색 성적이나 신규 파싱 성공률이 아니다.
