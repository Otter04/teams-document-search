# 작업명·핵심 필드·로그 문맥 개선 평가

작성: 2026-10-18. 같은 질문·데이터·비교 기준일(2026-10-17)을 사용했다. 모델·유료 API 호출 없음.

**Q-020의 전환 로그가 2위에서 1위로, Q-032에서 빠졌던 서버구성 문서가 8위에서 3위로 올라왔다.** Q-032의 정답 3개를 상위 5개에서 모두 찾았다. 전체 61개 질문의 첫 정답 순위·정답별 순위·상위 5개 정답 회수율에 악화가 없다.

## Q-020의 정답과 과거 순위가 뜻하는 것

질문은 계속 **“TMS 전환 작업 로그”**로 같았다. 정답 라벨은 **D-036, `deploy_20250913_tms-app01.log`**다. 경로는 `sites/운영팀/Shared Documents/다온/운영로그/2025-09/deploy_20250913_tms-app01.log`이다.

로그 2행에 다음 내용이 실제로 들어 있다.

```text
[2025-09-13 22:01:42] target: TMS_MIGRATION_CUTOVER / system: TMS
```

거래처는 다온로지스, 대상 시스템은 TMS, 작업명은 `TMS_MIGRATION_CUTOVER`다. 전환 작업을 기록한 이 로그가 목표 문서이며, TMS 백업 로그 D-037과 구분해야 한다.

| 검색 구현 버전 | 같은 정답 D-036의 위치 | 의미 |
|---|---:|---|
| 최초 키워드 기준선 (`native-search-run-002`) | 5위 | 제안서·계약서·견적서 4개 뒤에서 발견 |
| 한영 표현·날짜 해석 추가 (`rule-search-run-004`) | 6위 | 다른 문서 5개가 앞서 상위 5개에서 제외 |
| 문서 종류·대상 시스템 조건 추가 (`condition-search-run-001`) | 2위 | TMS 실행 로그로 좁혔지만 백업 로그 D-037이 앞섬 |
| 이번 표현·필드·문맥 개선 (`field-search-run-002`) | **1위** | 전환 로그 D-036이 백업 로그보다 먼저 나옴 |

‘순위’는 검색 결과를 관련성 점수로 정렬한 **문서 목록의 위치**다. 청크 번호, 정답 확률, 평가 회차를 말하는 것이 아니다. 이 질문은 정답이 하나이므로 5위까지는 Hit@5 성공, 6위는 실패다.

**‘한영·날짜’는 질문 종류가 아니라 기능을 추가한 검색 버전의 줄임말**이다. 한영 표현 연결은 한국어와 영어의 같은 뜻을 규칙으로 연결하는 것이고, 날짜 처리는 질문에 적힌 연도·월·기간을 문서 날짜 조건으로 해석하는 것이다. Q-020에는 날짜 표현이 없으므로 그 버전에서 날짜 필터는 실제로 적용되지 않았다. 같은 질문도 검색 토큰과 점수 계산에 쓰는 통계가 바뀌면 상대 순위가 달라질 수 있다. 날짜 조건 때문에 6위가 됐다고 해석하면 안 된다.

## 무엇을 구현했는가

| 작업 | 실제 처리 | 출처 보존 |
|---|---|---|
| 작업명·핵심 필드 가중치 | 작업명·역할·식별자 일치를 일반 본문 일치보다 강하게 반영 | 일치한 값과 블록/셀 위치를 결과에 기록 |
| 로그 문맥 연결 | 로그 각 청크가 같은 문서의 작업명·시스템을 함께 검색할 수 있게 연결 | 원문과 별도 `linked_log_context`, 468개 청크 |
| 필요한 표현 연결 | 작업 로그의 ‘전환’↔CUTOVER, ‘자동으로 서버 늘림’↔오토스케일링 | 명시적 규칙, 모델 추론 없음 |
| 식별자 보호 | 서버명 내부 `db`를 일반 DB 개념으로 과확장하여 가산하지 않음 | 정확한 전체 서버명 일치는 유지 |

예를 들어 로그 뒷부분에 작업명 없이 성공/실패만 있어도 별도 문맥에서 이 청크가 어느 작업의 기록인지 연결할 수 있다. 원문에 없는 사실을 새로 써 넣지는 않는다. 가중치·점수식·실행 명령은 [구현 설명](../rag-field-search-v1/README.md)에 있다.

## Q-032의 세 정답

질문: **“수강신청 몰릴 때 자동으로 서버 늘리는 구성”**

| 정답 문서 | 기존 순위 | 이번 순위 |
|---|---:|---:|
| D-054 · `제안서_학사정보시스템 클라우드 전환_v1.0.pdf` | 1 | 1 |
| D-053 · `제안서_학사정보시스템 클라우드 전환_v1.0.pptx` | 2 | 2 |
| D-061 · `서버구성_학사정보시스템.xlsx` | 8 | **3** |

D-061의 `서버목록!B5`에 있는 실제 역할 값은 **`학사 웹 (오토스케일 그룹)`**이다. ‘자동으로 서버 늘림’을 오토스케일 표현과 연결하고, 단순 언급보다 실제 ‘역할’ 열의 값을 강하게 반영해 올라왔다. 세 정답 회수율은 **2/3 → 3/3**이다. 이는 정답 문서 회수 평가이며, 질문의 모든 의미 조건을 개별 근거로 완전히 검증했다는 뜻은 아니다.

## 기능별 효과를 분리한 실험

| 설정 | Q-020 순위 | Q-032의 D-061 순위 | 전체 1위 정답 질문 | 전체 5위 내 정답 질문 |
|---|---:|---:|---:|---:|
| 기존 | 2 | 8 | 56/61 | 60/61 |
| 필드 가중치만 | 2 | 8 | 58/61 | 60/61 |
| 로그 문맥만 | 2 | 8 | 55/61 | 60/61 |
| 가중치 + 문맥 | 2 | 8 | 58/61 | 60/61 |
| 추가 표현 연결만 | **1** | 8 | 57/61 | 60/61 |
| 전체 적용 | **1** | **3** | **59/61** | **60/61** |

가중치·문맥 두 기능만으로 두 목표가 달성된 것은 아니다. Q-020은 ‘전환–CUTOVER’ 표현 연결만으로도 1위가 됐다. Q-032는 시험한 설정 중 표현 연결과 필드 가중치를 함께 적용한 전체 설정에서 3위가 됐다. 로그 문맥의 독립적인 순위 향상 효과는 확인하지 못했고, 문맥만 적용하면 일부 순위는 악화됐다. 구현 완료와 성능 효과 입증을 구분한다.

## 전체 성능과 남은 범위

| 평가 지표 | 이전 | 이번 |
|---|---:|---:|
| 전체 Hit@5: 정답이 하나라도 상위 5개에 있는 질문 | 60/61 (98.36%) | 60/61 (98.36%) |
| 전체 Hit@1: 첫 결과가 정답인 질문 | 56/61 (91.80%) | **59/61 (96.72%)** |
| 전체 질문별 정답 회수율 평균 | 96.99% | **97.54%** |
| 전체 정답을 모두 상위 5개에서 찾은 질문 | 58/61 | **59/61** |

Hit@5와 정답 회수율은 다르다. Q-032는 이전에도 정답 두 개가 있어 Hit@5는 성공이었지만 정답 회수율은 2/3이었다. 이번에는 세 개를 모두 찾았기 때문에 회수율도 100%가 됐다.

‘네이티브’ 지표는 이미지 해석 없이 원래 파일 구조에서 본문을 얻은 정답 문서만 대상으로 한다. 네이티브 정답이 있는 질문 60개에서, 각 질문의 네이티브 정답 집합을 기준으로 다시 계산한다. 전체 정답 중 스캔 문서를 제외했으므로 전체 시스템 성능과 동일하지 않다.

- **Q-037**: D-069 스캔 구성도를 못 찾는 기존 실패가 남아 있다. 비전 처리 대기다.
- **Q-025**: 네이티브 정답 D-043은 1위지만 다른 정답인 스캔 D-044는 아직 못 찾는다. 따라서 전체 정답을 모두 찾은 질문은 59/61이다.
- 전체 검색 90% 목표는 통과했고, 혼합형 질문군은 여전히 4/5(80%)다.
- 문서 보강의 기존 메타데이터 불일치, 비전 모델 평가, 독립 자료에서의 일반화 검증, 운영 통합 완료를 의미하지 않는다.

## 악화 점검과 재현 증거

첫 실험 [field-search-run-001](../field-search-run-001/evaluation/summary.json)에서는 Q-038 `loan-db-dr01`의 내부 `db`가 데이터베이스 개념으로 과확장되어 관련 없는 백업 작업명에 보너스가 붙었다. 이 결과와 당시 구현을 보존했다. 식별자에는 정확한 값의 필드 일치만 적용하도록 고친 결과가 이 실행이다. 필드 가중치는 첫 실험 전 정한 값을 유지했다.

최종 실행에서는 첫 정답 순위, 개별 정답 순위, Hit@5, 정답 회수율에 악화가 없다. 개별 정답 순위가 바뀐 질문은 Q-008, Q-020, Q-032, Q-039, Q-061이며 모두 개선 방향이다. 모든 질문 비교는 [61개 질문 상세표](QUERY_COMPARISON.md)에 있다.

19개 단위 검사를 통과했다. 동일 검색 재실행 결과 일치, 기존 버전 점수·순위 재현, 필터 위반 0, 검색 중 외부 입출력 시도 0을 확인했다. 원본·기존 결과 해시 및 인용 위치 추가 검증은 [verification.json](verification.json), 재현용 입력·코드·결과 해시는 [provenance.json](provenance.json)을 참고한다.
