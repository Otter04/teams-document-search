# 모델 없는 표현·날짜 검색 개선 규칙

2026-10-17, 첫 개선 평가 전 고정.

기존 native-search-run-002의 문서 110개·청크 1,042개·메타데이터·원문 근거를 그대로 사용한다. 원본, 파싱, 보강, 청킹, 기존 검색 결과는 변경하지 않는다. 외부 API와 모델 호출은 하지 않는다.

## 표현 연결

운영 도메인의 수동 한영 사전을 질의와 색인 양쪽에 동일하게 적용한다. 원문은 그대로 두고 별도 concept 토큰으로 연결한다. 밑줄로 조합한 영문 식별자는 전체 토큰을 유지하며 구성 단어도 추가한다. 기술 번호·버전을 임의로 대체하지 않는다. DG 같은 약어에는 주변 용어 조건을 둔다. 일치한 용어·원문 범위를 기록한다. 동의어는 문서별 정답 가중치가 아니며, 이 사전은 기존 개발 세트·실패 관찰을 참고한 것이므로 독립 평가로 부르지 않는다.

## 날짜 및 명시적 결과 조건

기준일은 호출자가 YYYY-MM-DD로 명시한다. 이번 비교는 기존 평가와 동일하게 2026-10-17, Asia/Seoul을 사용한다. 절대 연/월/일, 올해·작년·지난해·재작년·내년, 이번 달·지난달·다음 달, 오늘·어제를 지원한다. 달의 끝과 윤년은 달력으로 계산한다.

로그 질문은 로그시작 필드의 해당 기간 포함 여부로 해석한다. 문서 작성일·계약 시작일·계약 종료일을 명시하면 해당 필드를 쓴다. 단순한 '2025년 유지보수 계약'은 기간인지 작성일인지 모호하므로 필터를 적용하지 않고 경고한다. 복수 날짜·범위 연결·부정·지원하지 않는 비교 표현도 추정하지 않고 보류한다. 날짜를 보류한 결과는 조건을 만족했다고 표시하지 않는다.

로그에 '실패한' 또는 '성공한'처럼 최종 결과를 명시한 경우만 실행결과 필터를 적용한다. '오류가 난'을 작업 실패로 확정하지 않는다. 보류 메타데이터는 필터값으로 사용하지 않는다. 조건 적용 뒤 결과가 없어도 필터를 몰래 완화하지 않는다. 적용한 필터·인식 구간·미처리 이유를 반환한다. conditions_verified=false를 유지한다. 이 값은 자연어 질문 전체 조건 검증과 답변 생성을 아직 하지 않음을 뜻한다.

## 비교 평가

기존 질문 61개를 동일하게 사용해 기존, 표현만, 날짜/명시 결과 조건만, 둘 다 적용의 네 경우를 비교한다. 전체 Hit@5와 MRR@10, 유형별 점수, 네이티브 정답이 존재하는 60질문의 네이티브 정답 Hit@5, 개선·악화 질의를 공개한다. 문서별 기대 필터와 답안은 검색기에 전달하지 않는다. 90% 기준은 그대로 유지한다. 질문 내용으로 만든 조건은 검색 결과와 함께 기록한다.

표현·날짜 파싱의 별도 경계/부정/연도 변경 검사는 수동 작성한 기능 회귀 검사다. 별도 사내 자료의 검색 품질 검증은 아니며, 전체 파이프라인 완료 판정도 아니다. 새로운 검색 결과가 잘못되면 실패도 그대로 보고하고 원인 없이 성적 맞추기용 조정은 하지 않는다.
