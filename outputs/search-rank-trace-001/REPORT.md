# 검색 단계별 청크 순위 표시

2026-10-20 · `search-1.2.0` · Orin 배포 및 실제 화면 검증 완료.

## 구현한 화면

사용자 요청대로 계산 과정·계산식 없이 검색별 청크 순위와 결합된 순위를 보여준다. 각 청크의 출처 문서명, 문서 ID·청크 ID, 페이지/슬라이드/문단/셀 위치를 함께 표시한다. ‘청크 내용 일부’를 펼치면 검색용 본문의 앞 180자를 볼 수 있다. 문서 열기 기능은 추가하지 않았다.

1. 키워드 검색 순위: 실제 BM25 후보 최대 50청크.
2. 의미 검색 순위: 실제 벡터 후보 최대 50청크.
3. 결합된 청크 순위: 중복 청크를 합친 전체 후보, 각 청크의 키워드·의미 검색 당시 순위. 점수와 계산식 없음.
4. 현재 R1 코드 기반 순위 조정 결과: 결합 상위 30청크의 조정 전후 순위. 별도 리랭커 모델을 도입한 것이 아니다.
5. 최종 문서 순위: 기존 문서·버전 묶기를 적용한 결과.

각 단계는 처음 5개를 보여주며 나머지 전체 순위를 펼칠 수 있다. 같은 문서에서 나온 여러 청크가 목록에 반복되는 것은 정상이며 문서별 결과와 구분한다.

작성일·수정일 등 날짜 정렬 요청에서는 결합 결과를 참고용이라고 표시한다. 4단계는 전체 일치 자료의 날짜순 청크이며, R1이나 결합 상위 후보만으로 최종 날짜 순위를 만든 것으로 설명하지 않는다. 작성일 미확인 제안서의 별도 목록은 유지했다.

## 실제 진행 상태 전달

`POST /search/stream`의 한 검색 실행에서 단계 완료마다 NDJSON 이벤트를 전송한다. 두 검색 분기는 병렬로 실행하고 각각 완료되는 대로 표시한다. 질의 분석 모델의 내부 사고 과정이나 생성한 설명이 아니라 실제 검색 산출물이다. 가짜 타이핑 지연은 없어서 빠른 질문에서는 여러 단계가 짧은 간격으로 나타날 수 있다.

완료 전에 연결이 끊기거나 오류가 발생하면 중간 결과라고 표시한다. 조건 확인이 필요한 질문에는 검색하지 않았음을 표시한다. 운영 질문과 단계 응답은 디스크에 저장하지 않는다. 고정 개발 평가 입력의 응답은 평가 폴더에만 보존했다.

## 실제 확인 예시

화면에서 ‘청람정밀 MES 고도화 계약서’를 검색했다.

| 동일 청크의 출처 | 키워드 순위 | 의미 순위 | 결합 순위 | R1 후 순위 |
|---|---:|---:|---:|---:|
| D-005 계약서 초안, D-005-C-d7faa41d8ba08a2d | 1 | 2 | 1 | 2 |
| D-006 계약서 서명본, D-006-C-d206a0915670b4a5 | 2 | 1 | 2 | 1 |

문서군으로 묶은 최종 1위는 D-006 서명본이었다. 계산식을 보여주지 않고 위 순위와 출처만으로 단계를 비교할 수 있다. [실제 화면](combined-ranks.png).

날짜 질문은 실제 API에서 `combined → date_order → complete` 순서를 확인했고 최종 1위 D-069를 유지했다. 부정 조건 질문은 `analysis → complete(needs_clarification)`로 종료하며 순위를 만들지 않았다.
