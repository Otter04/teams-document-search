버전: rules-0.1.0 · 공통 블록 입력: 1.0.0 · 보강 JSON: 1.0.0

## ‘네이티브 범위’란

파일 안에 저장된 글자와 구조를 직접 읽는 범위입니다. Word 문단, Excel 셀, PowerPoint 도형의 글자, 텍스트 PDF의 글자, TXT/LOG를 포함합니다. 스캔 이미지에만 있는 글자나 그림의 연결선·사진의 상황을 비전 모델로 해석한 결과는 포함하지 않습니다.

이번 보강에는 파일명·SharePoint 경로도 근거로 사용합니다. 따라서 스캔 계약서라도 파일명으로 문서종류와 ‘서명본’ 표기, 경로로 거래처를 확인할 수 있습니다. 하지만 본문 금액·기간은 이미지에서 읽기 전까지 대기입니다. 구성도에 저장된 ‘MES’라는 글자를 읽은 것과 장비 사이의 연결 관계를 이해한 것은 다른 작업입니다.

## 실행

Python 3.10 이상, jsonschema 4.25.1, openpyxl 3.1 이상이 필요합니다. `common-block-design`의 입력 검증기와 `rag-evaluator`의 값 정규화를 참조합니다. 파일 형식별 파서를 다시 실행할 필요는 없습니다.

```sh
python enrich.py \
  --parsed ../parsing-run-003/parsed.jsonl \
  --reference reference-data.json \
  --output ../new-enrichment-run

python evaluate.py \
  --parsed ../parsing-run-003/parsed.jsonl \
  --enriched ../new-enrichment-run/enriched.jsonl \
  --dataset '/path/to/RAG_예비데이터셋(클로드)' \
  --output ../new-enrichment-run/evaluation

python -m unittest discover -s tests -v
```

출력 폴더는 새 경로여야 합니다. 추출기는 `--dataset`을 받지 않으며 문서별 정답을 읽지 않습니다. 별도의 평가기만 gold 문서 라벨을 읽습니다. 제공된 거래처 사전에서 이름·별칭·폴더만 운영 입력으로 분리해 사용한 사실은 실행 이력에 기록합니다.

이 작업 환경에서는 번들 Python과 `PYTHONPATH=work/schema-deps`로 실행했습니다. 추가 유료 서비스나 모델 설치가 필요하지 않았습니다.

## 출력 구조

`enriched.jsonl`은 문서별 JSON, `pending-fields.jsonl`은 미확정·적용 제외 필드 목록, `provenance.json`은 입력·사전·규칙 해시와 실행 이력입니다. `evaluation/`에는 상태를 보존한 채점 결과가 있습니다.

필드 상태는 추출 완료, 비전 대기, 검토 대기, 네이티브에서 미발견, 적용 대상 아님으로 나눕니다. 값이 없으면 null입니다. 문서 전체에 비전 대기가 남아 있는지와 각 필드의 적용 범위는 별도로 기록합니다. **null을 N/A로 바꿔 ‘문서에 없음’으로 확정하지 않습니다.**

이전 평가기는 null을 N/A로 정규화하므로 이번 상태를 그대로 표현하지 못합니다. 새 평가기는 기존 정규화·비교 규칙을 재사용하면서 대기와 미발견을 유지합니다. 기존 엑셀이나 정답 파일을 덮어쓰지 않습니다. [필드별 CSV](../enrichment-run-001/evaluation/field-metrics.csv)는 이번 평가에서 새로 생성한 단순 결과 표입니다.

## 규칙의 한계와 후속 연결

- 지원하는 명시적 표식이 없는 값은 보류합니다. 금액의 한글 표기만 읽기, 계산으로 VAT 추정, 상대 날짜 계산, 계약유형 의미 추론은 하지 않습니다.
- ‘초안’ 계약서 끝의 날짜는 작성일인지 체결 예정일인지 불분명해 후보와 근거를 보존하고 검토 대기로 둡니다.
- 서로 다른 후보가 나오면 검토 대기로 둡니다. 동일한 원문 값의 반복은 같은 값으로 모읍니다.
- 정답 라벨과의 불일치는 결과를 바꾸는 신호가 아니라 원문 검토 대상입니다. 문서별 정답을 이용한 보정표는 없습니다.
- 사람의 수정값을 보존하는 저장 계층, 사본 묶기와 최신본, LLM 요약, 비전 응답 연결은 후속 작업입니다.
- 비전 결과를 추가하면 해당 문서의 보강을 다시 실행하고, 값의 충돌을 검토한 후 청크·색인을 갱신해야 합니다. 이번 버전은 비전 결과를 입력으로 받지 않습니다.

## 검증 기록

27개 회귀 검사가 통과했습니다. 실제 파싱 레코드와 합성 경계 사례를 사용해 잘못된 날짜·기간, 금액 뒤 쉼표·소수 금액, 다중 줄 문단, 거래처/시스템 충돌, 중간 ERROR 뒤 최종 SUCCESS, rollback 시작, 완료-with-warnings, 원문 외 claims, 스캔 대기, 적용 범위, 인용 변조, 결정적 재실행을 확인합니다. 이 테스트 수는 실제 문서 정확도를 대신하지 않습니다.

첫 실행의 누락을 수정하고 재평가했으므로 이번 예비 세트는 개발용 평가입니다. 정답을 보지 않은 독립 자료에서 일반화 성능을 확인한 결과가 아닙니다. 수정 경위와 원본 대조 결과는 실행 보고서에 기록했습니다.
