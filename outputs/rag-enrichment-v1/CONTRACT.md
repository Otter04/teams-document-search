# 규칙 기반 문서 보강 입출력·평가 규칙

작성일: 2026-10-16 · 버전: 0.1.0 · 범위: 네이티브 원문 + 파일명·경로 + 명시적으로 제공된 거래처 사전

이번 단계는 유료 API, 로컬 LLM, 비전 모델을 실행하지 않는다. 파싱 결과의 구조와 원문은 변경하지 않고 별도의 보강 결과를 만든다. 문서당 LLM 보강을 최종 구현한 것이 아니라, 검증 가능한 규칙을 먼저 구현하는 단계다.

## 입력

- `parsed.jsonl`: 공통 블록 1.0.0의 실제 `run_result`만 허용. 설계 예시·가상 모델 출력·추론 claims는 사용하지 않는다. 원문 블록, 셀, 위치, 원본 해시, 처리 단위 상태를 읽는다.
- `reference-data.json`: 거래처 정식명·별칭·폴더명과 대상시스템 어휘. 거래처 자료는 제공된 사전 `entities.json`에서 이 세 항목만 가져온다. gold 폴더에 있지만 정답 문서 라벨과는 다른 명시적 운영 입력이며 사용 사실과 해시를 공개한다. 사업별 정답·문서별 매핑·IP/호스트 추론은 사용하지 않는다.
- 추출 프로그램은 정답 `documents.jsonl`, 필수 문자열, 질의 정답을 읽지 않는다. 평가는 추출 파일 저장 후 별도 프로그램에서 수행한다.

## 출력

문서별 JSON 한 개를 JSONL 한 줄로 저장한다. `doc_id`, 원본 정보·해시, 파싱 레코드 해시, 규칙 버전, 처리 범위, `fields`, 보류 작업을 기록한다. 기존 채점 20개 필드와 채점 제외 `사업명`을 모두 제공한다.

각 필드는 `value`, `status`, `rule_id`, `evidence`, `candidates`, `reason`을 가진다. 원문 위치는 파싱 블록 ID와 원래 loc를 그대로 참조한다. 파일명·경로 근거는 source의 해당 속성을 가리킨다. 날짜는 YYYY-MM-DD, 로그 시각은 YYYY-MM-DD HH:MM, 금액은 쉼표 없는 정수 문자열이다. 시간대는 새로 추측하지 않는다.

| status | value | 뜻 |
|---|---|---|
| extracted | 문자열 | 명시적 근거와 규칙으로 값이 하나로 결정됨 |
| pending_vision | null | 필요한 정보를 이미지에서 더 읽어야 할 수 있음. 미해석 시각 단위가 있고 규칙으로 값이 결정되지 않음 |
| needs_review | null | 후보가 충돌하거나 형식이 잘못됐거나 의미 판정이 필요함 |
| not_found_native | null | 읽은 네이티브 범위에서 지원하는 규칙으로 찾지 못함. 문서에 정보가 없다는 판정이 아님 |
| not_applicable | null | 확정된 문서종류가 해당 메타데이터 필드의 적용 대상이 아님. 예: 계약서의 로그 종료 시각. 원문 정보 부재를 확인했다는 뜻은 아님 |

현재 규칙은 미발견을 `N/A`로 확정하지 않는다. 특히 pending을 N/A로 바꿔 정상공란으로 채점하거나 검색 필터에 쓰지 않는다. 이미 추출된 값이 있어도 문서의 비전 처리 대기는 별도로 유지한다. 스캔의 파일명에 있는 ‘서명본’은 파일의 상태 표기이며 실제 서명·날인을 확인한 의미가 아니다.

필드 적용 범위는 인수인계서의 대상 열을 따른다. 계약 관련 필드는 계약서, 금액·통화·VAT는 계약서/견적서/제안서, 견적유효기간은 견적서, 사이트는 구성도, 작업·로그시각·실행결과는 실행 로그, 오류코드는 실행 로그/기타 메모를 대상으로 한다. 견적번호는 메일 등에서도 언급되므로 종류로 제외하지 않는다. 문서종류가 미확정이면 임의로 적용 제외하지 않는다. 비전 대기 필드도 보수적 후보이며, 해당 값이 반드시 이미지에 존재한다는 뜻은 아니다.

서로 다른 후보는 임의의 우선순위로 덮어쓰지 않고 검토 대기로 남긴다. 같은 정규화 값의 근거는 합칠 수 있다. 규칙 추출 결과에는 사람의 확정값을 덮어쓰는 기능이 없다. 후속 저장 계층에서 사람의 수정값을 별도 유지·우선 적용해야 한다.

## 우선 구현 규칙

| 필드 | 허용 근거와 제한 |
|---|---|
| 문서종류 | 명시적인 문서 제목·파일명, 로그 형식, 점검 보고/메일·메모 표식. 본문에서 다른 문서를 언급했다고 종류를 바꾸지 않음 |
| 거래처 | 지정 SharePoint 거래처 폴더와 수신·고객·갑 등 명시적 당사자. 사전 별칭의 경계 일치. 공급자는 거래처에서 제외 |
| 문서일자 | 견적일자·작성일·메일 Date, 제안 표지 날짜, 계약 체결부의 독립 날짜, 로그 시작일·점검일. 초안 체결부의 날짜는 작성일/체결 예정일의 역할이 불분명해 검토 대기. 계약기간 시작일을 문서일자로 쓰지 않음 |
| 대상시스템 | Target system·대상 시스템·system 표기, 아니면 제목/파일명의 알려진 어휘. 본문에 언급된 연동 시스템은 제외 |
| 상태 | 파일명의 구분된 초안·최종·서명본 또는 명시적 문서상태. ‘최종 검수’ 같은 본문 표현은 제외 |
| 계약번호·견적번호 | 해당 번호 라벨, 견적 문맥의 번호. 외형만 비슷한 번호를 무작정 수집하지 않음 |
| 계약기간 | 명시적인 계약기간 문장에 있는 유효한 날짜 쌍. 문서 전체의 가장 이른/늦은 날짜를 사용하지 않음 |
| 금액·통화·VAT | 대표 계약금액·견적금액·제안금액 라벨의 같은 원문. 소계/단가/합계로 대표 금액을 대체하지 않음. 환율 변환·VAT 계산 없음 |
| 견적유효기간 | 유효기간 라벨의 명시된 날짜. ‘30일’처럼 기준일 계산이 필요한 표현은 이번 범위 밖 |
| 사이트 | 구성도의 설치 위치 라벨. 기존 메타데이터 스키마의 대상 범위에 맞춰 제안서 본문에 나온 설치 위치는 이 필드에 넣지 않음. 거래처 주소를 설치 위치로 바꾸지 않음 |
| 작업명·로그시각·실행결과 | 작업 헤더, 시작·종료 표식, 명시된 최종 결과. 중간 ERROR/WARN만 보고 최종 실패/경고를 단정하지 않음 |
| 오류코드 | 오류·경고 줄이나 관련 메모에 명시된 지원 형식. 여러 코드면 검토 대기. WARN에 코드가 있다고 최종 결과를 경고로 추정하지 않음 |
| 계약유형 | 명시적인 계약유형 라벨만. 사업명에서 용역·구매 등을 추론하지 않음 |
| 사업명 | 건명·관련 사업·계약의 명시적 사업 표기. 자유 텍스트로 별도 보관, 채점 제외 |

3줄 요약, 사본 묶기, 최신본, 이미지 의미 보강은 이번 실행에서 미실행이다. 비전 처리 대기는 원래 단위 ID·위치와 연결한다. 나중에 비전 결과가 들어오면 해당 문서의 보강 결과를 재계산하고, 충돌을 검사한 뒤 청크·색인을 갱신하는 방식으로 연결한다.

## 평가 기준 — 첫 정답 비교 전 고정

현재 데이터셋은 규칙 개발에 사용하는 합성 예비 세트다. 원문 양식을 보고 규칙을 작성하며 독립 시험 세트 성적이라고 부르지 않는다. 정답 자체도 생성 스크립트가 만든 라벨이므로 충돌은 원문 근거와 함께 별도로 보고하고 원본 정답을 고치지 않는다.

1. 문서 110개와 모든 필드의 출력 존재, 스키마·참조·인용 일치 100%. 입력·정답·규칙·사전 해시를 보관한다.
2. **채운 값의 정확도** = 정답과 일치한 값 / 정답이 있는 평가 대상에 채운 모든 값. 정답 N/A에 채운 값도 오답이다. 값이 없는 대기는 이 분모에 넣지 않으므로 다음 지표를 반드시 함께 본다. 초기 기준 ≥95%, 금액·통화·VAT·번호·기간·최종 실행결과 등 중대한 오답 0.
3. **정답 값 회수율** = 일치한 값 / 정답에 실제 값이 있는 모든 필드. 대기·충돌·미발견도 분모에 남긴다. 전체·네이티브 글자가 있는 문서·글자가 없는 스캔을 나눠 보고한다. 이번 제한 구현에는 전체 회수율 통과를 선언하지 않는다.
4. **빈 정답 오기입률** = 정답 N/A에 값을 채운 건 / 정답 N/A인 모든 필드. 기존 기준 ≤2%를 참고하되, 미기입을 ‘없음 확인 완료’로 취급하지 않는다. 독립적인 의미상 환각 판정은 아니다.
5. 기존 인수인계서의 문서종류·거래처·날짜/금액/번호 정확도 ≥95%도 정답 값 회수 방식으로 별도 보고한다. 일부 필드를 보류해도 전단계 통과가 되지 않는다.
6. 상태별 수, 필드별 정확도·회수율, 오답과 대기 목록, 포맷별 결과를 공개한다. `needs_review`, `not_found_native`, `pending_vision`은 모두 미완료 상태이며 점수 100으로 대체하지 않는다.
7. 회귀 검사: 충돌, 잘못된 날짜, 부가세 포함/별도, 중간 ERROR 뒤 성공, 불완전 로그, 원문 외 claims 배제, 스캔 대기, 인용 위조 거부, 재실행 일관성, 정답 비의존성을 검증한다.

이전 평가기는 null을 N/A로 정규화하므로 상태를 보존하는 이번 보강 평가기를 사용한다. 기존 평가기의 정규화·대소문자/공백 비교 규칙을 재사용하되, 대기를 정상공란으로 확정하는 기존 입력 형식으로 억지 변환하지 않는다. 청킹·검색·비전 성능은 이 단계의 평가 대상이 아니다.
