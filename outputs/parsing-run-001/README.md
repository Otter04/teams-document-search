# 예비 데이터셋 파싱 결과

**이전 실험 기록:** 현재 이미지 처리 방향은 비전 LLM을 통한 의미·구조·맥락 추출입니다. OCR 관련 고려사항은 다음 설계에서 제외했습니다. [현재 방향과 다음 작업](../parsing-run-002/README.md#현재-설계-방향)을 따르며, 아래 수치는 당시 실험 결과로 보존합니다.

2026년 10월 14일, 제공된 예비 데이터셋 110건을 실제로 읽어 공통 JSON 블록으로 변환하고 기존 평가기에 연결했습니다. 파싱 단계의 다섯 지표는 전체 집계 기준을 충족했습니다. 스캔 문서의 글자 오독과 표 구조 복원은 개선이 필요합니다.

이번 단계는 파일마다 다른 구조를 제목·문단·표·슬라이드·시트 등의 단위로 추출하고, 내용과 원문 위치가 보존되는지 확인하는 과정입니다. 계약서·견적서 같은 의미상의 문서 분류는 문서 보강 단계에서, 검색용 길이로 나누는 작업은 청킹 단계에서 수행합니다.

## 처리 범위

| 파일 형식 | 문서 수 | 주요 결과 |
|---|---:|---|
| DOCX | 13 | 제목, 문단, 표의 행과 셀, 제목 경로 |
| PPTX | 21 | 슬라이드, 도형 텍스트, 표, 발표자 노트 |
| XLSX | 23 | 시트별 행, 셀 주소, 병합 셀 원점 |
| PDF | 20 | 페이지별 텍스트와 표 또는 OCR 글자와 좌표 |
| TXT | 8 | 문단, 줄 번호, 인코딩 |
| LOG | 25 | 로그별 줄 번호, 시각, 수준과 오류코드 후보 |

110건에서 최상위 블록 4,549개를 생성했습니다. 슬라이드와 OCR 페이지 내부 요소를 포함한 5,200개 요소의 위치 필드와 기본 좌표 범위를 검사했고 위반은 없었습니다. 이는 위치의 의미적 정확성을 전부 수동 검증했다는 뜻은 아닙니다. 원본 파일 해시는 실행 후에도 모두 일치합니다.

## 평가 결과

| 지표 | 실제 측정 | 평가 기준 | 판정 |
|---|---:|---:|---|
| 오류 없이 내용이 추출된 문서 | 110/110건, 100% | 99% 이상 | 통과 |
| 필수 문자열 보존율 | 344/346개, 99.42% | 98% 이상 | 통과 |
| 표 셀 정확도 | 표본 531/531셀, 100% | 95% 이상 | 통과 |
| 스캔 PDF 문자 오류율 CER | 76/2,556자, 2.973% | 3% 이하 | 통과 |
| 인코딩 오류 문서 | 0건 | 0건 | 통과 |

파싱 성공은 오류나 빈 결과 없이 지원 범위의 내용을 추출했음을 뜻합니다. 스캔 문서의 표 행·열까지 복원했다는 판정은 아닙니다. CP949 문서 D-052와 D-087도 오류 없이 읽혔습니다.

표 검사는 DOCX 6개, XLSX 8개 영역, PPTX 6개, 텍스트 PDF 4개로 총 24개 표본을 사용했습니다. Office 문서는 원본 OOXML 셀과 비교하고, PDF는 페이지 이미지에서 확인한 전사본과 비교했습니다. 스캔 PDF의 표는 이 셀 정확도에 포함하지 않았습니다.

파서 구조 테스트 11개와 평가기 테스트 18개를 통과했습니다. 보강·청킹·검색은 실행하지 않아 평가기에 미측정으로 남아 있습니다.

## OCR에서 남은 오류

스캔 PDF 3건의 전체 5쪽을 비교했습니다. 평가용 전사본은 계약서의 대응 DOCX 및 원본 스캔 이미지, 구성도 이미지로 준비했으며 사용자 검수는 아직 받지 않았습니다. 계약서는 페이지별, 구성도는 사전에 정한 영역별로 비교하므로 이 수치는 구성도의 연결 관계나 전역 읽기 순서의 정확도를 평가하지 않습니다.

공식 입력값은 NFC 정규화 후 연속 공백을 한 칸으로 통일한 문자열의 문자 오류율입니다. 공백을 모두 제외하는 보조 지표는 6/2,014자, 0.298%입니다. 두 수치는 정규화 기준이 다르므로 서로 대체할 수 없습니다.

| 문서 | 쪽 수 | 공백을 포함한 문자 오류율 |
|---|---:|---:|
| D-044 PACS 계약서 스캔 | 2 | 33/1,099자, 3.003% |
| D-069 네트워크 구성도 스캔 | 1 | 6/316자, 1.899% |
| D-102 계약서 스캔 | 2 | 37/1,141자, 3.243% |

전체 오류율은 기준을 간신히 충족하지만 계약서 두 건은 개별적으로 3%를 넘습니다. 운영 품질이 안정적이라고 판단하기에는 이릅니다.

필수 문자열 누락 2개는 모두 D-069에서 발생했습니다. 원문의 곱셈 기호 `×`를 영문 `x`로 읽었습니다.

- `FortiGate 600F × 2 (본사) / FortiGate 400F × 2 (DR)`
- `본사-DR 전용회선 1Gbps × 2`

정답에 맞춰 파싱 결과를 덮어쓰지 않았습니다. 비스캔 문서의 필수 문자열은 334/334개, 스캔 문서는 10/12개가 보존됐습니다.

당시 실험은 Mac의 Apple Vision OCR을 사용했습니다. 스캔 표의 행·열 복원, 구성도의 연결 관계, 복잡한 혼합 페이지를 모두 지원한 결과는 아닙니다. OCR 엔진 선정과 오류 교정은 현재 진행 계획에서 제외합니다.
