Hit@5는 정답 문서 중 하나라도 상위 5개에 있으면 성공입니다. 네이티브 범위는 네이티브 정답이 존재하는 60질문만 남기고 **원래 순위 상위 5개에 네이티브 정답이 있는지** 채점합니다. 스캔 문서를 순위에서 제거해 뒤 문서를 당겨 올리지 않았습니다.

| 검색 방식 | 전체 61질문 | 네이티브 정답 60질문 | 전체 MRR@10 |
|---|---:|---:|---:|

전체는 **8.20%p**, 네이티브 기준은 **8.33%p** 상승했습니다. 정답 문서 전부의 회수 비율을 질문별로 평균한 별도 지표는 84.70% → 92.90%입니다. 이 값도 답변 정확도나 검색 결과 모두의 적합도를 의미하지 않습니다.

## 모델 없이 더 개선할 수 있는 것

우선순위는 이번 남은 실패와 현재 코드의 한계에 근거합니다. 아래 추가 기능은 이번에 구현한 것으로 계산하지 않습니다.

| 후보 | 개선할 문제 | 주의할 점 |
|---|---|---|
| 명시된 문서 종류·거래처·대상 시스템 조건 | “TMS 로그”에서 다른 시스템이나 제안서가 앞서는 문제 | 분명한 표현만 필터링하고 값이 없으면 보류 |
| 정확한 번호·서버명·핵심 필드에 가중치 | 반복 문맥·일반 단어가 중요한 식별자보다 강해지는 문제 | 기존 성공이 악화되는지도 함께 확인 |
| 한국어 조사·띄어쓰기 정규화와 용어 사전 관리 | 표현 변형·붙여 쓴 용어·등록되지 않은 약어 | ‘전환’처럼 다의어를 무조건 확장하지 않기 |
| 로그 작업명·대상 시스템을 각 청크 문맥에 연결 | 긴 로그의 시작 작업명과 뒤쪽 오류가 떨어지는 문제 | 원문 근거와 중복 점수 증가를 분리해서 검사 |
| 문서 점수 집계·중복 근거 정리 | 현재는 문서의 최고 청크 점수 하나로 순위를 정함 | 많은 청크가 있다는 이유만으로 점수를 과대 평가하지 않기 |
| 계약 기간·금액·서명 상태의 명시적 조건 | 날짜 외 여러 조건을 함께 만족하는 문서 찾기 | 작성일과 계약 기간, 초안과 최신본을 혼동하지 않기 |
| 사본·버전 관리와 최신본 정책 | 같은 내용의 여러 파일, 과거 버전 혼재 | 최신의 업무적 의미·날짜 우선순위 정책 필요 |
| 정답 라벨 검토와 별도 평가 자료 | 규칙 과적합과 기존 원문/정답 불일치 | 별도 검수로 확정하고 기존 점수 이력 보존 |

다음 구현 우선순위로는 **명시된 문서 종류·대상 시스템 처리 → 핵심 필드 가중치·로그 문맥**을 권합니다. 스캔 이미지의 의미를 읽는 일은 이러한 텍스트 규칙 개선과 별도로 남습니다.
