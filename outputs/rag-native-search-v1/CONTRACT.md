# 모델 미선정 상태의 청킹·키워드 색인 규칙

작성일: 2026-10-17. 유료 API·비전·임베딩·생성 모델을 호출하지 않는다.

입력은 실제 공통 블록과 규칙 기반 보강 결과다. 청킹·색인은 정답 문서 라벨, 필수 문자열, 질의 정답을 읽지 않는다. 원본·기존 파싱·보강 결과는 변경하지 않는다.

## 청킹

- 문서마다 모든 네이티브 원문을 검색 조각으로 분리한다. 원문 없는 스캔은 chunks=[]로 남기며 문서 자체와 비전 대기를 유지한다.
- 계약서는 조항/제목, PPTX는 슬라이드, PDF는 페이지와 명시적 조항, XLSX는 시트의 표 행, 로그는 5분 구간과 크기를 기준으로 묶는다. 구간 뒤 스택 추적은 앞 로그에 붙는다.
- 원문 text와 context_header, 반복한 표 헤더를 별도 저장한다. 근거는 원본 block_id·문자 시작/끝·loc다. claims·가상의 이미지 설명은 원문에 합치지 않는다.
- 청크 본문 한도는 1,200 Unicode 문자다. 한도를 넘는 원문은 공백 경계를 우선 사용하고 120문자 이내 겹침으로 분할한다. 문장·표 행 하나가 한도를 넘는 경우도 원문 범위를 남기고 구조 분할 경고를 기록한다.
- 모델별 토큰 한도 300~500은 아직 평가하지 않는다. 토큰 검사 상태는 pending_model_selection이다. 문자 수를 토큰 수로 보고하지 않는다.
- 표 헤더는 원본의 열 이름 규칙으로 다시 확인한다. 기존 inferred header_rows를 자동 확정하지 않는다. 데이터행까지 헤더로 분류하지 않으며, 인식된 헤더를 모든 후속 표 조각에 연결한다. 모르는 헤더는 unknown으로 남겨 누락 검사에서 공개한다.
- 메타데이터는 status=extracted인 값만 필터·문맥에 사용한다. 미확정 값은 채우지 않고 상태를 별도 유지한다. 최신본·사본 군집·요약을 생성하지 않는다.

## 키워드 색인과 검색

- 로컬 파일의 BM25 역색인으로 문서·청크 검색을 구현한다. 영어/번호/호스트/IP 단어와 한국어 어절·음절 2-gram을 사용한다. 한국어 형태소 분석/Nori의 구현이나 성능 검증으로 부르지 않는다.
- 문서 항목은 파일명·경로·확정 메타데이터를 저장한다. 청크 항목은 원문·문맥·표 헤더와 원문 위치를 저장한다. 스캔도 파일명/메타데이터로 발견될 수 있지만 결과에 본문 미해석을 표시한다.
- 질의 전체를 토큰화한다. LLM 자연어 필터 생성, 날짜 해석, 의미 검색, 재순위화, 최신본 판정은 하지 않는다. 구조화 필터를 명시적으로 전달했을 때만 적용한다. 알 수 없는 필드/연산은 거절하며 null·보류를 필터 값으로 사용하지 않는다.
- 청크 전체 점수를 계산한 뒤 문서별 최고 점수로 묶는다. 문서당 상위 3개 근거는 순위 결정 후 선택한다. 결과에는 점수·검색 근거·위치·비전 대기를 반환하며 질문 조건이 충족됐다는 답변은 생성하지 않는다.
- 전체 문서 스냅샷으로 새 색인 디렉터리를 만든다. 입력에 없는 삭제 문서가 새 색인에 남지 않게 한다. SharePoint 실시간 수집·권한·삭제 동기화 서버를 구현한 것은 아니다.

## 첫 실행 전 고정한 평가

1. 문서 110건 보존, 원문 문자 범위 누락 0, 원문 참조·해시 오류 0, 문맥 머리말 누락 0.
2. 1,200자 본문 제한 준수. 실제 모델 토큰 길이는 미측정.
3. 인식된 표 헤더가 필요한 조각의 헤더 누락 0. 헤더 미확정 표와 긴 행 분할은 별도 공개. 헤더 규칙의 독립 의미 정확도는 별도 검수 사항.
4. 파싱에 있던 필수 문자열 중 청크 본문 어느 하나에도 온전히 없는 비율 ≤1%. 문맥 머리말과 반복 헤더로 원문 보존 점수를 올리지 않는다. 스캔에서 애초에 못 읽은 문자열은 파싱 누락으로 별도 유지한다.
5. 기존 61개 자연어 질의를 모두 검색한다. 입력에는 query_id·query만 전달하고 gold filters·answers는 검색에 전달하지 않는다. 전체와 유형별 Hit@5, MRR@10을 출력한다. 이 프로젝트의 Recall@5는 정답 문서 중 하나라도 상위 5개에 있으면 성공인 Hit@5다.
6. 기존 전체/유형별 90% 기준을 비교 대상으로 그대로 보고한다. 실패를 숨기거나 의미형 질문을 분모에서 제외하지 않는다. 키워드 시험 결과는 전체 하이브리드 검색 검증이 아니다.
7. 필터의 미확정 값 배제, 스캔 빈 청크, 표 헤더, 초과 행, 참조 변조, 원문 외 주장 배제, 삭제 반영, 점수 집계·평가 계산을 회귀 검사한다.

합성 예비 세트의 개발용 실행이다. 검색 벤치마크는 질문 내용을 확인해 문서 ID별 가중치나 정답 보정표를 만들지 않고 첫 결과를 저장한다. 실패 원인은 보고하되 성적을 맞추기 위해 사례별 규칙을 추가하지 않는다.
