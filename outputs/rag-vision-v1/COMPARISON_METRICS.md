# 두 비전 후보의 비교 지표

평가 대상은 동일한 36문서의 132장이다. 모델당 132개 출력을 비교한다. 원본 이미지, 네이티브 문맥, 프롬프트, JSON 규격, 출력 한도를 고정했다. 제공업체는 DeepInfra FP8이다. Qwen3.6은 reasoning을 비활성화했다. 실행 조건은 `../vision-comparison-run-001/manifest.json`에 보존한다.

## 현재 자동 집계하는 항목

| 항목 | 계산과 의미 | 평가 범위 |
|---|---|---|
| 응답 확보율 | 결과를 저장한 이미지 수 / 132 | 모든 대상. 인증·전송 오류와 모델 출력 실패를 구분 |
| 공통 블록 변환 통과율 | JSON 형식, 좌표 순서, 표 셀 범위·겹침·누락, 노드 참조 검사를 통과한 수 / 132 | 모든 대상. 내용 정확도와는 별개 |
| 출력 잘림 | 종료 사유가 `length`인 응답 수 | 모든 응답. 출력 토큰 상한 도달 여부 |
| 필수 문자열 보존 | 지정 문자열이 추출 텍스트·표 셀·노드 라벨에 포함됐는지 | D-044, D-102, D-069의 기존 필수 문자열 |
| 표 셀 정확성 | 행·열 위치, 병합 크기, 셀 내용이 모두 일치하는 셀의 precision·recall·F1 | D-044 2쪽의 8셀 초안 정답 |
| 구성도 노드 | 라벨이 일치하는 노드의 precision·recall·F1 | D-069 1쪽의 초안 정답 |
| 구성도 연결 | 양 끝 노드 라벨과 방향이 일치하는 연결의 precision·recall·F1 | D-069 1쪽의 초안 정답 |
| 처리 시간 | 요청별 경과 시간의 중앙값·최댓값 | 현재 API와 동시 요청 조건에서 관찰한 값 |
| 사용량·비용 | 응답의 입력·출력 토큰과 실제 cost 합계 | 저장된 응답. 중단 중 유실된 응답의 비용은 별도 불확실성 |

Precision은 추출한 항목 중 맞은 비율, recall은 정답 중 찾아낸 비율이다. F1은 두 비율의 조화평균이다. 문자열 비교는 유니코드 정규화와 공백 제거 후 수행한다. 의미가 같은 다른 표현은 자동 일치에서 탈락할 수 있어 원문 대조가 필요하다.

`evaluate.py`는 공통 블록으로 받아들인 결과만 평가한다. 실패·누락은 성공한 분모에서 제외하지 않고 미검출로 계산한다. `audit_outputs.py`는 좌표 등의 검사를 통과하지 못했어도 읽을 수 있는 원응답 내용을 별도로 진단한다. 이 진단은 실패 출력을 성공으로 바꾸지 않는다.

## 원문 대조가 더 필요한 항목

- 이미지 설명의 사실성: 실제 보이는 사실과 추론의 구분, 근거 없는 설명 여부.
- 전체 누락·중복: 원문에 있는 내용의 누락 또는 같은 내용의 반복 추출.
- 근거 좌표의 실제 정확성: 좌표가 숫자 규칙에 맞는 것과 대상 위치를 정확히 가리키는 것은 다르다.
- 전체 표·구성도 정확도: 현재 일부 문서에만 상세 정답 초안이 있다.

전체 132장에는 원문 대조 대기 목록을 남긴다. 일부 원문 대조 사례와 자동 초안 점수를 전체 의미 정확도나 독립적인 사람 검수 성적으로 표현하지 않는다. 현재 정답 주석은 보조자가 작성한 초안이다.

## 이번 비교에 포함되지 않은 검증

- 문서 보강 LLM 역할의 메타데이터 정확도·환각률·요약 품질. 비전 결과와 별도로 같은 두 모델을 시험해야 한다.
- 비전 결과를 실제 청크·색인에 반영한 뒤의 검색 Hit@5·정답 문서 회수율. 기존 검색 목표 90%는 이 단계의 지표다.
- DGX Spark에서의 메모리, 지연, 처리량. OpenRouter FP8 결과로 로컬 장비 성능을 확정하지 않는다.
- 반복 실행에 따른 안정성. 이번 실행은 이미지당 첫 응답 한 번을 기준으로 한다. 중단으로 결과가 유실된 요청만 이력을 남기고 재개했다.

따라서 현재 결과는 비전 파싱 후보를 좁히는 근거이며, 두 역할을 맡을 최종 운영 모델의 확정 판정은 아니다. 모델마다 대기열 진행 속도와 동시 요청 수가 달라 시간 수치는 엄격한 동일 부하 벤치마크로 사용하지 않는다.
