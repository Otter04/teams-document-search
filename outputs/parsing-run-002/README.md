# 비전 LLM 파싱 방향과 기존 실험 기록

**최신 실행(2026-10-16):** [공통 블록 규격으로 네이티브 110문서 재파싱·평가](../parsing-run-003/README.md)를 완료했습니다. 비스캔 필수 문자열 334/334, 표 표본 531/531셀을 확인했습니다. 전체 시각 자료는 처리 대기이며 다음 비전 시험은 OpenRouter에서 진행하는 방향입니다.

## 현재 설계 방향

![비전 LLM을 반영한 RAG 파이프라인 구조도](/Users/kangdongkyoon/Documents/Codex/2026-10-14/rag/outputs/diagrams/rag-pipeline-vision-llm.png)

사용자 결정에 따라 이미지 처리는 **이미지의 의미적 맥락을 이해하는 비전 기능이 있는 LLM**을 사용하는 방향으로 변경합니다. OCR 엔진 선택, OCR 오류 교정, OCR 기준선 개선에 관한 기존 고려사항은 앞으로의 설계와 다음 작업에서 제외합니다.

처리 흐름은 **이미지 → 비전 LLM → 구조화된 내용과 시각적 맥락 → 평가**입니다. 대상은 스캔 PDF뿐 아니라 문서에 포함된 사진·그림·도표·구성도입니다. 추출 범위는 이미지의 글자, 표의 행·열과 셀 관계, 구성도의 연결 관계와 흐름, 사진·그림의 의미 및 주변 문서와의 맥락입니다. 모델이 직접 확인한 내용과 추론한 해석은 구분하고 원문 위치를 함께 남기는 방향으로 설계합니다.

2026년 10월 15일, **[공통 블록 규격 1.0.0과 평가 기준 설계안](../common-block-design/README.md)**을 작성했습니다. 원문·구조·관찰/추론·근거 위치를 분리하며 파일 형식별 양식과 실제 자료 기반 예시를 제공합니다. JSON 스키마와 참조 검사를 준비한 상태이며, 비전 LLM 모델 선정·연동·실행과 의미 평가기 구현은 아직 남아 있습니다. 평가 임계값은 초기 제안입니다. 기존 Apple Vision OCR과 OpenCV 표 복원 결과를 비전 LLM의 구현 또는 검증 결과로 간주하지 않습니다.

## 기존 OCR 실험 기록

아래는 방향 변경 전에 수행한 실험의 사실 기록입니다. 코드와 측정값은 재현을 위해 보존하며, OCR 개선을 계속하라는 작업 지시나 현재 설계의 전제가 아닙니다.

2026년 10월 14일, 파서 1.1.0으로 예비 데이터셋 110건을 다시 처리했습니다. 스캔 PDF의 선으로 구분된 표 2개를 각각 4행과 2열로 복원했으며 16개 셀의 내용과 배치가 기준에 일치했습니다. 공백을 포함한 문자 오류율은 2.973%에서 2.387%로 낮아졌습니다. 글자와 기호 자체의 오독은 아직 남아 있습니다.

이번 평가 엑셀의 표 셀 정확도는 기존 표본 24개 영역에 스캔 표 2개를 더한 26개 영역, 총 547/547셀입니다. 표본이 늘어났으므로 스캔 표 16개 셀의 결과를 별도로 제시했습니다. 기존 파서도 같은 새 표 기준으로 다시 검사했으며 구조가 없으므로 셀 배치 0/16으로 기록됩니다. 이것은 이전에 스캔 글자까지 읽지 못했다는 뜻은 아닙니다.

비교에는 이전과 동일한 OCR 전사본 및 정규화 규칙을 사용했습니다. 공백 포함 CER은 NFC 정규화 후 연속 공백을 한 칸으로 통일한 문자열의 편집 거리입니다. 공백 제외 CER은 모든 공백을 제거합니다. **이번 OCR 개선은 주로 띄어쓰기에서 나왔고, 글자와 기호 오류 6개는 줄지 않았습니다.**

| 스캔 문서 | 이전 공백 포함 CER | 개선 후 |
|---|---:|---:|
| D-044 계약서 2쪽 | 33/1,099자, 3.003% | 28/1,099자, 2.548% |
| D-102 계약서 2쪽 | 37/1,141자, 3.243% | 30/1,141자, 2.629% |
| D-069 구성도 1쪽 | 6/316자, 1.899% | 3/316자, 0.949% |

전체 및 문서별 공백 포함 오류율이 모두 3% 아래입니다. 구성도의 `×`를 `x`로 읽는 문제로 필수 문자열 2개가 여전히 불일치합니다. 문자만 교정한 것처럼 보이도록 정답으로 결과를 덮어쓰거나, 영문 x를 일괄 치환하지 않았습니다.

## 기존 실험에서 구현한 처리

1. 페이지를 이미지로 변환하고 Apple Vision의 정확도 우선 OCR을 실행합니다. 200 DPI를 유지합니다.
2. 언어 교정 없이 읽은 결과와 언어 교정을 켠 결과를 좌표로 대응시킵니다. 공백을 제외한 글자가 완전히 같을 때만 교정된 띄어쓰기를 채택합니다. 이번 실행에서는 20줄에 적용했고 글자가 다른 후보 3개는 채택하지 않았습니다.
3. OpenCV로 이미지의 가로선과 세로선을 찾습니다. 반복되는 행·열과 닫힌 외곽선이 확인된 표만 복원합니다. 이번 구성도의 상자와 연결선은 표로 처리하지 않았습니다.
4. 각 OCR 줄을 표의 셀에 배치하고, 셀 내부의 여러 줄을 같은 셀에 유지합니다. 셀 경계를 크게 가로지르거나 인식 결과가 없는 경우에는 셀 영역 OCR을 사용합니다. 모든 셀을 무조건 잘라 읽으면 짧은 글자가 악화되는 문제를 실험에서 확인해, 안정적으로 배치되는 페이지 OCR을 우선합니다.
5. 셀별 `row`, `column`, `row_span`, `col_span`, 원문 좌표와 내용을 기록합니다. 원래 페이지 OCR은 감사용 `raw_page_lines`에 남기고 본문에 중복 삽입하지 않습니다.

아래는 D-044 스캔에서 실제로 복원한 표입니다. 마지막 셀의 두 줄도 한 셀로 유지됩니다.

| 갑 | 을 |
|---|---|
| 상호: 의료법인 새봄의료재단 | 상호: 라움정보기술 주식회사 |
| 대표이사: 류정원 (인) | 대표이사: 정태오 (인) |
| 주소: (생략) | 주소: 서울특별시 구로구 디지털로 000, 7층 |

표 영역 좌표도 이미지에서 별도로 확인한 대략의 경계와 비교했습니다. 두 표의 최소 영역 겹침 비율은 96.7%입니다. 첫 행은 헤더 후보로 표시하며 의미상 헤더라는 확정 판정은 아닙니다.

## 기존 실험의 검증 범위와 제한

- 원본 파일 해시 110건이 유지됐고 비스캔 문서 107건의 기존 블록은 완전히 동일했습니다. 최상위 블록 4,549개, 내부 요소 포함 5,208개를 기록했습니다.
- 16개 파서 테스트가 통과했습니다. 새 테스트는 빈 셀, 병합 헤더, 구성도 오탐 방지, 선 없는 텍스트의 오탐 방지, 셀 좌표와 중복 텍스트를 검사합니다. 실제 스캔 두 표에는 병합 셀이 없어 병합 지원은 합성 테스트 범위입니다.
- 기존 평가기에 실제 결과를 넣었고 파싱 지표 다섯 개가 통과했습니다. 엑셀은 LibreOffice로 재계산해 대조하고 원래 수식과 서식을 보존했습니다. 실행기록에는 이전과 이번 실행이 함께 있습니다.
- 전사본과 표 기준은 원본 이미지를 확인해 AI가 준비한 자료이며 사용자 검수는 아직 받지 않았습니다. 구성도 CER은 영역별 문자 비교이므로 연결 관계 정확도를 뜻하지 않습니다.
- 같은 예비 세트를 개선 과정에도 사용한 개발 평가입니다. 새로운 독립 문서에서의 성능이나 운영 준비 완료를 의미하지 않습니다.
- 표 복원은 선이 있는 단순한 표 중심입니다. 선 없는 표, 큰 회전·심한 기울어짐, 손상된 선, 복잡한 병합과 구성도 연결 관계는 이 실험에서 검증하지 못했습니다. 이 제한을 기존 OCR 방식으로 보완하는 작업은 진행 계획에서 제외합니다. 보강·청킹·색인·검색은 이번에 실행하지 않았습니다.
