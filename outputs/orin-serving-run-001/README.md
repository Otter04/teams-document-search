| 같은 텍스트 + JSON 출력 옵션 | HTTP 200 | 3/3 일치 | 순수 JSON 파싱 성공 | 6.871초 |

총 생성 요청은 3건이다. 첫 텍스트의 실패는 서버/내용 오류가 아니라 응답의 Markdown 코드블록 때문이다. 그 결과도 `tests/`에 그대로 보존했다. 이후 `response_format: {"type":"json_object"}`를 요청에 추가했다. 서버 설정이나 가중치는 바꾸지 않았다. 이것은 JSON 문법 제약이며 각 필드 의미의 정확성이나 공통 블록 전체 규격 준수를 보장하지 않는다.

이미지는 기존 예비 데이터셋의 계약서 페이지 [D-044-2.png](../common-block-design/assets/D-044-2.png)를 사용했다. 요청 전에 원본 이미지를 직접 확인해 기대값을 정했다. 이미지 외에 해당 문서의 정답 텍스트를 모델에 제공하지 않았다.

실제 이미지 응답:

```json
{
  "date": "2025-03-22",
  "party_a": "의료법인 새봄의료재단",
  "party_b": "라움정보기술 주식회사",
  "court": "서울중앙지방법원"
}
```

텍스트는 짧은 합성 회의록 문장, 이미지는 실제 예비 자료 1장이다. 응답 시간은 Mac → SSH 터널 → Orin의 요청 전체 시간이며 순수 생성 속도나 대표적인 처리량이 아니다. 요청별 길이·출력 제약·첫 실행 준비가 달라 시간을 직접 비교하지 않는다. OpenRouter 평가 결과의 재현, 전체 파싱·보강 품질, 운영 부하 검증은 아직 수행하지 않았다.

## 접속

- Orin 내부: `http://127.0.0.1:8001/v1`
- 현재 Mac SSH 터널: `http://127.0.0.1:18001/v1`
- 모델 이름: `qwen3.6-35b-a3b`

Mac 주소는 현재 VPN/SSH 연결이 유지되는 동안 사용할 수 있다. SSH가 끊겨도 detached 컨테이너는 계속 실행되지만, 호스트/Docker 재시작 시 자동 복구 정책은 설정하지 않았다. 이미 실행 중인 서버에 `docker run`을 다시 실행할 필요는 없다.
