# 의미 표현 검색 개선 평가 규약

2026-10-26. 질문별 단어 사전을 추가하지 않고 기존 Orin 모델로 후보 문서의 의미를 비교한다. 질문 ID나 정답 문서 ID는 검색기·모델 입력에 전달하지 않는다. 문서195개·청크3,754개, 기존 정답과 응답은 변경하지 않는다.

## 후보 코드 search-1.8.4

명시 거래처·날짜·식별자·버전·정렬·포함 내용·기존 개념 확장이 없으며 네 단어 이상인 질문 중 BM25 후보가 0개인 경우에만 원문 대조를 실행한다. 일반 문서종류는 기존 B 정책의 선호로 유지한다. 질문 분석 단계는 제거하지 않는다. 이 경로에서는 질문 분석 대신 검색 후 원문 대조를 호출하며, 그 외 질문 분석의 기존 2.5초 제한은 유지한다.

1. 기존 BM25 50청크·벡터 50청크·RRF·R1 결과를 확보한다.
2. 해당 질문의 의미 후보를150청크까지 넓히고, 순위 순으로 최대60문서를 검토한다. 기존 필수 필터는 유지한다.
3. 전체 본문 분량을 약24,000자로 나누어 제한한다. 문서당 최대1,200자; 짧은 원문은 전체, 긴 자료는 검색 청크 두 개의 앞부분을 쓴다. 후보가 많으면 문서당 검토 분량은 줄어든다. 따라서 전체 문서 정독으로 설명하지 않는다.
4. 기존 Qwen3.6-35B-A3B에 질문·후보만 전달해 가장 직접적으로 맞는 문서와 100자 이하 연속 인용문을 받는다. 온도0, thinking off, 출력160토큰, 최대 대기90초. 후보 전체에 점수를 붙이는 전용 cross-encoder 방식과 구분한다.
5. 후보 ID·형식·출력 종료·인용문을 검사한다. 인용문이 제공된 후보 텍스트와 실제 공통 블록 양쪽에 있어야 채택한다. 요약에만 있는 문장은 채택하지 않는다. 이는 문자열 근거 검사이며 의미 판단의 무오류를 보장하지 않는다.
6. 같은 문서군의 다른 검색 후보에도 동일 인용이 있으면 공백·줄바꿈만 무시해 근거를 확인한다. 그 후보들 사이에서는 기존 최신본·최종본 선택 정책을 유지한다. 근거가 없는 새 버전에 우선순위를 넘기지 않는다.
7. 숫자가 직접 포함된 질문은 금액·단위·대소관계를 별도로 검증하지 못하므로 Qwen 원문 대조를 호출하지 않고 원래 순위를 유지한다. 모든 수치 표현을 새로 해석한 것은 아니다.
8. 모델 실패·잘린 출력·검증 실패·맞는 문서 없음은 원래50청크 기반 순위를 그대로 반환한다. 검토 후보를 넓혔다는 이유만으로 기존 결과가 바뀌지 않는다.

## 비교 실행과 판정

`inputs.jsonl`은 기존150+이미 작성된 변형16개다. 원문 대조용 중복2문항은 포함하지 않았다. 고정 날짜2026-10-14, filter B/R1/use_llm=true, 시간은 클라이언트의 요청 시작부터 최종 결과 수신까지다. 모델의 원문 검토와 기존 질문 분석 호출을 별도로 집계한다.

기존150개는 모든 필수 대표 정답이 상위5에 있는지, 변형16개는 해당 목표 문서가 상위5에 있는지를 비교한다. 정답1위, 기존 성공 회귀, 날짜 조건, 모델 근거, 처리시간도 별도 기록한다. 150개는 개발용 질문이며16개도 이미 실패를 확인한 질문이므로 독립적인 일반화 성능으로 주장하지 않는다.

## 보존한 실험 이력

- probe-001/002: 설치된 bge-reranker-v2-m3 청크/문서 문맥 비교. 기존 성공을 떨어뜨려 채택하지 않았으며 전용 컨테이너는 중지했다.
- probe-003: Qwen 질문 핵심어 정리. 간접 표현의 일부만 해결해 채택하지 않았다.
- probe-004: Qwen 후보 원문 대조의 초기 범위 확인. 후보30문서 밖에 있는 정답을 확인해 후보를60문서로 늘렸다.
- run-001(search-1.8.2): 166개 전체 실행. 변형16/16, 기존146/150. Q-070/080은 근거가 같은 최종본 대신 모델 선택 초안·이전본으로 대표가 바뀌었으며, Q-074에는 요약에만 존재하는 인용이 있었다.
- run-002(search-1.8.3): 위 근거·버전 보호와 원래 순위 복원 보완 후 전체 재평가. 변형16/16, 기존147/150. Q-083은 금액만 맞는 다른 사업 계약서를 선택했다.
- run-003(search-1.8.4): 숫자로 명시된 조건의 보호 후 전체 재평가. 결과는 해당 실행의 summary.json을 따른다.
