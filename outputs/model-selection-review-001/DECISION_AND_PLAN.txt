2026-10-19 / 설계만 작성 / 추가 모델·유료 API 호출 0회

1. 결정 범위

추가 비전 프롬프트·생성 설정 튜닝을 중단한다. 현 자료에서 비전 우선 후보는 Qwen3.6-35B-A3B다. 문서 보강 능력과 DGX Spark 실제 운영 검증 전의 잠정 추천이며, 운영 기본 모델·프롬프트·파이프라인을 변경하지 않았다.

같은 기존 조건의 전체 36문서·132장 비교:
- 원문 필드 기준 항목 보존: Qwen3.6 1315/1338(98.28%), VL 1246/1338(93.12%).
- 완결 JSON: 130/132(98.48%), 70/132(53.03%).
- 형식·좌표·참조 검사 후 공통 JSON 전달 가능: 104/132(78.79%), 65/132(49.24%). 경고부 전달도 포함하므로 의미상 합격률이 아니다.
- 내용 중복 검출 이미지: 13/132, 98/132.
- 문맥 없는 스캔 6장 기준 항목 보존: 77/100, 79/100. VL의 근소한 우세이며 표본이 작다.
- 출처: ../vision-source-review-001/README.md 및 ../vision-validation-run-003/README.md.

수정 프롬프트로 재시험한 문제 중심 7장에서는 Qwen3.6/VL의 원문 보존이 66/77 대 73/77, 완결 JSON이 5/7 대 6/7, 전달 가능이 4/7 대 6/7이었다. VL의 개선 가능성을 보여주지만 전체 132장 성적과 합치거나 이를 전체 성적으로 일반화하지 않는다. Qwen3.6도 공백 반복·좌표 오류·스캔 오독/누락이 남았다. ../vision-prompt-trial-001/REPORT.txt 참조.

전체 126장에 네이티브 문맥이 제공됐고 같은 양식·문서군이 반복된다. 순수 이미지 인식 능력이나 독립 운영 정확도로 해석하지 않는다. 참조는 AI 검수 초안이고, 모든 시각 설명의 의미 정확도를 정량 검증하지 않았다. 현재 요청된 모델 선정의 업무상 우선순위는 정보 보존과 구조/JSON 전달이며, 잠정 추천은 이 범위에 한정된다.

2. 다음 비교의 목적과 종료 조건

목적: 이미 읽은 동일 문서 내용을 메타데이터와 근거 있는 짧은 요약으로 정리할 때 어느 모델이 더 유용한지 확인한다. 비전 재시험·검색 Hit@5·임베딩·모델별 튜닝은 제외한다.

20문서 × 두 모델 × 1회 = 계획상 최대 40회인 단일 선정 평가를 제안한다. 아직 호출하지 않았고 실행 승인도 받은 것으로 간주하지 않는다. 입력·정답·공통 지시·스키마·설정은 최초 호출 전에 동결한다. 응답을 본 뒤 바꾸어 재시험하지 않는다. 자동 재호출하지 않으며 실패도 실패로 기록한다. 모델당 반복 시행이 아니므로 실행 변동성은 한계로 남긴다.

동일한 공통 지시와 명시적 생성 설정 한 벌을 사용한다. 설정은 이전에 확인한 양 모델 공통 비사고/Instruct 설정 temperature=0.7, top_p=0.8, top_k=20, presence_penalty=1.5, repetition_penalty=1, min_p=0, frequency_penalty=0을 제안값으로 적는다. seed=42, 최대 출력 16384, 동일 DeepInfra FP8, fallback=false, Qwen3.6 reasoning=false를 유지한다. 이것은 아직 적용하지 않은 선정 평가 설정안이며 최적값 주장이나 별도 튜닝 비교가 아니다. 호출 전 공개 지원 정보만 다시 확인하고, 불지원/입력 초과 시 임의 제공자 변경·중간 절단 대신 중단 사유를 남긴다.

3. 평가 자료 20문서

selected-cases.json에 실제 파싱 레코드 위치·원본 해시·선정 이유를 기록한다.
- 계약 5: D-005, H-001, H-002, D-044, D-102. 당사자/공급자, 금액·기간·번호, 초안 날짜의 보류, 서명본이라는 파일명과 실제 서명 확인을 구분한다.
- 제안·날짜 4: D-002, H-006, H-007, H-016. 표지일/명시적 작성일/수정일 구분, 대상시스템과 단순 연동 언급, 핵심 사업 요약.
- 견적 3: H-011, H-015, H-020. 대표 금액/단가, VAT, 견적번호·유효기간, 표 밖 문구.
- 메모·메일 3: H-021, H-022, H-023. 문서종류, 본문 오류코드, 작업과 상태, 현재 문맥과 인용 문맥 구분.
- 로그 3: H-026, H-027, H-030. 중간 WARN/ERROR와 최종 결과, 작업명과 시작·종료 시각, 오류코드.
- 구성도 2: D-007, H-018. 대상시스템·설치 위치, 블록에 명시된 연결과 추론의 구분.

17개는 기존 네이티브 블록을 공통 입력으로 사용한다. D-044/D-102/H-020은 스캔이므로 기존 원본과 저장된 추출을 대조해 평가용 검수 공통 블록 한 벌을 먼저 만들어야 한다. 이를 두 모델에 똑같이 준다. 어느 모델 자신의 비전 출력과 결합해 입력하지 않는다. 교정은 별도 평가용 사본에만 기록하고 원응답은 보존한다. 지금은 선정 목록만 작성했으며 스캔 검수 블록을 완성한 상태가 아니다.

H-020 등에서 검수로 보충한 글자는 제공된 입력으로 간주한다. 보강 모델이 이미지를 새로 읽어 복구했다고 평가하지 않는다. 실제 누락·비전 대기 상태는 유지하며, 불완전 입력에 없는 값은 모델이 추측해서 채우면 안 된다. 네이티브 구성도의 미해석 관계도 그대로 보류한다.

4. 공통 입력과 출력 경계

입력: 동일한 문서 전체 공통 블록(본문·표·그림 설명의 관찰/추론 구분·block_id·loc·coverage), 파일명/경로, 실제 수집 수정시각, 동일 거래처/시스템 사전. 문서 앞부분만 잘라 마지막 서명/종료를 놓치지 않는다. 문서별 정답, 질의 정답, 생성기 내부값은 넣지 않는다. 규칙의 예측값도 모델 입력에서 제외하여 독립된 후보 값을 얻고 규칙 결과와 사후 비교한다.

출력 설계: llm_enrichment_candidate_v1이라는 별도 실험 응답을 사용한다.
- 기존 21개 업무 필드와 date_context의 표지일·명시적 작성일에 대해 value/status/evidence/candidates/reason을 제출한다.
- evidence에는 실재 block_id 또는 source 속성과 정확한 원문 인용을 포함한다. 여러 블록의 의미를 합칠 때 모든 필요한 근거를 제시한다.
- 상태: extracted / needs_review / pending_vision / not_found_in_input / not_applicable. 기존 not_found_native를 비전 포함 결과에 그대로 사용하지 않는다.
- extracted는 근거 있는 값, 나머지는 null과 사유를 사용한다. 충돌 후보는 candidates에 보존한다. 상태와 값 조합을 검증한다.
- summary는 최대 3문장, 문장마다 evidence를 붙인다. 금액·날짜·번호·운영 성공·서명·최종본 등 원문 밖의 사실을 만들지 않는다.
- 파일 수정시각은 수집값을 프로그램이 복사한다. 모델 추출 성과로 세지 않으며 작성일·제출일로 바꾸지 못한다.
- 입력 문서 ID/해시·모델/설정·응답/비용/실행 시간은 실행기가 별도 기록한다.

현재 enrichment.schema.json에는 model_called=false와 규칙 버전 상수가 있으므로 LLM 결과를 기존 규칙 전용 파일에 정상 결과처럼 저장하지 않는다. 위 후보 응답 스키마와 어댑터는 설계이며 아직 구현하지 않았다. 기존 공통 블록 규격과 규칙 전용 보강 파일은 변경하지 않는다.

5. 원문 기준 정답과 평가

기존 원문 기준 라벨 ../metadata-policy-v1/documents.source-v1.jsonl 및 추가 자료 ../additional-dataset-v1/package/metadata-labels.jsonl을 출발점으로 삼되, 선택 문서별 원문·동결 입력·날짜 정책과 대조한다. 오래된 생성기 정답을 그대로 정답으로 확정하지 않는다. unknown 라벨에 임의의 날짜를 채우지 않는다.

첫 호출 전에 각 필드의 적용 여부, 확정 값/허용 별칭, 근거 block_id·인용·위치, 정답 상태, 입력에서 관찰 가능 여부를 기록한다. 미확정 값은 값 정확도 분모에서 제외하되 올바른 보류 평가에는 포함한다. 입력에 필요한 근거가 있는데 모델이 보류한 것은 회수 실패로 센다. 입력에 없는 원문 정보는 upstream_missing으로 별도 집계하며 모델이 맞혀야 할 값으로 세지 않는다. 핵심 요약 사실도 문서당 3~5개를 사전에 고정한다.

평가자는 결과 모델명을 가린 A/B로 원문 근거를 확인한다. 사람 검수자가 아직 지정되지 않았으며 기존 AI 초안을 사람 검수 완료로 표시하지 않는다. 사람 검수 없는 첫 비교라면 개발용 선정 근거로만 발표한다. 20문서는 과거 규칙 개발에 사용된 자료여서 독립 일반화 평가가 아니다.

주 지표(문서 전체와 필드별, 17네이티브/3검수 스캔별 모두 보고):
1) 채운 값 정확도 = 근거와 의미 역할까지 맞는 값 / 판정 가능한 대상에 모델이 채운 값. 값 없는 것이 정답인 칸의 오기입도 분모·오답에 포함한다.
2) 필요한 값 회수율 = 맞게 채운 값 / 동결 입력에서 추출 가능한 확정 정답 값. 무조건 null로 점수를 높이지 못한다.
3) 올바른 보류율 = 기대 상태를 지키고 값은 비운 칸 / 미확정·충돌·미해석·미관찰 칸. 적용 제외는 별도 평가한다.
4) 근거 정확성 = 인용이 입력에 존재하고 주장까지 뒷받침하는 항목 / 근거가 필요한 출력 항목. 단순 인용 존재 검사와 의미 지지 판정을 분리한다.
5) JSON·참조 검증 = 완결·스키마·상태 일관성·실재 ID를 모두 통과한 문서 / 20. 실패 응답을 자동 복구해 성공으로 세지 않는다.
6) 요약 사실성 = 지지되는 원자적 사실 / 모든 요약 사실. 핵심 내용 회수 = 포함된 사전 핵심 사실 / 사전 핵심 사실. 문장을 거의 안 쓰고 높은 사실성을 얻는 것을 구분한다.
7) 규칙 대비 순증 = 기존 규칙에서 빠졌던 값 중 올바르게 추가한 수, 기존 올바른 값과 충돌/오염한 수. 미확정은 강제로 해소할 대상이 아니다.
8) 응답 시간 중앙값/최댓값, 입력·출력 토큰, 실제 응답 비용, 실패 수. 비용을 정확도 대신 합격 기준으로 사용하지 않는다.

예시:
- H-021: 본문의 E-SENSOR-17을 오류코드로 기록하면서 해당 문장·블록을 근거로 제시한다. 현재 규칙의 실제 미추출 1개이므로 순증을 확인할 수 있다.
- D-002: 표지의 2025.01.13을 표지일로 분류한다. 별도 명시적 작성일/제출일로 승격하지 않는다. 파일 수정시각은 수집값으로 별도 보존한다.
- D-005: 초안 끝의 모호한 날짜를 작성일로 단정하지 않고 검토 대기로 유지한다. 날짜를 많이 채우는 것보다 보류가 올바른 경우다.
- 로그: 중간 ERROR 한 줄만으로 최종 실패를 정하지 않고 마지막 명시적 결과를 확인한다.

6. 선정 규칙: 결과를 보고 기준을 바꾸지 않는다

권고 통과 기준은 기존 보강 계약과 연결한다: 채운 값 정확도·필요한 값 회수율 각각 95% 이상, JSON/참조 형식 20/20, 근거 없는 확정 금액·날짜·번호·최종 실행결과 0건, 모호한 날짜를 근거 없이 확정한 경우 0건. 이는 작은 표본의 선정 기준이며 운영 보증이 아니다. 요약 사실성/핵심 회수는 별도 공개하고 문체 취향으로 사실 오류를 상쇄하지 않는다.

규칙만 / 규칙+Qwen3.6 후보 / 규칙+VL 후보를 같은 고정 정책으로 오프라인 비교한다. 두 모델의 후보 응답 자체 성적도 반드시 공개한다. 병합은 검증된 추가값만 후보로 유지하고 규칙·사람 확정값과 충돌하면 검토 대기, 자동 덮어쓰기 없음. 병합기가 모델 오류를 숨기지 않도록 원후보 오류·억제 건수를 함께 센다. 운영 반영은 별도다.

두 모델 모두 통과하면 순증과 요약 핵심 회수를 우선하고, 유사하면 현재 비전 전체 평가에서 앞선 Qwen3.6을 우선한다. VL만 보강 통과 시 비전의 전달 실패 부담을 함께 설명하고 역할 통합 적합성을 판단한다. Qwen3.6만 통과하면 이를 통합 우선 후보로 정한다. 둘 다 실패하면 '현재 조건에서 통합 모델 미확정'으로 종료하며 자동 튜닝을 재개하지 않는다. 어느 모델도 규칙 대비 유의미한 추가값·요약 이득이 없으면 메타데이터는 규칙을 유지하고 LLM 사용 범위를 줄인다.

단일 장비 운영 성능은 이번 평가에서 확인하지 않는다. DGX Spark 메모리·추론속도·양자화별 품질 검증은 모델 선정과 별도 운영 확인이다.

완료: 저장된 두 비전 평가 범위를 구분한 잠정 선정, 20문서 목록과 원본/파싱 연결 확인, 입력·출력·지표·종료 조건 설계.
미완료: 스캔 3문서 공통 검수 블록, 전체 선택 필드/요약 정답과 별도 검수, 후보 JSON Schema·입력 패키지·오프라인 평가기/실행기 구현, 첫 호출 전 입력/정답 해시 동결, 모델 실행과 실제 보강 점수.
유료 호출·API 키 접근·기존 파일 변경·색인 반영·추가 튜닝은 하지 않았다.
