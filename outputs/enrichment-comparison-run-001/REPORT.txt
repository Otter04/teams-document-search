왜 JSON 전달이 2/20 대 0/20인가

대표적인 원인은 본문 문단 인용을 kind='source'로 표시하는 것이다. 이번 규격에서 source는 파일명 같은 파일 속성을 뜻하고, 본문 문단은 kind='block'과 실제 block_id로 연결해야 한다. VL은 이 둘을 반복해서 혼동했다. Qwen3.6도 file_name 앞에 '파일명:' 같은 문구를 덧붙이거나, 서로 다른 문단을 한 인용으로 합쳐 실제 원문 인용 검사에 실패했다.

또한 extracted 상태에서는 candidates=[]와 reason=null을 요구했는데 VL은 확정 값에도 후보 목록·사유를 함께 넣는 경우가 많았다. Qwen3.6은 반대로 빈 값의 사유를 누락한 사례가 있었다. 이는 모델 응답에 이미 있는 문제이며 JSON 변환기가 내용을 잘못 읽어 만든 문제는 아니다.

정확한 인용을 요구하는 기준 때문에 따옴표 종류를 바꾼 정도의 표기 차이도 차단에 포함된다. 이를 실제 의미 왜곡과 구분해 원응답과 오류 목록을 제공했다. 응답을 본 뒤 검증 기준을 느슨하게 바꿔 점수를 올리지 않았다.
