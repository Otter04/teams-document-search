# 추가 질문 포함 검색 평가

2026-10-20. 사용자 첨부 `search_gold.jsonl`을 별도 확장 평가세트로 등록하고 현재 Orin `search-1.2.0`에서 99개 전체를 실행했다. 검색 규칙·프롬프트·모델·색인은 바꾸지 않았다. 외부 유료 API 호출 없음.

## 핵심 결과

새 간접 표현 30개 중 **정답 문서군을 26개(86.67%)** 찾았고, **지정한 대표 버전까지 일치한 것은 25개(83.33%)**다. 해당 대표 문서가 1위에 나온 질문은 **14개(46.67%)**다. 새 30개만 따로 보면 기존 90% 목표에 미달한다.

기존 61질문의 실제 상위 문서와 순서는 이전 `rank-trace-008`과 **61/61 모두 동일**하다. 기존 ‘정답 하나 이상’ 기준도 59/61을 유지했다. 새 파일에서 필수 대표 문서를 모두 요구하면 기존 질문은 58/61이다. Q-061에서 정답 로그 3개 중 D-072만 보이고 D-109·D-110이 빠지는 기존 문제가 더 엄격한 기준에서 드러난 것이다.

99개 모두 약 93.30초에 실행 완료했고 요청 오류는 0건이다. 97개는 검색 결과 반환, 2개는 추가 조건 확인 요청 상태였다. 단순 결과 저장을 성공으로 간주하지 않고 아래 기준으로 정답과 대조했다.

## ‘정답과 동일’의 기준

1. **정답 하나 이상:** `answer_doc_ids` 중 하나가 최종 상위 5개 본문 카드에 있으면 성공. 기존 90% 목표와 비교할 때 쓰는 Hit@5이며, 버전 차이나 추가 정답 누락을 허용한다.
2. **필수 문서군 모두:** `expected_cards.priority=필수`의 문서군을 전부 찾아야 한다. 다른 버전이 대표이면 문서군 발견은 인정한다.
3. **필수 대표 문서 모두:** 각 필수 카드의 `representative` ID가 실제 본문 카드에 모두 있어야 한다. ‘첫 견적’에 최종 견적이 나오면 실패다. 이번 새 질문의 엄격한 결과는 25/30이다.
4. **결과 목록 완전 일치:** 추가 후보를 포함한 실제 목록 전체가 첨부의 필수·추가 대표 문서 목록과 일치하는지 비교했다. 이 기준은 **0/99**였다. 현재 서비스는 최대 5개의 관련 후보를 제공하므로 정답을 포함하더라도 다른 후보가 함께 나오는 경우를 성공으로 세지 않는 별도 기준이다. 상위 5개 정답 포함률과 혼동하지 않는다.

문서 ID·문서군·대표 버전·순위 중심의 평가이며, 첨부 파일의 모든 근거 문자열·위치·필터 JSON까지 완전히 같다는 뜻은 아니다. 특히 추가 8질문은 대표 문서 기준 8/8이지만 Q-068·Q-069의 예상 ‘기간 조건 제거’는 기본 B 방식에서 기간이 처음부터 선호 조건이므로 실제 완화 이벤트와 같지 않다.

첨부 파일은 61+8+30=99질문이며, 기존 61개 질문 문구는 동일하다. 기존 정답 집합은 Q-013·Q-021·Q-038에서 확장되어 있어 새 정답으로 계산한 MRR의 차이를 검색 개선으로 해석하지 않는다. 원래 정답·기존 결과·첨부 원본은 수정하지 않고 복사본의 해시를 확인했다. 정답과 `keyword_check`, 조건, 힌트는 검색 API에 전달하지 않았다. API에는 질문·기준일·기존 B/R1 설정만 전달했다.
