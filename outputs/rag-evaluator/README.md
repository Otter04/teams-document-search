# RAG 인덱싱 평가기

**문서 보강 후속(2026-10-16):** [규칙 기반 실제 보강 평가](../enrichment-run-001/README.md)를 추가했습니다. 이번 결과에는 비전 대기·검토 대기 등의 상태가 있으므로, null을 N/A로 정규화하는 아래 기존 입력 형식에 억지 변환하지 않고 상태를 보존하는 별도 평가기를 사용합니다. 기존 값 정규화·비교 규칙은 재사용합니다.

**현재 프로젝트 방향:** 이미지의 글자·표 관계·구성도 흐름·사진과 그림의 의미 및 문서 맥락을 비전 LLM으로 추출합니다. OCR 관련 고려사항은 후속 설계에서 제외했습니다. [공통 블록 설계안](../common-block-design/README.md)에 이어 2026년 10월 16일 [새 네이티브 파서와 원문 전용 변환 계층으로 실제 평가](../parsing-run-003/README.md)를 수행했습니다. 이 평가기의 기존 문자·표 검사는 이미지의 의미 이해까지 검증하지 않으며 비전 LLM 전용 평가 기능은 아직 남아 있습니다. 다음 비전 시험 서비스는 OpenRouter입니다.

파이프라인이 만든 결과를 정답과 비교하고, 평가 엑셀의 **복사본**에 입력하는 도구입니다. 인수인계서 10절을 구현했습니다. 원본 데이터셋을 수정하거나 모델을 호출하지 않습니다.

현재 파이프라인·OCR·검색 엔진은 이 패키지에 포함되지 않습니다. 이 도구를 완성했다는 것은 실제 RAG 성능이 검증되었다는 뜻이 아닙니다.

## 실행 준비

Python 3.10 이상과 openpyxl 3.1 이상을 사용합니다. Python 환경에 필요한 패키지를 설치합니다.

```sh
python3 -m pip install -r requirements.txt
```

이 폴더의 `evaluate.py`를 실행합니다. 아래 경로는 실제 입력 위치로 바꿉니다. `--dataset`은 `files/`, `gold/`, 원본 평가 엑셀이 들어 있는 폴더입니다. 출력 폴더는 새 경로여야 합니다.

```sh
python3 evaluate.py \
  --dataset '/path/to/RAG_예비데이터셋(클로드)' \
  --run-info run-info.json \
  --parsed parsed.jsonl \
  --chunks chunks.jsonl \
  --metadata metadata.jsonl \
  --search search.jsonl \
  --output results/R-001
```

파싱만 평가하려면 `--parsed`만 지정합니다. 네 입력 중 하나 이상이 필요합니다. 제공하지 않은 단계는 미실행, 파일에 일부 문서만 있으면 일부 평가로 기록합니다. 출력 폴더가 이미 있으면 중단하며 원본 안에는 결과를 쓰지 않습니다.

이 Mac에서는 별도 설치 없이 다음 Python으로 실행을 검증했습니다.

```sh
/Users/kangdongkyoon/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3 evaluate.py --help
```

## 결과물

| 파일 | 내용 |
|---|---|
| `evaluation.xlsx` | 원본 서식·수식을 보존한 평가 엑셀 복사본 |
| `report.md` | 단계별 완료 건수, 점수, 검색 판정, 전체 단계 판정 |
| `report.json` | 항목별 상세 결과, 누락 ID, 수동 측정 근거, 입력 파일 SHA-256 |

JSON과 보고서 점수, 엑셀 실행기록의 값은 Python이 직접 계산합니다. 기존 수식 칸은 덮어쓰지 않습니다. **엑셀 수식 화면은 Excel 또는 LibreOffice에서 파일을 열어 재계산해야 합니다.** 자동 재계산 설정을 저장하지만 이 도구 자체에는 Excel 계산 엔진이 없습니다.

검증에 사용한 Artifact Tool 미리보기 계산 엔진에서는 숫자 0을 빈 문자열과 같게 처리하여 검색 실패 두 건을 전체 집계에서 제외하는 차이를 확인했습니다. 따라서 그 미리보기의 검색 점수를 검증 결과로 사용하지 않았습니다. 점수는 `report.json`·`report.md`와 값으로 저장한 실행기록에서 확인하세요. 실제 Excel/LibreOffice에서의 재계산은 이 환경에서 확인하지 못했습니다. 자세한 범위는 `VERIFICATION.md`에 기록했습니다.

기존 실행 이력을 이어가려면 직전 결과를 템플릿으로 지정합니다.

```sh
python3 evaluate.py \
  --dataset '/path/to/RAG_예비데이터셋(클로드)' \
  --template results/R-001/evaluation.xlsx \
  --run-info run-info-R-002.json \
  --parsed parsed-R-002.jsonl \
  --output results/R-002
```

이전 실행기록은 유지하고 현재 실행의 입력 칸은 먼저 비웁니다. 같은 실행ID의 중복 기록은 거절합니다. 이력은 기존 양식의 100회 입력 공간까지 지원합니다. 같은 ID로 재평가할 때는 원본 템플릿과 새로운 출력 폴더를 쓰거나 실행ID를 새로 정합니다.

## 실행 정보

`examples/run-info.json`을 복사하여 실제 실행값을 적습니다. `run_id`, `environment`, `llm_model`, `quantization`, `provider`, `embedding_model`, `prompt_version`, `pipeline_version`, `measured_at`은 필수입니다. 사용하지 않은 모델 항목은 `N/A`로 적습니다. `measured_at`은 날짜 형식 `YYYY-MM-DD`입니다.

- `run_kind`: 실제 파이프라인 결과는 `evaluation`, 평가기 자체를 확인하는 가상 입력은 `synthetic-test`.
- `query_reference_date`: 검색 입력을 제공할 때 필수입니다. 정답 질의의 ‘올해/작년’이 **2026-10 기준**이므로 `2026-10-DD` 날짜만 허용합니다. 검색 파이프라인에도 동일한 기준일을 전달해야 합니다. 파일에 이 날짜를 적는 것만으로 검색 시스템의 날짜가 설정되지는 않습니다.

## 입력 규격

UTF-8 JSONL은 한 줄에 객체 하나를 기록합니다. `.json` 파일은 객체 배열도 지원합니다. ID는 gold 파일의 `doc_id`/`query_id`를 그대로 사용합니다. 중복·미등록 ID, JSON 키 중복, 잘못된 날짜·금액은 입력 오류로 중단합니다.

### 파싱 결과

```json
{"doc_id":"D-005","blocks":[{"type":"paragraph","text":"원문에서 추출한 내용","loc":{"page":1},"heading_path":["제1조"]}]}
```

`blocks`는 배열이며 블록마다 `type`, `text`, `loc` 객체, `heading_path` 배열을 둡니다. 기존 실행은 OCR 텍스트를 넣었습니다. 새 [공통 블록 규격](../common-block-design/SCHEMA.md)은 원문과 해석을 구분합니다. 이 평가기에 연결할 때는 원문을 소유한 블록의 text만 한 번씩 전달하는 변환 계층이 필요하며, claims 등 의미 설명을 문자열 보존 검사에 합치지 않습니다. 결과가 비어 있는 문서는 `blocks: []`로 기록하고 해당 문서 자체를 누락시키지 마세요.

### 청크 결과

```json
{"doc_id":"D-005","chunks":[{"chunk_id":"D-005-C001","text":"청크 본문","context_header":"[거래처 | 계약서 | 날짜 | 제1조]"}]}
```

문서당 한 레코드이며 `chunks`는 배열입니다. `chunk_id`는 문서 안에서 유일해야 합니다. `text`는 **머리말을 제외한 본문**입니다. 머리말은 필수 키 `context_header`에 분리합니다. 머리말이 없으면 빈 문자열을 기록합니다. 청크 안에 `doc_id`를 추가해도 되지만 상위 문서와 일치해야 합니다.

본문이 정말 머리말과 분리되어 있는지는 생산 측의 계약입니다. 평가기는 임의의 머리말을 본문에서 추측하여 삭제하지 않습니다. 머리말 누락 개수·토큰 수·표 헤더 여부는 별도 측정 항목입니다.

### 메타데이터 추출 결과

```json
{
  "doc_id": "D-005",
  "스캔": "N",
  "문서종류": "계약서",
  "거래처": "청람정밀",
  "문서일자": "2025-02-12",
  "사업명": "2025 MES 고도화 구축",
  "대상시스템": "MES",
  "상태": "초안",
  "계약번호": "CT-2025-0112",
  "계약유형": "용역",
  "계약시작일": "2025-03-01",
  "계약종료일": "2025-08-31",
  "금액": "248000000",
  "통화": "KRW",
  "VAT": "별도",
  "견적번호": "N/A",
  "견적유효기간": "N/A",
  "사이트": "N/A",
  "작업명": "N/A",
  "로그시작": "N/A",
  "로그종료": "N/A",
  "실행결과": "N/A",
  "오류코드": "N/A",
  "family": "predicted-family-001"
}
```

위 객체는 입력 구조를 설명하는 예시입니다. 정답으로 간주하거나 실제 실행값으로 복사하지 마세요. JSONL에서는 한 줄로 기록합니다.

`doc_id`와 인수인계서의 **채점 필드 20개**는 모두 필요합니다. `사업명`, `스캔`, `family`는 선택 사항입니다. 빠진 채점 필드를 `N/A`로 추정하여 채점하지 않도록 입력 단계에서 차단합니다. 필드가 존재하며 값이 null·빈 문자열이면 `N/A`로 정규화합니다.

파일명·경로·형식은 doc_id에 대응하는 원본 식별 정보로 채웁니다. 이 세 가지 외에 **정답 메타데이터를 예측값으로 복사하지 않습니다.** 파일명·경로·형식을 입력에 직접 제공한 경우 매핑과 일치하는지 검사합니다. 거래처 별칭을 정식명으로 바꾸는 작업은 파이프라인에서 수행해야 합니다.

- 날짜: `YYYY-MM-DD`만 허용하여 월/일 순서의 추측을 막습니다.
- 로그 시각: `YYYY-MM-DD HH:MM[:SS]` 또는 `T` 구분, 초는 버립니다. 시간대 변환은 파이프라인에서 먼저 합니다.
- 금액: 쉼표·정수형 소수 표현을 정리합니다. `1,234.0` → `1234`. 소수 금액은 현재 인수인계 명세에 맞춰 거절합니다.
- `family`: 모델이 예측한 군집 ID입니다. 정답 ID와 이름이 같을 필요는 없습니다. 단독 문서에도 고유 ID를 부여합니다. 전체 문서에 대한 family 입력이 있어야 통과 판정에 반영합니다.
- `최신본` 정확도는 현재 인수인계서의 자동 채점 대상에 포함되지 않습니다.

### 검색 결과

```json
{"query_id":"Q-001","doc_ids":["D-006","D-005","D-001"]}
```

순위순 문서 ID 목록입니다. 중복 문서는 첫 출현을 남기고, 상위 10개로 제한합니다. 평가 대상 밖 문서 ID는 거절합니다. 정답 중 어느 하나가 처음 나타난 순위를 기록합니다.

- `doc_ids: []`: 실행했지만 검색 결과 없음 → 순위 0, Hit@5 0, RR 0.
- 질문 레코드 자체 없음: 미측정 → 빈칸.
- 정답이 6~10위: Hit@5 0이지만 RR은 1/순위.
- 정답이 11위 이후: 상위 10개 안에 없음 → 순위 0, RR 0.

## 계산과 판정

1. **필수 문자열 보존**: 파싱 전체 텍스트와 정답 문자열의 모든 공백·줄바꿈을 제거해 포함 여부를 확인합니다. 대소문자·구두점·내용은 임의로 바꾸지 않습니다.
2. **잘림**: 파싱에 존재하는 문자열이 어느 청크 본문에도 온전히 없으면 Y입니다. 파싱에서 빠졌거나 청킹 입력이 없는 문서는 빈칸입니다. 잘림 Y는 실제 경계 절단뿐 아니라 청킹 중 누락도 포함하는 인수인계서의 진단 정의입니다.
3. **메타데이터**: 일치/불일치/정상공란/환각/미추출/제외를 구분합니다. 기존 Excel TRIM과 맞추기 위해 앞뒤 ASCII 공백 제거 및 연속 ASCII 공백 축약 후 대소문자를 무시합니다. 이는 문서에 적힌 단순 ‘앞뒤 공백 제거’보다 기존 엑셀의 실제 동작을 따른 것입니다.
4. **사본 묶기**: 문서 쌍의 같은 군집 여부로 평가합니다. 정밀도 분모가 0이면 미측정으로 남깁니다. 군집 이름 자체는 정답과 비교하지 않습니다.
5. **Recall@5**: 이 프로젝트에서는 Hit@5 평균입니다. 모든 정답 문서를 찾은 비율이 아니라, 정답 중 하나라도 상위 5개에 있는 질문의 비율입니다. MRR은 상위 10개 기준입니다.

임계값은 엑셀 `통과기준` 시트의 값을 읽습니다. 운영 처리량 기준은 `용량계획!B18/B19`로 계산합니다. 해당 수식을 다른 구조로 바꾸면 오류를 표시하므로 임의의 Excel 수식을 해석하지 않습니다.

**두 판정을 분리합니다.**

- 검색 최종 판정: 전체 61개 질문을 평가했을 때 전체 Recall@5 기준으로 결정합니다.
- 전체 단계 판정: 단계별 기준과 완료 건수를 함께 봅니다. 미달이 있으면 ‘미달 항목 있음’, 나머지 미측정이 있으면 ‘측정 진행 중’입니다.

일부 결과의 점수는 확인할 수 있지만 전체 통과로 인정하지 않습니다. 엑셀 원래 종합 판정 수식은 완료 건수를 보지 않으므로 별도 보고서와 다를 수 있습니다. 수식은 원본 보존 원칙에 따라 유지합니다. 실행기록의 ‘최종 판정’에는 검색 판정을 넣고, 메모에는 전체 판정과 완료 건수를 남깁니다.

## 별도 측정값

다음 형태의 JSON을 `--manual-metrics`로 제공합니다. 측정하지 않은 항목은 키를 생략하세요. 값을 만들거나 기본 0으로 채우지 않습니다.

```json
{
  "table_cell_accuracy": {
    "value": 0.97,
    "evidence": "표본 100셀 중 97셀 일치. 실제 검수 기록 경로를 여기에 기재"
  }
}
```

예시 숫자 0.97은 실측값이 아닙니다. 아래 키만 지원하며 모두 `value`와 `evidence`가 필요합니다.

| 키 | 단위 |
|---|---|
| collection_rate | 0~1 |
| sync_rate | 0~1 |
| parse_success_rate | 0~1 |
| table_cell_accuracy | 0~1 |
| ocr_cer | 0~1, 과거 OCR 실험 재현용 지원 키 |
| encoding_error_documents | 0 이상 정수 |
| schema_success_rate | 0~1 |
| oversize_chunks | 0 이상 정수 |
| missing_table_headers | 0 이상 정수 |
| missing_context_headers | 0 이상 정수 |
| throughput_docs_per_hour | 0 이상 숫자 |

사본 묶기 정밀도·재현율은 metadata의 family로 계산해 엑셀 수동 입력 칸에 자동 기록합니다. 이 값은 별도 실측값으로 덮어쓸 수 없습니다.
