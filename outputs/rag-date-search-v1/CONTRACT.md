# 날짜 검색 및 수정일 수집 계약 v1

- 유료 API, 비전·임베딩 모델, 외부 네트워크를 호출하지 않는다. 기존 파싱·보강·검색 실행과 원본 gold를 보존한다.
- 원본 파일을 읽어 해시가 파싱 입력과 같은지 확인하고 `stat.st_mtime_ns`를 수집한다. 수집 중 변경·경로 이탈·해시 불일치는 실패 처리한다. UTC 시각과 나노초 값, 수집시각, 출처를 함께 저장한다. 수정일은 작성일·제출일·승인본 여부를 의미하지 않는다.
- 공통 블록 1.0과 보강 1.1은 유지한다. 새 `source-metadata.jsonl`, `date-metadata.jsonl`을 문서 ID와 원본 해시로 연결하고, 색인의 문서에 `date_metadata`를 넣는다. 새 날짜를 검색 본문에 끼워 넣어 기존 BM25 가중치를 바꾸지 않는다.
- `표지일`은 cover_date, `작성일`은 explicit_written_date만 사용한다. 원문 대표일인 기존 문서일자를 대체하지 않는다. 같은 역할의 여러 날짜가 충돌하면 needs_review, 네이티브에서 관찰되지 않으면 not_observed_native다. 비전 미처리 여부도 함께 보존한다.
- 파일 수정일을 요청한 최신순 검색에만 수정일 정렬을 적용한다. 모든 조건·본문 후보를 적용한 후 전체 후보를 정렬하고 마지막에 limit을 적용한다. 동일 수정시각이면 관련성 점수, 문서 ID 순이다. 최신 수정은 최신 승인본과 다르다.
- 수정일의 날짜 조건은 Asia/Seoul의 하루·월·연도를 UTC 반개구간으로 바꾼다. 역할별 본문 날짜는 YYYY-MM-DD 범위다. 명확하지 않은 다중 역할·날짜·부정·비교 표현은 확인 필요 상태로 남긴다.
- 수정일이 없는 문서는 최신순 결과에서 제외하고 미확인 목록으로 반환한다. 날짜 필터는 추출이 확인된 값만 통과시킨다. 지원하는 메타데이터 조건 검사와 전체 의미 조건 충족은 구분한다.
- 기존 61문항은 같은 기준일 2026-10-17과 원본 정답으로 비교한다. 날짜 전용 개발 검사를 별도 보고하고 기존 점수에 합산하지 않는다. 메타데이터 정답 기준 변경 전후 점수도 분리한다.
- 독립 평가는 새로운 원본·질문·별도 검수 라벨이 있어야 실행 완료로 인정한다. 기존 문서의 변형 질문·합성 경계 테스트는 독립 평가가 아니다.
