구성도는 이미 검수한 노드·연결 관계를 재사용했고, 계약서·견적서·로그의 명확한 값은 기존 추출을 유지했다. 93개가 앞으로도 LLM이 전혀 필요 없다는 뜻은 아니다. 이번에 추가하기로 한 의미 정보의 필요성에 따른 분류다.

LLM은 문서의 원문 구절들을 읽고 의미별 필드에 해당하는 구절 번호를 골랐다. 프로그램이 그 번호를 원문 문자열·블록 ID·위치·문자 범위에 연결했다. **요약도 LLM이 선택한 핵심 원문을 모은 발췌형 요약**이다. 새 문장으로 다시 쓴 서술형 요약과 구분한다. 모든 필드를 무조건 채우거나 전체 내용을 빠짐없이 요약하도록 요구한 것은 아니며, 주요 항목만 저장하고 `exhaustive=false`로 기록했다.

이 방식은 기존 금액·날짜를 덮어쓰지 않고, 원문에 없는 표현이 생성되는 문제를 줄이기 위한 이번 인덱싱의 구현 선택이다. [실제 프롬프트](PROMPT.txt), [문서별 입력](inputs/), [요청 원본](requests/), [응답 원본](responses/)을 보존했다. 기존의 장문 메타데이터 비교 테스트 프롬프트·설정과 다르므로 속도나 성적을 그대로 비교하지 않는다.

## 임베딩·벡터 색인 방식

- Orin의 기존 `/media/sdcard/models/bge-m3` 파일을 읽기 전용으로 사용했다. 새 모델 다운로드는 없다.
- 기존 로컬 Docker 이미지를 사용한 일회성 `rag-bge-m3-index-001` 컨테이너에서 실행했다. 외부 네트워크는 차단했다. Qwen 서버 설정은 바꾸지 않았다.
- CLS 벡터를 L2 정규화했다. 모델 연산은 FP16, 저장 벡터는 FP32다. 모델 설정·토크나이저·가중치 해시를 기록했다.
- 모든 입력의 실제 토큰 수를 먼저 계산하고 8,192토큰 이내임을 확인했다. 자동 잘라내기는 하지 않았다.
- 기존 본문 청크는 제목·문맥·표 머리말·본문을 입력으로 사용한다. 추가 17청크는 검수된 의미 필드와 발췌 요약이며, 원문 청크와 구별되는 `semantic_metadata_excerpt` 유형이다.
- Mac에서 FAISS `IndexIDMap2(IndexFlatIP)` 색인 파일을 만들었다. 벡터 생성은 Orin에서 수행했다. 이 규모에서는 근사 색인이나 별도 학습 없이 전체 벡터를 저장하는 방식을 사용했다.
- BM25와 벡터 색인은 동일한 청크 ID에 연결된다. 검색 결과 결합 방식·가중치·필터·답변 방식은 아직 구현하지 않았다.

공식 구현 근거: [bge-m3 모델 문서](https://huggingface.co/BAAI/bge-m3), [FAISS 시작 문서](https://github.com/facebookresearch/faiss/wiki/Getting-started). 모델의 sparse/ColBERT 기능은 이번에 사용하지 않았으며 기존 BM25를 유지했다.
