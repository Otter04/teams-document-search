# Q-130·Q-131 표현 변형 검색 평가

2026-10-25. search-1.7.4의 규칙·코드·설정과 기존195문서·3,754청크 Elasticsearch v003 색인을 유지한 실제 검색 평가다. 신규 파싱·문서 보강·문서 임베딩·색인 변경·외부 유료 API 호출은 하지 않았다. 질문 임베딩과 기존 정책의 Orin 질문 분석은 실행했다.

## 결론

직전 개선은 Q-130·Q-131의 실패를 보고 추가한 어휘 규칙이다. 질문 ID·문서 ID·정답 숫자를 코드에 지정하지는 않았지만, 관찰한 실패에 맞춘 개발용 개선이라는 점은 분명하다. 이번에는 규칙을 먼저 고정하고 표현을 바꿔 확인했다.

16개 변형 중10개(62.5%)만 필수 정답 문서가 최종 상위5에 포함되었다. 등록된 관련 어휘를 유지한8개는8/8(100%), 어휘를 크게 바꾼 간접 표현8개는2/8(25%)다. 원문2개는 별도 대조군이며 모두 정답1위. 같은 의미를 어떤 표현으로 물어도 찾는 수준은 아직 아니다. 결과를 보고 규칙을 추가하지 않았다.

## 정답 기준과 원문

- Q-130 정답 D-178 `OUDC_질의 답변서_250910.docx`: 디스크 폐기 질의에 대해 공사 직원 입회하에 물리 파쇄하고 파쇄 확인서를 제출하도록 답한 자료다. 질의서 D-176·D-177은 방법을 묻는 문서이므로 답변서 대신 성공으로 인정하지 않았다.
- Q-131 정답 D-175 `온새미도시공사_시설관리시스템 노후서버 교체_제안요청서.pdf`: 기술 평가80점, 가격 평가20점이라는 기준을 포함한다. 단순한 제안서나 평가 계획이라는 이유만으로 정답으로 인정하지 않았다.

## 방법과 해석의 범위

각 질문을 가까운 어휘4개·간접 표현4개로 바꿔 총16개를 만들고, 검색 실행 전에 cases.json과 inputs.jsonl의 해시를 고정했다. 원문2개도 대조용으로 추가했다. 정답 ID는 로컬 채점 자료에만 저장했고 검색 API에는 질문·기준일2026-10-14·기존 설정만 전달했다. 실행 순서는 가까운/간접 표현 순서이며 무작위 순서는 아니다.

두 질문의 의미를 유지하려 했지만 간접 표현에는 본래 질문보다 문서 단서가 줄거나 표현이 더 넓어지는 경우가 있다. 예를 들어 Q-130-P07은 처분 방법을 물어본 답이라는 맥락을 유지하면서도 '버려도 되는지'라는 허용 여부 표현을 쓴다. 규칙을 알고 만든 소규모 탐색 시험이므로 독립 검증 성적이나 전체 서비스 정확도로 해석하면 안 된다. 다만 상대적으로 직접적인 '하드를 버릴 때 어떻게 처리하라고 알려 준 자료'에서도 실패했으므로 일부 표현의 모호성만으로 모든 실패를 설명할 수는 없다.

## 실패가 발생한 지점

1. **등록되지 않은 표현은 새 어휘 규칙이 작동하지 않는다.** 가까운 표현8개에서는 새 규칙이 모두 작동했고 간접 표현8개에서는 모두 작동하지 않았다. '하드/기록매체/데이터를 담은 부품'과 '버리다/없애다/못 쓰게 만들다', '잘 수행할 능력/완성도/수행 수준'과 '중요하게 보다/높게 쳐 주다'를 등록 어휘와 연결하지 못했다.
2. **실패6개 중5개는 정답이 의미 후보에는 있었다.** Q-130-P05/P07 및 Q-131-P05/P06/P07은 각각 의미 검색의26·18·32·10·24번째 청크로 정답이 들어왔고 순위 조정 후보에도 남았다. 하지만 최종 문서 상위5에서는 제안서·장비 목록·계약서·질의서 등에 밀렸다. 즉 '벡터 검색이 아예 못 찾았다'고만 설명하면 틀리다. '원래 질문에서 작동하던 어휘 및 근거 우선순위가 간접 표현에서는 빠졌고, 기존 결합·문서 순위에서 밀렸다'가 관찰과 부합한다.
3. **Q-131-P08은 두 후보 목록에서 모두 정답이 없었다.** 이 질문은 기술/품질·점수/배점·평가/심사 표현군을 쓰지 않는다. '제안'을 '제안서' 종류로 해석하는 별도 기존 규칙도 작동했다. 필터는 비어 있으므로 강제 제외라고 단정할 수는 없으며 어휘 연결 부재와 문서 종류 선호가 함께 관찰된다. 각 요인의 기여도는 별도 비교 시험 없이 확정하지 않는다.
4. **정답을 찾더라도1위가 보장되지는 않는다.** Q-131-P01은 새 어휘 규칙이 작동했지만 '제안 심사'를 문서 종류 '제안서'로 해석했다. 원문 표현 우선 대상 선정에서 제안요청서 정답이 빠져 preferred_doc_ids가 비었고 최종4위였다. 간접 표현 Q-130-P06/P08은 새 규칙 없이 의미 후보를 통해 각각5위·4위로 찾았다.
5. **LLM 질문 분석은 보완하지 못했다.** 전체18요청 중14회 시도했지만 모두2.5초 제한에서 시간 초과했다. 채택0회이며 나머지4개는 분석을 시도하지 않았다. 따라서 이번 결과는 실제로 규칙 해석과 BM25+bge-m3 의미 검색 및 기존 결합·순위 조정으로 나온 결과다.

## 시간·보존·후속 상태

18요청44.67초, 평균2.480초, HTTP/실행 오류0건. 이전150개 평가와 실행 중 서버 Python 코드 해시·설정·색인명과 개수·임베딩 지문이 동일했다. 실행기는 평가 전후 설정·색인 상태도 비교했다. 로컬 검색 코드, 이전150개 응답, 이번 고정 질문 파일의 해시도 유지되었다. 이번에 Elasticsearch 전체 내용 해시를 새로 검증한 것은 아니다.

기존150개 148/150(98.7%)는 직전 평가 기록이며 이번에150개를 다시 실행한 값이 아니다. 이번에는 변경 없는 검색 시스템에16개 변형과2개 대조만 추가 실행했다. 새 테스트를150개에 섞거나 기존 정답을 고치지 않았다. 다음 개선을 한다면 단어 사전을 계속 늘리는 것만으로 충분한지, 질문의 동작·답변 의도와 문서 종류를 구분하는지, 의미 후보에 들어온 정답이 왜 최종에서 밀리는지 따로 검토할 필요가 있다. 이번 요청에서는 그 개선을 실행하지 않았다.
