# 작업 재개 기록 — “이어서”

기록일: 2026-10-20. 사용자는 VPN을 끊고 나중에 다시 작업하기로 했다. **사용자가 “이어서”라고 하면 이 파일을 먼저 읽고 VPN·SSH·서버 상태를 확인하여 기존 서비스를 복구한 뒤 검색 품질 보완을 이어간다.** 사용자가 다른 방향을 추가하면 그 지시를 우선한다. 예약 실행이나 자동 재접속 요청은 아니다.

## 최신 재개 상태

사용자의 VPN·SSH 재연결 및 “이어서” 요청으로 작업을 재개했다. 현재 배포는 `search-1.2.0`이다. 키워드·의미·결합 청크 순위와 R1 후 순위(날짜 질문은 전체 일치 자료 날짜순), 최종 문서 결과를 단계 완료 시 표시한다. 계산식은 표시하지 않는다. 기존 61질문 순서·정답 포함률 59/61 유지, 동작 검사 24개 통과. [최신 보고서](outputs/search-rank-trace-001/REPORT.md). 다시 접속할 때 아래 절차를 사용하되 최신 버전은 이 절을 기준으로 한다.

## 최신 확장 평가

현재 평가세트는 사용자 첨부를 등록한 99질문(`datasets/search-gold-v2/`)이다. 새 간접 표현 30개는 지정 대표 문서 기준 25/30, 문서군 기준 26/30. 이전 61질문 결과 순서는 유지됐다. [평가 보고서](outputs/search-gold-v2-run-001/REPORT.md)에 실패 5질문을 기록했으며 검색 튜닝은 수행하지 않았다. 과거 61개만의 성적과 새 30개 성적을 혼동하지 않는다.

## 접속과 서버 복구 순서

1. 사용자가 VPN에 다시 로그인했는지 연결 상태로 확인한다. VPN이 꺼져 있으면 사용자에게 로그인만 요청한다. 비밀번호·API 키를 대화나 문서에 저장하지 않는다.
2. Mac SSH 공유 연결 `ubuntu@192.168.60.40`, 소켓 `/Users/kangdongkyoon/.ssh/rag-orin.sock`을 확인한다. 오래된 소켓 파일의 존재만으로 연결 성공을 판정하지 않는다.

```bash
ssh -S /Users/kangdongkyoon/.ssh/rag-orin.sock -O check ubuntu@192.168.60.40
```

3. 기존 연결이 살아 있으면 재사용하고 터널의 실제 응답을 확인한다. 연결이 없으면 일반 Mac 터미널에서 인증 연결을 다시 만든다. 아래는 **재개 시 사용할 예시**이며 이번 기록 작업에서는 실행하지 않았다. 먼저 소켓·로컬 18020 포트를 점검해 중복 실행을 피한다. 오래된 소켓 충돌은 활성 연결이 없음을 확인한 후 정리한다.

```bash
/usr/bin/ssh -M -S /Users/kangdongkyoon/.ssh/rag-orin.sock \
  -o ExitOnForwardFailure=yes \
  -o ServerAliveInterval=30 -o ServerAliveCountMax=3 \
  -L 127.0.0.1:18020:127.0.0.1:8020 \
  -N ubuntu@192.168.60.40
```

비밀번호가 필요하면 사용자가 직접 입력한다. 인증 후 출력 없이 대기하는 것은 터널 유지 상태일 수 있으므로 별도 연결 검사로 확인한다. 서버 호스트 키가 변경되면 기존 검증을 무시하고 자동 수락하지 않는다.

4. SSH 접속 후 `docker ps -a`로 기존 컨테이너 상태를 확인한다. 실행 중이면 재시작하지 않고, 꺼진 서비스만 기존 컨테이너로 시작한다. 모델 다운로드, 컨테이너 재생성, 색인 재생성은 기본 복구 절차가 아니다.

| 서비스 | 기존 컨테이너 | Orin 확인 주소 |
|---|---|---|
| 검색 저장소 | `rag-elasticsearch` | `http://127.0.0.1:9200` |
| Qwen 모델 | `rag-qwen36` | `http://127.0.0.1:8001/v1/models` |
| 검색 API·화면 | `rag-search` | `http://127.0.0.1:8020/health` |

Elasticsearch와 Qwen을 먼저 준비시키고 검색 API를 시작한다. Qwen 준비는 `/v1/models`뿐 아니라 컨테이너 로그의 로딩 완료와 실제 요청 가능 상태도 확인한다. 시작 실패 시 로그를 보고 원인을 확인하며 현재 문맥 49,152·KV 캐시 8GiB·기존 AWQ4 모델 설정을 임의로 바꾸지 않는다. 다른 사내 컨테이너는 건드리지 않는다.

5. 검색 API `ready:true`, 버전 `search-1.2.0` 또는 이후 사용자 승인 변경 버전, 기본 B+R1을 확인한다. 기존 별칭 `rag-documents`/`rag-chunks`와 검색용 `rag-search-documents-v001`/`rag-search-chunks-v001`은 각각 110문서/1,089청크였음을 대조한다. 다르면 기록과 실제 변경 원인을 먼저 확인한다.
6. Mac `http://127.0.0.1:18020/`에서 위 작성일 질문 1건으로 연결·정렬·근거 표시를 확인한다. 건강 점검에 전체 61질문 평가나 전체 인덱싱을 반복할 필요는 없다. 코드를 바꾸면 관련 동작 검사와 회귀 평가를 수행한다.
