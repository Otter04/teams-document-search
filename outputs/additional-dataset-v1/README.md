# 추가 평가 데이터셋 v1

2026-10-18. **새 합성 원본 30문서·질문 60개·근거가 연결된 정답 초안을 제작하고 최초 파싱·검색 평가까지 실행했다. 별도 사람 검수는 아직 없다.**

모든 회사명·사업·금액·일정·로그는 이 평가를 위해 구성한 가상 정보다. 기존 110문서의 복사·이름 변경·형식 변환본은 사용하지 않았다. 같은 assistant가 규칙을 알고 자료와 정답을 만들었으므로 독립적인 실제 업무 성능을 입증하는 자료로 부르지 않는다. 새 결과를 보고 규칙을 개선하면 이 세트는 개발 자료로 취급해야 한다.

## 구성

| 형식 | 문서 수 | 내용 |
|---|---:|---|
| DOCX | 5 | 용역·유지보수·구매 계약, 명시적 작성일과 무라벨 초안 날짜 |
| PPTX | 5 | 2슬라이드 제안서, 표지 날짜·요구 조건·행열 표 |
| XLSX | 5 | 견적 메타데이터와 품목 표, 수량×단가 및 합계 수식 |
| PDF | 5 | 제안서 2, 구성도 2, 스캔 견적서 1 |
| TXT | 5 | 점검·회의·메일·시험·복구 메모. CP949 문서 1개 포함 |
| LOG | 5 | 전환·재시작·부하·대사 작업, 경고 후 성공과 최종 실패 |

거래처 5개와 MES/ERP/WMS/TMS/PACS/학사정보시스템/온라인몰을 포함한다. 같은 거래처의 관련 문서를 하나의 문서군으로 기록했다. 기존 개발 세트와 파일 해시·문서군 키 중복은 0건이다. 이는 기계적인 중복 검사이며, 의미상 독립성을 사람이 검수한 결과는 아니다.

질문은 관련 문서 검색 48개(그중 스캔 내용 의존 1개), 수정순 정렬 6개, 네이티브 확정 결과 없음 3개, 확인 질문 필요 3개다. 정답이 여러 개인 질문과 한영 표현·표의 수량 조건·로그 문맥·날짜 역할을 포함한다. 구조와 언어는 합성 자료의 제한된 양식이며 실제 업무 문서 전체를 대표하지 않는다.

## 파일과 정답 검토

- [원본 파일](files/): 실제 6개 형식의 문서 30개.
- [질문](package/queries.jsonl): 질문과 반환 개수만 담은 검색 입력.
- [검색 정답 초안](package/answers.jsonl): 정답 문서·정렬 순서·근거 위치. 검색 입력과 분리.
- [메타데이터 정답 초안](package/metadata-labels.jsonl): 30문서 × 23필드, 총 690칸. 값·적용 제외·미관찰·미확정과 근거.
- [질문별 검토 문서](review/QUESTIONS_REVIEW.md), [필드별 검토 문서](review/METADATA_REVIEW.md): 원본 링크와 근거, 검수 기록란.
- [최초 평가 결과](../additional-evaluation-run-001/README.md): 새 자료의 실패 원인 포함.

`reviewer_id`는 모두 null이며 `review_status`는 `assistant_source_checked_pending_human`이다. 원문을 대조한 정답 초안과 별도 사람이 검수한 정답을 구분한다. 기존 독립 평가기는 이 패키지를 정식 독립 정답으로 받아들이지 않는다. 별도의 초안 평가기가 같은 검색·채점 함수를 사용하고 결과에 `independent_evaluation: false`를 기록했다.

9개 필드는 미확정으로 분리했다. H-004의 무라벨 초안 날짜 1개와 H-020 스캔의 본문 날짜·금액·번호 등 8개다. 스캔의 예상 내용은 [후속 비전 검토용 초안](review/vision-ground-truth-draft.json)에 별도 보관하고 네이티브 색인에 주입하지 않았다.

## 확인한 범위

- 30문서의 파서 실행·공통 블록 스키마 검사 오류 0건. 블록 387개, 검색 청크 69개.
- 29개 네이티브 문서에서 원본 문자열 529/529 보존. 표·셀·수식 캐시 301/301 비교 통과.
- DOCX 5페이지, PPTX 10슬라이드, XLSX 5시트, PDF 5페이지를 렌더링해 읽기·표시 상태를 확인했다. DOCX의 한글 누락은 격리 렌더러 글꼴 설정으로 해결했다.
- 스캔 H-020의 네이티브 본문은 비어 있다. PPTX 10슬라이드와 스캔 1페이지, 총 11단위는 기존 파서의 보수적인 비전 검토 대기 목록에 남아 있다.
- 규칙·파서 동결, 정답의 검색 전 고정, 입력 해시, 가짜 검수자·정답 유입·빈 평가 입력 거부를 확인했다. [검증 기록](review/verification.json).

원문 문자열·셀 보존은 의미 해석 전체가 옳다는 뜻이 아니다. 표의 의미상 헤더 판정, 이미지 이해, 실제 업무 문서 일반화는 별도 평가 대상이다.

## 파일 수정시각과 이동

파일 수정시각은 이 합성 실험을 위해 저자가 지정했다. 실제 고객의 수정·제출·승인 기록이 아니다. 원본의 시각은 [source-files.jsonl](source-files.jsonl)에 해시와 함께 보관했다. 작성일·표지일·파일 수정일을 서로 대신 쓰지 않는다.

폴더나 ZIP을 다른 위치로 옮기면 수정시각이 달라질 수 있다. 아래 명령은 선언된 합성 시각을 복원하며, 평가 정답 파일을 읽지 않는다. `--apply`를 빼면 확인만 한다.

```sh
python3 restore_synthetic_mtimes.py --apply
```

이후 [기존 파서](../rag-parser-v3/README.md)에 `files/`와 `parser-manifest.jsonl`을 입력하고 [색인 빌더](../rag-date-search-v1/README.md)에 해당 파싱 결과·`files/`·`reference-data.json`을 전달한다. 정답은 빌더 입력이 아니다. 기존 폴더를 덮어쓰지 않고 새 실행 경로를 사용한다.

## 다음 판단
