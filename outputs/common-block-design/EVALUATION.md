# 공통 블록 및 비전 해석 평가 설계

작성일: 2026-10-15 · 상태: 초기 기준 제안, 모델 평가 미실행

후속 실행(2026-10-16): [네이티브 파싱·원문·표 표본 평가](../parsing-run-003/README.md)를 실제로 수행했습니다. 비전 모델 및 의미 평가의 미실행 상태는 유지합니다.

목적은 **필요한 내용을 빠짐없이, 원래의 구조와 의미를 유지한 채, 근거 위치를 붙여 추출했는지** 확인하는 것입니다. JSON이 만들어졌다는 것과 파싱 품질이 좋다는 것을 구분합니다. 아래 임계값은 다음 개발 실험에 적용할 제안값이며, 측정 성적이나 사용자 승인 완료 기준이 아닙니다. 독립 검수한 자료와 실제 모델 실행으로 적정성을 검토해야 합니다.

## 먼저 평가 대상과 정답을 고정

1. 입력 문서 목록과 SHA-256, 페이지·슬라이드·시트·문단/줄 범위, 처리할 그림·표 영역을 파서 출력과 별도로 저장합니다. 어떤 대상을 처리하지 못했는지도 분모에 남깁니다.
2. 원본에 필수인 글자, 표의 앵커 셀과 병합, 제목/캡션 관계, 구성도의 대상·선·방향, 의미상 꼭 찾아야 하는 사실을 주석으로 만듭니다.
3. 주석에 원본 위치와 critical 여부를 붙입니다. 금액·기간·IP·모델명·방향 등 중대한 항목은 실행 결과를 보기 전에 지정합니다.
4. 모델 출력과 독립적으로 원본을 검수하고, 이견은 해결 기록을 남깁니다. 같은 모델의 응답을 정답으로 복사해 독립 평가라고 부르지 않습니다.
5. 모델·프롬프트·입력 이미지·규격·정답 버전·정규화·평가 코드를 고정합니다. 수정에 사용한 개발 세트와 마지막 확인에만 사용할 별도 세트를 분리합니다.

`annotations/D-069-draft.json`과 `D-044-draft.json`은 원본을 확인해 준비한 **검수 전 주석 초안**입니다. 설계 예시와 같은 작성자가 만들었으므로 이 둘의 일치율은 모델 정확도나 독립 검증을 뜻하지 않습니다. D-044 좌표는 표 전체 영역이며 셀별 위치 정답으로 사용할 수 없습니다.

## 지표와 초기 제안값

| 구분 | 측정 정의 | 초기 통과 제안 |
|---|---|---|
| 입력 완전성 | 독립 목록의 문서·필수 처리 단위와 출력 상태를 대조 | 목록 누락 0, 필수 단위 처리 완료 100% |
| 스키마·참조 | JSON Schema, ID 유일성, 부모/근거/자산 참조, 좌표 범위, 표 셀 겹침 | 오류 0 |
| 영역 분리·유형 | 정답 문단/표/그림 영역과 예측 영역을 1:1 대응, 종류 일치와 IoU≥0.5일 때 정답 | 영역·유형 F1≥0.95, 치명적 누락 0 |
| 읽는 순서·문맥 | 순서가 지정된 블록 쌍의 앞뒤 일치율, 제목/캡션 연결의 P/R/F1 | 순서≥0.98, 문맥 연결 F1≥0.95 |
| 필수 문자열 | 기존 346항목이 원문 채널에 보존됐는지 | 전체≥0.98, 각 형식 및 비전 대상 하위 집단도≥0.98 |
| 핵심 값 | 사전 지정한 금액·기간·IP·장비 모델·수량 등을 해당 셀/영역에서 정확 비교 | 100%, 틀린 대상에 연결한 값도 실패 |
| 표 구조 | 각 셀의 (행, 열, row_span, column_span) 앵커 튜플 및 헤더 역할을 비교 | 구조 F1≥0.95, 헤더 역할 F1≥0.95 |
| 표 내용 | 구조 대응 셀의 text를 정규화 후 정확 비교, 추가/누락 셀도 오답 | 셀 내용 P/R/F1 각각≥0.95, 핵심 셀 100% |
| 구성도 대상 | 대상의 이름·위치 일치 여부를 1:1 비교 | 노드 P/R/F1 각각≥0.95 |
| 구성도 연결 | 대응 노드의 양 끝, 선의 방향·라벨을 비교 | 관계 P/R/F1 각각≥0.90, 중대한 허위 연결·방향 0 |
| 의미 설명의 정확성 | 원본이 뒷받침하는 관찰 주장 / 제출한 모든 관찰 주장 | ≥0.98, 중대한 근거 없는 주장 0 |
| 의미 설명의 완전성 | 사전 정의한 필수 사실 중 정확히 표현한 사실 / 필수 사실 | ≥0.90 |
| 근거 위치 | 근거를 요구하는 출력 항목에 실제 유효한 위치가 있는 비율 | 참조 존재 100%, 위치 정답률≥0.95, 핵심 항목 100% |

P(정밀도)=TP/(TP+FP), R(재현율)=TP/(TP+FN), F1=2PR/(P+R)입니다. TP는 맞춘 항목, FP는 추가했거나 잘못 만든 항목, FN은 놓친 항목입니다. **빈 출력이나 전부 판단 불가로 답한 출력은 누락과 필수 사실 재현율 때문에 통과하지 못합니다.**

각 지표는 전체 합산값과 문서별 평균, 파일 형식별·표/구성도/사진별 값을 함께 보고합니다. LOG의 많은 줄이 소수 구성도의 실패를 가리지 않게 하고, 문서별 치명적 오류를 평균 점수로 상쇄하지 않습니다. 범주에 실제 평가 사례가 없으면 `not_evaluated`로 기록하고 100점으로 넣지 않습니다. 별도의 사진 자료가 없으면 “사진까지 검증된 파싱 완료”로 판정할 수 없습니다.

이 단계의 품질 통과는 모든 해당 필수 기준을 만족해야 합니다. 운영 장애 허용률·가용성은 별도 기준입니다. 실패 문서가 있어도 성공 문서만 모아 높은 점수를 보고하는 방식을 허용하지 않습니다. 일부 평가의 상세 점수는 참고로 계산할 수 있으나 전체 판정은 `incomplete`입니다.

## 세부 판정 규칙

### 원문·중복·분리

기본 문자열 정규화는 Unicode NFC와 공백 처리뿐입니다. 기존 평가기의 346항목 비교는 공백 제거 규칙을 유지해 비교 가능하게 보고합니다. 단, 이 기존 검사는 여러 블록을 합쳐 찾으므로 **잘못된 셀·대상에 붙은 값이나 과도한 병합을 검증할 수 없습니다.** 핵심 값과 구조 검사를 함께 통과해야 합니다.

`×`를 `x`로, 다른 숫자·하이픈·부호·IP를 정답에 맞춰 바꾸지 않습니다. 대소문자·쉼표·날짜 형식의 다른 허용 규칙이 필요하면 정답 작성 전에 해당 항목별로 정의하고 별도 지표로 보고합니다. 원문 채널에 없는 문장을 claims에서 가져와 필수 문자열을 맞히지 않습니다.

영역 정답은 의미 단위인 문단·표·그림 수준으로 작성합니다. 표 컨테이너와 내부 셀을 같은 영역 검사의 분모로 중복 계산하지 않습니다. 한 문단을 잘게 쪼개거나 두 영역을 하나로 합친 경우 1:1 대응에서 남는 항목이 FP/FN이 됩니다. 의도적인 복합 영역은 주석 단계에서 기준을 고정합니다. 페이지·줄·셀 주소만 있는 원본은 논리 위치의 일치로 검사하며 bbox가 있는 자료와 별도 보고합니다.

읽는 순서는 표의 행·열, 다단 문서, 슬라이드 배치를 원본과 비교합니다. 제목 경로가 달라지거나 표의 값이 다른 헤더에 연결되면 문맥/구조 오류입니다. 동일한 문자열이 여러 곳에 실제로 존재할 수 있으므로 전체 문자열만 보고 일괄 중복 제거하지 않습니다. 네이티브 추출과 비전 해석의 중복은 원본 영역과 소유 블록을 기준으로 조정합니다.

### 표·병합·읽을 수 없는 값

표 영역은 문서·페이지/시트·위치를 이용해 1:1 대응시킨 뒤 셀을 평가합니다. 구조 TP는 앵커와 span이 모두 같은 셀입니다. 내용 TP는 위치·span 및 정규화한 내용이 모두 맞는 셀입니다. 전체 정답 셀을 재현율 분모, 전체 예측 셀을 정밀도 분모로 삼으므로 누락한 셀을 평가에서 빼지 못합니다.

병합 셀을 여러 셀로 복제하면 추가 셀로 판정합니다. 빈 셀도 격자 정답에 포함합니다. 원본이 실제로 읽을 수 없는 셀은 검수자가 판독 불가로 주석하고 구조 검사에는 남기되 문자열 정확도 분모에서 제외한 수를 공개합니다. 모델만 unreadable로 표시한 읽을 수 있는 셀은 누락입니다.

비전이 표 값을 옮겨 적었어도 단가를 금액에, 갑의 주소를 을의 주소에 넣었다면 오답입니다. D-044의 마지막 주소처럼 여러 줄이 한 셀에 속하는 경우 줄 수가 아니라 셀 경계와 관계를 기준으로 평가합니다.

### 구성도·사진·차트의 의미

노드는 원문 이름과 위치로 1:1 대응하며 같은 이름의 상자는 위치로 구분합니다. 명시적 라벨이 없는 대상은 사전에 정의한 객체 종류·위치 기준을 사용합니다. bbox는 IoU≥0.5를 기본 대응 조건으로 쓰되 흐릿한 경계나 큰 선 영역은 검수 근거를 남겨 판단합니다. 모델 결과를 본 뒤 매칭 기준을 유리하게 바꾸지 않습니다.

관계는 대응 노드 쌍·방향·라벨이 모두 일치해야 정답입니다. undirected 관계는 양 끝 순서를 바꿔도 같고 forward는 바꿀 수 없습니다. undirected를 bidirectional로 바꾸면 “화살표 없음”을 “양방향 화살표 있음”으로 바꾼 것이므로 오답입니다. 빠진 노드의 연결선도 빠진 관계로 집계합니다.

claims는 한 문장에 한 사실을 기본으로 하며, 복합 주장은 평가자가 원자적 사실로 분해합니다. 각 관찰 사실은 `supported`, `contradicted`, `unverifiable`로 판정하고 마지막 두 종류를 정확도 분자의 정답으로 세지 않습니다. 원본이 뒷받침하는 각 사실과 제시한 근거 위치를 같이 확인합니다.

구조화된 노드·관계 자체도 관찰 주장으로 평가합니다. claims 문장이 비어 있어도 정확한 관계가 필수 사실을 표현하면 재현율에 반영할 수 있습니다. 같은 사실을 관계와 문장에 중복 표현해도 재현율 정답 수는 한 번만 셉니다. 서로 모순된 중복 주장이 있으면 오류를 별도로 기록합니다.

`inferred`는 별도 목록에 전부 공개하며 필수 관찰 사실 재현율의 정답으로 세지 않습니다. 이 이름표를 붙여 허위 연결·단정이 평가를 피할 수 없도록, 검색 입력과 사용자 결과에 추론이 섞이지 않는지도 확인합니다. 모델의 자체 confidence는 품질 점수로 사용하지 않습니다.

사진의 물체 개수·배치·행동·주변 캡션과의 관계를 주석합니다. 외관만 보고 상태·원인·기종을 단정하면 근거 부족입니다. 차트의 축·단위·범례·추세·인쇄된 수치는 별도 필수 사실로 주석합니다. 그림의 숫자를 원문과 구별 없이 추정해 넣으면 실패입니다.

### 원본 위치

네이티브 자료는 문단/도형/셀/줄이 정확히 맞는지 확인합니다. 이미지 자료는 같은 페이지/슬라이드의 대상 영역과 비교하고, 근사 영역은 IoU≥0.5를 초기 기준으로 사용합니다. 전체 페이지를 모든 주장에 붙이면 작은 객체의 위치 기준을 통과할 수 없습니다. 구성도의 연결선 근거는 선을 포함한 영역과 양 끝 대상의 일치를 함께 확인합니다.

## 현재 예비 세트가 확인해 줄 수 있는 범위

| 영역 | 현재 근거 | 추가로 필요한 검증 |
|---|---|---|
| 필수 문자열 | 기존 346항목, 110문서 | 새 출력의 원문 투영 후 다시 측정 |
| 스캔 문서 | D-044 2쪽, D-069 1쪽, D-102 2쪽 | 5쪽 전체에서 누락·잘못 만든 표·구성도 해석 검사 |
| 단순 스캔 표 | 기존 원본 대조 표 2개, 16셀 | 셀별 위치 주석·독립 검수. 복잡한 병합/선 없는 표는 별도 보강 |
| Excel 병합 | D-003 A1:F1 실제 병합 예시 | 복잡한 다중 헤더·수식/캐시 없음·숨김 영역의 실제 자료 추가 |
| 구성도 | D-069의 8상자·7선 주석 초안, D-007 도형 문자 예시 | D-007 렌더링과 선 주석, 교차선·양방향·흐릿한 선·복수 그림 사례 |
| 사진의 의미 | 이번에 확인한 실제 사진 평가 사례 없음 | 사진+캡션+주변 문단이 있는 독립 세트 |
| 차트/다단/복합 레이아웃 | 이번 패키지에서 정답·성능 검증하지 않음 | 축·범례·수치, 읽는 순서, 잘림·회전 등 사례 |

기존 61개 검색 질의는 후속 검색 평가에 사용합니다. 공통 블록 평가를 통과했다고 Recall@5나 검색 품질이 검증되는 것은 아닙니다. 예비 자료는 합성 문서이므로 이 세트의 성적만으로 실제 사내 자료의 성능을 확정하지 않습니다.

## 기존 평가기와 보고 방식

기존 평가기의 원문 보존 검사는 재사용하되 새 원문 투영 어댑터를 먼저 구현합니다. 기존 평가 엑셀의 후속 단계 스키마 지표와 이번 파싱 스키마 지표를 혼동하지 않도록 `parsing_schema_validity` 등 별도 이름을 사용합니다. 의미·구성도 평가 결과를 기존 보고서에 임의로 통과 입력하지 않습니다.

새 평가 보고서는 최소한 입력/모델/주석 버전, 처리 누락, 원문 지표, 유형별 구조 지표, 관찰 주장 판정, 필수 사실 재현율, 위치 정확도, 실패 사례, 지연·비용·재시도를 포함합니다. 상태는 `not_run`, `incomplete`, `failed`, `passed`로 구분합니다. 미실행 지표의 score는 null입니다.

현재 [verification.json](verification.json)은 JSON 형식과 참조 검사, 의도적으로 손상시킨 입력의 거부 여부만 기록합니다. **비전 성능 평가는 not_run입니다.**
