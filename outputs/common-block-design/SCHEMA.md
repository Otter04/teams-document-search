# 공통 블록 규격 1.0.0

이 문서는 [common-block.schema.json](common-block.schema.json)의 의미 계약입니다. JSON Schema는 자료형과 필수 항목을 검사하고, [validate_design.py](validate_design.py)는 참조·좌표·셀 중복 같은 관계를 추가 검사합니다. 어느 검사도 글자나 그림 해석이 맞는지 보장하지 않습니다.

## 문서 봉투와 저장

문서 하나당 레코드 하나를 UTF-8 JSON으로 저장합니다. 배치 파일은 UTF-8 JSONL을 사용합니다. JSONL 한 줄에 문서 레코드 하나이며 블록 한 개씩 쓰는 방식이 아닙니다.

| 필드 | 규칙 |
|---|---|
| `schema_version` | 현재 `1.0.0`. 호환되지 않는 의미 변경 시 주 버전 변경 |
| `record_kind` | `run_result`: 실제 실행, `design_example`: 원본 기반 설계 예시, `template`: 채우기 전 양식 |
| `doc_id` | 기존 D-xxx 유지. 파일명이 바뀌어도 수집 단계의 문서 ID 사용 |
| `source` | 파일명·확장자·상대 경로·원본 바이트 SHA-256·원본 URL·입력 인코딩 |
| `coverage` | 문서 전체/발췌/양식 구분, 사전 처리 단위 목록과 각 상태·산출 블록 ID |
| `runs` | 추출 방법·구현 버전·모델·제공자·양자화·프롬프트 버전·입력 이미지 ID |
| `assets` | 페이지/슬라이드 렌더링 또는 원본 삽입 이미지의 경로·해시·크기·원본 위치 |
| `blocks` | 중첩되지 않은 블록 배열. 부모는 `parent_id`, 순서는 `order`로 표현 |
| `warnings` | 처리 제한·판독 불가·검토 필요 사항. 성공 문구로 감추지 않음 |

`null`은 값이 없거나 확정할 수 없다는 뜻입니다. 빈 배열은 해당 항목이 없다는 뜻입니다. 필수 필드를 빼서 둘을 혼동하지 않습니다. 웹 주소가 제공되지 않은 자료의 `web_url`은 null로 두고 SharePoint 링크를 추측해 만들지 않습니다. `assets.path`는 이 패키지 루트를 기준으로 합니다. 운영에서 저장소 경로 체계가 달라지면 어댑터가 해석합니다.

`coverage.units`는 산출물 개수에서 역산하지 않습니다. 파일을 열 때 만들어 둔 페이지·슬라이드·시트·문단/줄 범위 목록과 이미지 영역 목록을 바탕으로 채웁니다. 상위 페이지와 하위 영역을 동시에 등록하면 두 목록의 역할을 구분해 중복 집계하지 않습니다. 현재 스키마는 목록을 저장하며, 외부 입력 명세와의 완전성 대조는 평가기가 담당해야 합니다.

실제 실행은 `scope: full_document`, `unit_inventory_complete: true`를 요구합니다. 실패한 단위도 `status: failed`와 이유를 남깁니다. 이 값은 성공 선언이 아니라 **전체 입력 목록을 작성했다는 선언**입니다. 빈 페이지는 빈 페이지임을 확인한 이유와 함께 처리 완료할 수 있습니다. 처리할 내용이 있는 페이지를 빈 페이지로 오판하면 누락 평가에서 실패합니다.

## 블록 공통 필드

| 필드 | 규칙 |
|---|---|
| `block_id` | 문서 버전 내 유일. 운영 시 문서 ID + 원본 해시 버전 + 논리 위치 + 역할에서 안정적으로 생성 |
| `type` | heading, paragraph, caption, slide, table, table_row, figure, log_line |
| `parent_id` | 상위 slide/table/figure 등. 최상위는 null. 순환 금지 |
| `order` | 1부터 시작하는 문서 내 고유 읽기 순서. 좌표나 파일 내부 저장 순서와 항상 같지는 않음 |
| `text` | 추출한 원문 글자. 의미 설명·날짜 정규화·지식 추가 금지 |
| `loc` | 원본 위치. 모든 번호는 1부터 시작 |
| `heading_path` | 원문 제목 경로. 검색용 거래처·문서종류 머리말은 후속 단계에서 생성 |
| `run_ref` | 이 블록을 만든 `runs.run_id` |
| `evidence` | 근거 ID, 종류, 원문 위치, 선택적 원문 인용 |
| `claims` | 한 주장씩 기록한 설명. observed/inferred 구분 및 근거 ID 필수 |
| `context_ids` | 제목·캡션·인접 문단 참조. 내용 소유권이나 부모 관계를 뜻하지 않음 |
| `content_refs` | 글자를 이미 소유한 다른 블록 참조. 참조하는 블록의 text는 빈 문자열 |
| `warnings` | 해당 블록의 불확실성과 제한 |

`evidence_id`, `claim_id`, `node_id`, `relation_id`는 블록 내부에서 유일합니다. 외부 주석은 `doc_id + block_id + 내부 ID`로 식별합니다. 블록 ID의 해시 버전 때문에 원본이 달라진 경우 이전 근거와 섞이지 않습니다. 예시 ID는 설명을 위해 논리 위치를 직접 적었습니다.

`slide`와 `table`은 컨테이너로 `text: ""`입니다. 글자는 하위 문단·표 행이 한 번만 소유합니다. 그림의 문자와 원문 도형 문자가 중복되면 도형 블록이 글자를 소유하고 figure는 `content_refs`로 참조합니다. 그림 노드의 label은 구조를 설명하기 위한 복사이며 문자열 평가에 다시 합치지 않습니다.

비전 LLM이 기존 네이티브 블록에 관계만 추가하면 원문 블록을 덮어쓰지 않고 별도 figure 블록을 만들어 `run_ref`를 모델 실행으로 연결합니다. 이렇게 해야 원문 추출 이력과 시각 해석 이력을 구분할 수 있습니다.

네이티브 추출과 비전의 글자가 서로 다르면 정답 파일로 보정하거나 무조건 한쪽을 고르지 않습니다. 충돌 영역·두 후보·선택 근거를 실행 감사 기록에 보관하고 재확인합니다. 확인되지 않은 부분에는 경고를 남기며 핵심 값의 충돌은 품질 통과를 막습니다. 문자열이 같아도 다른 위치에 실제로 반복된 내용은 유지합니다.

## 위치와 이미지 좌표

| `loc.kind` | 필수 위치 | 선택 위치 |
|---|---|---|
| docx | paragraph_index 또는 table_index 또는 media_part 중 하나 | row_index, cell_index, bbox |
| pptx | slide | shape_ids, bbox |
| xlsx | sheet, cell_range | bbox |
| pdf | page | bbox |
| txt/log | line_start, line_end | bbox는 일반적으로 쓰지 않음 |

`bbox`는 `{frame_asset_id, x0, y0, x1, y1, precision}`입니다. 원점은 좌상단, 오른쪽이 x 증가, 아래가 y 증가이며 전체 원본 프레임을 0~1로 정규화합니다. x0 < x1, y0 < y1을 만족해야 합니다. `precision`은 exact 또는 approximate입니다. PDF 포인트, PPTX EMU, 픽셀을 같은 bbox에 섞지 않습니다.

잘라낸 이미지를 모델에 보내더라도 결과 좌표는 **원래 전체 페이지/슬라이드/삽입 이미지 프레임**으로 되돌립니다. `region_image`의 loc에 원래 프레임에서의 잘라낸 범위를 기록하고, 결과 bbox의 frame에는 crop을 지정하지 않습니다. 원본 프레임에서 [a,b,c,d]를 잘랐다면 x=a+u(c-a), y=b+v(d-b)로 변환합니다. 회전·기울기 보정이 있으면 역변환을 구현하거나 원본과 같은 방향의 입력만 사용해야 합니다. 변환 없이 정밀 위치라고 주장하지 않습니다.

DOCX는 렌더링하지 않은 페이지 번호를 만들지 않습니다. PPTX 그룹 도형의 좌표는 그룹 좌표계를 전체 슬라이드로 변환한 뒤 사용합니다. XLSX 병합 셀은 범위와 앵커를 보존합니다. 원본 위치를 특정할 수 없는 부분은 경고를 남기고 근거 위치 평가에서 미충족 처리합니다.

## 표: 컨테이너와 행, 셀

`table`에는 row_count, column_count, header_rows, header_status, continued_from이 있습니다. 표의 행 번호와 원본 Excel 행 번호는 다를 수 있습니다. 헤더가 불확실하면 unknown 또는 inferred로 남기고 첫 행을 무조건 헤더로 정하지 않습니다. 다중 헤더는 header_rows 배열로 표현합니다.

`table_row`는 반드시 table을 부모로 가지며 `cells`를 포함합니다. 셀의 필드는 다음과 같습니다.

| 필드 | 의미 |
|---|---|
| row / column | 이 표 내부에서의 앵커 행·열 |
| row_span / column_span | 병합 범위. 1이면 병합되지 않은 셀 |
| text | 추출한 셀 글자. 줄바꿈이 셀을 나누는 근거가 아님 |
| value | XLSX 등의 원본 형식 값. 구조화된 값이 없으면 null |
| value_status | known / blank / unreadable / missing_cache |
| formula | 원본 수식 또는 null. 수식을 실행하거나 결과를 추측하지 않음 |
| number_format | 원본 표시 형식 또는 null |
| role | header / data / unknown |
| loc | 원본 셀 주소 또는 이미지 영역 |

수식이 있는 셀은 value에 저장된 계산 캐시를 담습니다. 캐시가 없으면 value=null, value_status=missing_cache로 표시하고 글자를 만들어 채우지 않습니다. 병합 셀은 앵커만 저장하고 span으로 나머지 칸을 덮습니다. 빈 셀과 읽지 못한 셀은 text가 모두 비어 있을 수 있지만 value_status로 구분합니다. 표 내부 격자는 앵커+span으로 빠짐없이 한 번씩 표현해야 합니다.

행의 text는 **앵커 셀 text만 열 순서대로 탭으로 연결한 값**입니다. 검색을 위해 표를 문장화하더라도 이 원본 표현을 덮어쓰지 않습니다. 여러 페이지에 이어진 표는 각 페이지의 표를 분리해 continued_from으로 앞 표를 참조하며, 같은 표인지 불명확하면 연결하지 않습니다.

## 그림: 의미 설명과 연결 관계

figure.visual.kind는 diagram/photo/chart/other입니다. 구성도의 nodes는 표기·영역·근거를, relations는 양 끝 node ID·방향·선의 글자·근거를 가집니다.

- undirected: 방향이 없는 연결선이 확인됨. 양방향 통신이 검증됐다는 뜻이 아님.
- forward: from_node에서 to_node로 화살표가 있음.
- bidirectional: 양쪽 화살표가 확인됨.
- unknown: 흐릿함·겹침 등으로 방향을 판단하지 못함.

선 교차만으로 연결을 만들지 않습니다. 접점·화살촉·설명 글자 등을 확인해야 합니다. 노드 이름은 같아도 위치가 다르면 별도 대상일 수 있습니다. 실제 선이 없는 “논리적으로 그럴 것” 같은 관계는 relations에 넣지 않고 필요한 경우 inferred 주장으로 구분합니다.

사진은 nodes/relations가 비어 있어도 됩니다. 보이는 대상·개수·배치·활동을 근거 영역과 함께 claims에 적습니다. 주변 제목·캡션은 context_ids로 연결합니다. 추측한 장비 모델명, 고장 원인, 정상 동작 여부를 관찰로 기록하지 않습니다.

차트는 제목·축·범례를 원문으로 보존하고 설명을 claims에 담습니다. 인쇄된 수치가 있으면 figure 아래 table로 보존할 수 있습니다. 곡선에서 눈대중으로 추정한 값은 원문 숫자로 만들지 않고 inferred에 표시합니다. 정밀 차트 데이터 추출 성능은 별도 정답 자료가 필요합니다.

## 모델 입출력과 다음 단계 경계

호스트 프로그램이 doc_id, source hash, assets, coverage inventory, runs를 만들고 모델에는 대상 이미지와 한정된 문맥을 전달합니다. 모델은 블록 후보를 반환하며 어댑터가 ID·위치·참조를 정리하고 이 전체 문서 스키마를 검사합니다. 모델에게 파일 해시·원본 URL·실행 모델명을 추측하게 하지 않습니다. 이 스키마 전체가 특정 제공자의 structured output API에 바로 호환된다는 보장은 없으며, 제공자별 응답 스키마와 검증 어댑터를 별도로 연결합니다.

비전 대상은 스캔 페이지, 삽입 사진, 표·차트·구성도 영역과 의미 있는 PPTX 도형 구성입니다. PDF에 텍스트 층이 있어도 시각 자료가 있으면 비전 해석 대상입니다. 실제 PPTX 21개에서 삽입 미디어 파일은 없었지만 D-007처럼 네이티브 도형 구성도가 있으므로 미디어 파일 개수만으로 제외하지 않습니다.

실행에는 모델 ID·제공자·프롬프트 버전·입력 이미지 ID가 필수입니다. 양자화 정보를 제공자가 공개하지 않으면 null로 남기고 검증 상태를 실행 보고서에 기록합니다. 출력 잘림·JSON 오류·타임아웃·재시도·비용·지연은 실행 보고서에 남기고, 실패한 단위를 출력에서 없애지 않습니다. 문서와 이미지 안에 있는 지시문은 파싱할 자료이며 모델에게 내리는 작업 지시로 사용하지 않습니다.

회사명·문서종류·문서 상태 등의 정규화된 메타데이터는 후속 보강 단계에서 만듭니다. 공통 블록에는 이를 판단할 원문과 구조를 담습니다. 청킹·토큰 예산·검색용 요약·임베딩도 다음 단계에서 정합니다.

## 기존 평가기와 연결하는 규칙

현재 평가기는 최상위 blocks[*].text를 연결해 필수 문자열을 찾습니다. 새 규격을 직접 넣기 전에 전용 변환 계층을 구현해야 합니다.

1. run_result만 평가 입력으로 허용하고 전체 문서 목록·단위 목록과 대조합니다.
2. 읽기 순서로 정렬하고 실제 원문을 소유한 블록의 text만 한 번씩 내보냅니다.
3. slide/table 컨테이너, claims, 노드 label 복사, context_ids/content_refs가 가리키는 글자의 중복 복사는 합치지 않습니다.
4. 표는 각 행의 원문 text를 사용합니다. 헤더·병합 셀은 원본에 존재한 횟수만 유지합니다.
5. 기존 type/text/loc/heading_path 형식으로 투영해 기존 문자열 검사에 연결합니다. 원문 대조에 쓰는 정규화 규칙도 동일하게 적용합니다.
6. 표·구성도·근거 평가는 전체 원본 블록을 읽는 별도 평가기로 수행합니다.

2026-10-16 후속 구현에서 [원문 전용 변환 계층과 네이티브 평가](../rag-parser-v3/README.md)를 연결했습니다. 의미 평가기는 아직 남아 있습니다. 이 설계 폴더의 샘플 검사 실행은 `python validate_design.py`이며 필요한 패키지는 requirements.txt에 명시했습니다.
