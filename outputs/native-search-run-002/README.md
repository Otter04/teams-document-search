# 청킹·키워드 색인 실제 실행 결과

2026-10-17 · 모델 미선정 · 유료 API 호출 없음

**네이티브 청킹과 키워드 검색 기준선을 구현하고 예비 데이터셋으로 평가했습니다.** 파싱한 원문을 검색할 크기로 나누는 청킹의 보존 기준은 통과했습니다. 검색은 90% 목표에 미달했으며 비전·의미 검색을 포함한 전체 파이프라인은 미완료입니다.

## 이번에 이어진 흐름

공통 블록 → 규칙 메타데이터 → 구조별 청크 → 키워드 색인 → 질문 검색 → 문서별 결과·원문 위치

‘네이티브’는 파일에 이미 저장된 글자·셀·문단을 직접 읽은 범위입니다. 이미지의 의미나 연결선을 이해한 결과는 아직 포함하지 않습니다. 모델 선정 전에도 이 범위의 원문 보존과 키워드 검색을 독립적으로 시험할 수 있습니다.

| 확인 항목 | 실제 결과 |
|---|---:|
| 문서 | 110개 |
| 검색 청크 | 1,042개 |
| 색인 항목 | 1,152개 = 청크 1,042 + 문서 메타데이터 110 |
| 원문 참조·문자 범위 검증 | 110/110, 누락 0 |
| 네이티브 필수 문자열 보존 | 334/334, 잘림 0 |
| 인식한 표 머리말 연결 | 91개 표, 누락 0 |
| 청크 본문 최대 길이 | 1,200자; 실제 모델 토큰 수는 미측정 |
| 회귀 검사 | 21개 통과 |
| 원본 파일 해시 보존 | 110/110 |
| 전체 재현 | 청크·색인 동일, 질문 61개 결과 동일 |

전체 필수 문자열은 346개이며 기존 스캔 파싱에서 읽지 못한 12개는 여전히 대기입니다. 표 머리말 판정은 열 이름 규칙으로 검사한 결과이며 독립 검수자의 의미 정확도 평가를 대신하지 않습니다.

## 검색 결과

Hit@5는 **정답 문서 중 하나라도 상위 5개 안에 포함되는 비율**입니다. 여러 정답을 전부 찾는 비율이나 답변 정확도와 다릅니다. 기존 평가기의 Recall@5가 이 계산이어서 이번 보고서는 정확한 명칭으로 표시했습니다.

| 질문 유형 | Hit@5 |
|---|---:|
| 번호형 | 16/16 = 100% |
| 메타데이터형 | 16/19 = 84.21% |
| 의미형 | 17/21 = 80.95% |
| 혼합 | 4/5 = 80% |
| **전체** | **53/61 = 86.89%** |

MRR@10은 0.8220입니다. 전체·유형별 90% 기준 중 번호형만 통과했습니다. 61개 자연어 질문을 모두 사용했고 정답 문서 ID나 정답 필터를 검색기에 전달하지 않았습니다. 이 예비 세트는 합성 개발 자료이므로 사내 독립 자료 검증을 대신하지 않습니다.

실패 8건에는 영문 로그 용어와 한국어 질문의 차이, 상대 날짜 조건 미처리, 스캔 구성도 본문 부재가 관찰됩니다. [실패 분석](evaluation/FAILURE_ANALYSIS.md)에 확인한 근거와 한계를 기록했습니다. 현재 성적은 후속 개선의 비교 기준으로 유지합니다.

## 실제 자료의 결과 예시

- [D-003 견적서 청크](examples/D-003.json): 표의 행을 묶고 품목·수량·단가·금액 머리말과 원래 셀/행 위치를 연결합니다.
- [D-005 계약서 청크](examples/D-005.json): 조항 제목과 본문을 묶고 기존 확정 메타데이터만 문맥에 붙입니다. 보류된 문서일자는 필터에 채우지 않습니다.
- [D-009 서버 구성표](examples/D-009.json): 본문까지 포함하던 기존 inferred 헤더 목록 대신 확인한 열 이름 행을 연결합니다.
- [D-010 로그 청크](examples/D-010.json): 5분 구간과 길이 제한에 따라 나누고 각 원문 줄을 추적합니다. 긴 구간은 여러 청크가 될 수 있습니다.
- [D-044 스캔 계약서](examples/D-044.json): 청크는 빈 배열이며 파일명·경로 메타데이터와 비전 대기를 보존합니다.
- [ORA-01555 실제 검색](examples/search-error-code.json), [명시적 날짜·실패 필터 검색](examples/search-explicit-filter.json): 문서·점수·본문 근거·원문 위치를 반환합니다. 필터 예시는 위 61개 벤치마크 점수에 포함되지 않습니다.

예시 JSON은 실제 결과에서 복사했습니다. 청크는 원문을 대체하지 않으며 나중에 비전 결과가 추가되면 해당 문서의 보강·청킹·색인을 다시 만들어 평가해야 합니다. 이번 구현은 검증된 네이티브 입력만 받습니다.
