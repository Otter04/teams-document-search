# 공통 블록 파서 2.0.0

기존 1.1.0 파서의 문단·문자 처리 코드를 이어받아 공통 블록 규격 1.0.0으로 변경한 버전입니다. **현재 실행 범위는 네이티브 파싱**입니다. 사용자 선택에 따라 비전 모델은 이번 결과를 확인한 뒤 OpenRouter에서 시험합니다. 이 버전은 모델을 호출하지 않습니다.

현재 결과: [110문서 실제 실행·평가](../parsing-run-003/README.md).

## 변경 내용

- 원본 파일을 다시 읽어 `record_kind: run_result` 문서 레코드를 생성합니다. 과거 parsed.jsonl이나 설계 예시를 파싱 입력으로 사용하지 않습니다.
- 모든 블록을 평평한 배열에 저장하고 `parent_id`, `order`, 원문 위치, 근거, 추출 이력을 기록합니다. 문서 ID·원본 해시·논리 위치로 블록 ID를 만듭니다.
- DOCX·PPTX·PDF·XLSX 표를 `table → table_row → cells` 구조로 저장합니다. 병합 셀은 앵커와 span을 기록하며 글자를 여러 셀에 복제하지 않습니다.
- XLSX는 사용 범위의 전체 격자와 빈 셀을 보존합니다. 숨긴 시트도 포함하고 상태를 감사 기록에 남깁니다. 수식은 원문과 저장된 계산 캐시를 분리하며 캐시가 없으면 `missing_cache`입니다.
- DOCX 제목·문단과 PPTX 제목·본문의 문맥 참조를 유지합니다. PPTX 제목 후보와 XLSX 헤더 후보는 추정 방식임을 표시합니다.
- PDF의 실제 글자·표를 추출하고 렌더링 이미지의 0~1 좌표로 원본 위치를 연결합니다. 페이지 배경 테두리에서 생기는 극소 셀은 표 후보에서 제외하고 본문으로 읽습니다.
- LOG의 대괄호 없는 ERROR와 밀리초 시각을 보존합니다. 메시지 본문의 ERROR를 로그 등급으로 잘못 읽지 않도록 시각 다음 위치를 확인합니다.
- PPTX 렌더링에서 한글이 빠지는 문제를 확인하여 임시 복사본의 글꼴을 명시적으로 지정할 수 있게 했습니다. 원본은 수정하지 않고 글꼴 해시·대체 사실을 기록합니다. 렌더링 PDF의 한글 문자 수를 원문과 대조해 누락된 이미지를 시험 입력에 넣지 않습니다.
- TXT/LOG는 엄격한 인코딩 해석과 원본 줄 번호를 유지합니다.
- 스캔 페이지, 삽입 이미지, 시각 구조 검토 대상을 `vision-pending.jsonl`에 남깁니다. 기존 이미지 인식 결과를 새 모델 결과로 넣지 않습니다.

## 결과 파일

| 파일 | 내용 |
|---|---|
| parsed.jsonl | 문서별 실제 공통 블록. 이미지에서 읽지 않은 내용은 비어 있음 |
| manifest.jsonl | 입력 문서 ID·경로 |
| source-inventory.jsonl | 처리 단위 목록. 평가에서 원본의 페이지·슬라이드·시트 수를 별도로 대조 |
| vision-pending.jsonl | OpenRouter 후속 시험 대상 후보, 입력 이미지와 문맥 블록 참조 |
| assets/ | 실제 페이지·슬라이드 렌더링 이미지, 원본 해시와 대응 |
| audit.json | 파일별 실행 상태, 원본 구조 정보, 렌더링 오류, 스키마 오류 |
| provenance.json | 코드·규격·입력 해시, 실행 시간, 모델 미호출 여부 |

PPTX는 이번 버전에서 모든 슬라이드를 보수적으로 비전 검토 목록에 넣습니다. 텍스트 PDF도 삽입 이미지나 표 밖 그래픽이 있으면 후보로 등록합니다. 표지·배경 그림도 포함될 수 있으므로 후보 수가 반드시 API를 호출할 장수는 아닙니다. 후속 라우팅 개선은 실제 원본 검토와 누락 테스트를 거쳐야 합니다.

## 실행

Python 3.10 이상과 requirements.txt의 라이브러리가 필요합니다. 슬라이드 이미지는 LibreOffice를 사용하며 격리된 임시 프로필과 원본 복사본으로 렌더링합니다. 원본 폴더에 결과를 쓰지 않습니다. `../common-block-design`과 `../rag-evaluator`를 함께 유지하세요.

```sh
python parse.py \
  --files-root '/path/to/dataset/files' \
  --manifest '/path/to/manifest.jsonl' \
  --output '/path/to/new-run' \
  --work-dir '/path/to/work' \
  --soffice '/path/to/soffice' \
  --render-font '/path/to/Arial Unicode.ttf' \
  --render-font-family 'Arial Unicode MS'

python evaluate.py \
  --run '/path/to/new-run' \
  --dataset '/path/to/dataset' \
  --pdf-reference '../parsing-run-002/qa/pdf_table_reference.json'
```

manifest에는 `doc_id`, `relative_path` 두 키만 허용합니다. 출력 폴더는 새 경로여야 합니다. 기본 렌더링 해상도는 144 DPI이며 이미지를 다시 만들면 입력 해시를 다시 기록합니다. LibreOffice 미지정/실패 시 네이티브 슬라이드 문자는 추출하되 비전 입력 이미지 준비 실패를 경고로 남깁니다.

`evaluate.py`는 전체 레코드 검증 후 **원문 text만** 기존 평가기에 투영합니다. claims, 그림 노드의 라벨 복사, 컨테이너의 중복 텍스트는 문자열 검사에 넣지 않습니다. 스키마 일관성, 원본 해시, 단위 목록, 346개 필수 문자열과 기존 네이티브 표 표본을 검사합니다. 기존 평가 엑셀도 별도 하위 폴더에 생성합니다. 표본 셀 정확도를 전체 비전 표 정확도로 입력하지 않습니다.

## 검증과 남은 범위

테스트 실행: `python -m unittest discover -s tests -v`. 13개 테스트는 CP949, 로그 시각/등급, Excel 병합·캐시 누락·숨김 시트, DOCX 가로/세로 병합, 도형 기반 슬라이드의 검토 등록, 스캔의 처리 대기, 원문 투영 분리, 설계 예시의 평가 유입 방지, 잘못된 근거·좌표·배경 테두리와 렌더링 글꼴 대체 시 원본·문자 보존을 검사합니다.

현재 XLSX의 table은 사용 범위 격자 단위입니다. 여러 의미상 표를 자동 분리했다는 뜻은 아닙니다. 문서의 중첩 표, 복잡한 다단 읽기 순서, 그룹 도형의 정밀 좌표, 사진·차트의 의미, 표 헤더의 의미적 정확성은 별도 검증이 필요합니다. XLSX 삽입 그림/차트는 감지하지만 해당 영역의 렌더러는 아직 없습니다. 현재 예비 세트 실행에서는 이 경로가 필요하지 않았습니다.

검증기가 true를 반환해도 모델의 관찰 주장이나 전체 파싱 품질이 통과했다는 뜻은 아닙니다. 이미지 기반 필수 내용이 pending이면 전체 상태는 incomplete입니다. OpenRouter 응답을 공통 블록으로 연결하는 어댑터와 의미 평가 기능은 후속 범위입니다.
