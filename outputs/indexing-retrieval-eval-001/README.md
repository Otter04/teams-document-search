# 기존 RAG 인덱싱 평가세트 재평가

2026-10-20. **기존 Q-001~Q-061의 질문·정답을 변경하지 않고 최신 110문서 색인을 평가했다. 최신 BM25는 Hit@5·평균 문서 Recall@5 모두 100%로 90% 목표를 충족했다.** bge-m3 단독과 고정된 단순 결합 방식도 비교했다. 이 작업은 평가용 검색 실행이며, 사용자용 검색 서비스나 답변 생성 기능을 만들지 않았다.

## 동일한 61질문의 결과

| 방식 | 정답 1개 이상 발견: Hit@5 | 정답 문서 회수: 평균 Recall@5 | 모든 정답을 5위 안에 찾은 질문 | 첫 정답이 1위 |
|---|---:|---:|---:|---:|
| 이전 네이티브 중심 BM25 보존 결과 | 60/61 · 98.36% | 97.54% | 59/61 | 59/61 |
| 검수 비전 반영 BM25, 새 의미 보강 전 | 61/61 · 100% | 100% | 61/61 | 60/61 |
| 최신 BM25, 의미 보강 포함 | **61/61 · 100%** | **100%** | **61/61** | **60/61** |
| bge-m3 벡터 단독 | 52/61 · 85.25% | 83.06% | 49/61 | 46/61 |
| BM25 + bge-m3 단순 결합 | 61/61 · 100% | 99.18% | 60/61 | 57/61 |

Hit@5는 정답 문서가 여러 개여도 하나만 찾으면 성공이다. Recall@5는 각 질문에서 `찾은 정답 수 / 전체 정답 수`를 계산한 뒤 61질문의 평균을 낸 값이다. 예를 들어 정답 2개 중 1개만 찾으면 그 질문의 Hit@5는 1, Recall@5는 0.5다. 두 지표를 혼용하지 않았다.

이번 목표는 최신 BM25와 단순 결합에서 모두 충족했고, 벡터 단독에서는 충족하지 못했다. 동일 세트의 결과만 보면 최신 BM25가 가장 안정적이었다. 벡터 모델을 모든 질문에 동일한 비중으로 섞는 것이 반드시 개선은 아니라는 결과다. 검색 설계를 확정하거나 설정을 튜닝한 결과로 해석하지 않는다.

## 확인할 질문

| 질문 | 정답 | 이전 결과 | 최신 BM25 | 단순 결합 |
|---|---|---|---|---|
| Q-020 `TMS 전환 작업 로그` | D-036 | 1위 | **1위 유지** | 1위 |
| Q-032 `수강신청 몰릴 때 자동으로 서버 늘리는 구성` | D-053·D-054·D-061 | 3개 모두 5위 이내 | **1·2·3위** | 1·2·3위 |
| Q-037 `본사랑 대전 DR센터 전용회선 구성도` | 스캔 구성도 D-069 | 상위 10개에서 못 찾음 | **1위** | 1위 |
| Q-025 `CT-2025-0164` | D-043·스캔 계약서 D-044 | D-043만 1위, D-044 미회수 | **1·2위** | 개별 전체 결과 참조 |
| Q-053 `부가세 포함 금액으로 견적 낸 공공기관 건` | D-099·D-100 | 두 정답 5위 이내 | **1·2위** | **5·9위** |

Q-053의 단순 결합은 정답 하나가 5위에 있어 Hit@5는 성공이지만 다른 정답이 9위라 Recall@5는 50%다. 그래서 결합 방식 전체의 평균 Recall@5가 99.18%이고 모든 정답을 찾은 질문은 60개다. 이 차이를 숨기거나 정답·설정을 바꿔 재채점하지 않았다.

최신 BM25에서 이전에 성공하던 질문이 Hit@5 실패로 바뀐 경우는 없다. 첫 정답이 1위가 아닌 질문은 Q-030 한 개이며 5위다. 100%는 상위 5개 기준이며 모든 정답이 1위라는 뜻이 아니다.

검수 비전 반영 단계의 BM25에서 이미 전체 Recall@5가 100%였으므로, 이번 61질문만으로 새 의미 보강·임베딩이 추가 성능 향상을 입증했다고 말할 수 없다. Q-025·Q-037에서 스캔 자료를 회수한 개선은 새 의미 보강 이전 단계에서도 확인된다.

## 벡터 단독에서 놓친 질문

Hit@5 실패는 Q-013, Q-021, Q-025, Q-043, Q-044, Q-048, Q-051, Q-053, Q-058의 9개다. 견적·계약 번호, 호스트명 같은 정확한 식별자 질문과 일부 조건 질문에서 정답 순위가 내려갔다.

예를 들어 `Q-2504-02`의 정답 D-022·D-030은 벡터 단독에서 38·55위였다. `CT-2025-0164`의 정답 D-044·D-043은 20·71위였다. 이는 이번 입력 구성·문서별 최고 청크 점수·질문 조건 처리에서 관측한 결과이며, bge-m3 일반 성능 전체에 대한 결론은 아니다.

## 평가 방법과 보존

- 대상: 기존 110문서, Q-001~Q-061 전체. 예전의 ‘네이티브 정답이 있는 60질문’만 고른 평가가 아니다. 추가 H 데이터셋·별도 날짜 개발검사 20건은 이번 61질문에 포함하지 않았다.
- 원본 `gold/queries.jsonl`의 해시를 확인했다. 질문 문구·정답 문서 ID가 원본과 61/61 일치한다. 원본 정답의 `filters` 열은 검색 입력에 사용하지 않았다.
- 기존 평가의 질문 전용 파일을 그대로 사용했다. 상대 날짜의 기준일은 과거 비교와 동일한 **2026-10-17**로 고정했다. 실제 평가 실행일은 2026-10-20이다.
- BM25는 기존 한영 표현·조건·날짜·핵심 필드 가중치·로그 문맥 처리 코드를 그대로 사용했다. 현재 저장 항목의 명칭을 옛 평가 코드와 연결하기 위한 메모리상 호환 별칭만 추가했다. 원본 색인을 수정하지 않았다.
- bge-m3는 문서 벡터와 같은 모델 가중치·토크나이저 해시, CLS pooling, L2 정규화를 사용했다. 원문 질문만 임베딩했으며 정답·정답 필터를 모델에 보내지 않았다.
- 벡터 1,089개를 모두 비교하고 동일한 명시적 메타데이터 필터를 적용한 뒤, 문서별 최고 청크 점수로 순위를 만들었다. 벡터 후보를 미리 몇 개로 자른 뒤 문서로 묶는 방식은 사용하지 않았다. 단, BM25의 내용 단어 일치 조건은 기존 코드대로 유지하며 벡터 경로에 단어 일치를 강제하지 않았다.
- 단순 결합은 **문서 순위 기준 동일 비중 RRF, k=60**이다. BM25는 기존 함수의 최대 100문서 후보, 벡터는 전체 허용 문서를 사용했다. 명시적 수정순 요청은 정렬 우선이다. 이 설정은 점수를 보기 전에 고정했고 이번 결과에 맞춰 조정하지 않았다.
- 순위 계산 중 파일·네트워크 접근을 막았으며 위반 시도는 0건이다. 순위 결과를 파일에 확정한 다음 정답을 읽어 채점했다.
- 기존 1,089개 문서 벡터는 그대로 재사용했다. **새 질문 벡터 61개**만 Orin에서 생성했다. 문서 보강·비전·답변 LLM 재호출과 외부 유료 API 호출은 없다.

질문 임베딩 실행은 모델 확인·로딩 등을 포함해 **8.58초**, 61질문의 네 방식 순위 계산은 Mac에서 합계 **1.12초**였다. 파일 준비·전송·특징 준비·채점·검수 시간은 제외했다. 운영 서비스의 응답 시간이나 동시 사용자 성능 측정은 아니다.

## 해석의 한계

이 평가세트는 이전 규칙 개선에도 사용한 **개발용 회귀 평가세트**다. 이번에 질문·정답을 바꾸지 않았다는 것은 비교 가능성을 확보한 것이며, 독립된 새 자료에 대한 정확도 100%를 뜻하지 않는다. 또한 정답 문서를 찾았다는 사실만으로 문서의 모든 파싱 내용·설명·요약이 정확하거나 최종 답변이 정확하다고 판정하지 않는다.

현재로서는 **색인이 검색 가능한 상태로 연결됐고, 기존 세트에서 최신 BM25의 문서 회수 목표를 충족했다**는 결론이다. 벡터 활용 방식과 실제 검색 UX·답변 생성은 별도 설계 대상으로 남겨둔다.
