# 생성 설정에 따른 해석 범위

확인일: 2026-10-19. 반복 출력과 출력 잘림을 확인한 뒤 공식 자료를 대조했다. 현재 실행의 요청이나 점수는 변경하지 않았다.

현재 첫 비교는 두 모델의 요청 조건을 동일하게 고정하려고 `temperature=0`, seed 42, 출력 한도 16,384토큰과 strict JSON schema를 사용한다. `top_p`, `top_k`, `presence_penalty`는 요청에 명시하지 않았다. 이는 이번 파서의 고정 조건 평가이며 각 모델의 최적 설정 성능을 측정한 것이 아니다.

- [Qwen3.6 공식 모델 카드](https://huggingface.co/Qwen/Qwen3.6-35B-A3B#best-practices)는 non-thinking 모드에 temperature 0.7, top_p 0.8, top_k 20, presence_penalty 1.5를 권장한다. 반복을 줄이는 설정의 이점과 언어 혼합·성능 저하 가능성도 설명한다.
- [Qwen3-VL 공식 저장소의 평가 재현 설정](https://github.com/QwenLM/Qwen3-VL#evaluation-reproduction)은 Instruct 모델에서 같은 네 값을 사용하고, greedy를 끄며 출력 한도를 32,768토큰으로 둔다. 이는 그 공식 평가의 설정이지 이 문서 파싱 작업에 최적인 값임을 보장하지 않는다.

두 공식 설정 모두 현재 baseline의 temperature 0과 차이가 있다. 반복 출력의 원인이 이 차이라고 확정한 것은 아니다. 프롬프트, 엄격한 JSON 제약, 제공업체 구현, 이미지 조건도 영향을 줄 수 있다.

후속 시험에서는 대표 실패·정상 사례를 동일하게 고정하고, 우선 생성 설정만 바꾸어 비교하는 것이 적절하다. 좌표 규격 변경이나 프롬프트 수정을 동시에 적용하면 어느 변화의 효과인지 분리하기 어렵다. 출력 한도만 늘리는 것은 반복 문제의 해결로 간주하지 않는다. OpenRouter·해당 제공업체의 지원 파라미터를 확인한 뒤 실행해야 한다.

현재 결과는 두 모델의 모든 설정에서의 능력이나 최종 순위를 확정하는 자료가 아니다. 첫 결과를 보존하고 별도 실험 번호로 후속 점검을 남긴다. 이 문서는 제안이며 추가 유료 실험을 실행했다는 기록이 아니다.
