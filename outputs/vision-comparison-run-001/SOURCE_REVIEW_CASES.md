# 원본과 응답을 직접 대조한 사례

2026-10-19 보조자가 아래 이미지와 저장된 원응답을 대조했다. 일부 사례 검토이며, 독립적인 사람 검수나 전체 132장의 의미 정확도 평가가 아니다. 원응답과 기존 정답 초안은 수정하지 않았다.

## D-069 구성도 1쪽

[원본 이미지](../parsing-run-003/assets/D-069/page-1.png)에는 8개 상자와 방향 화살표가 없는 7개 연결선이 있다. 방화벽은 인터넷·본사 전용회선·대전 DR 센터·코어 스위치와 연결된다. 코어는 본사 서버팜·DR 서버팜·복제망으로 연결된다.

- [Qwen3.6 원응답](qwen3.6-35b-a3b/units/D-069-vision-page1/response.json): 8개 노드와 7개 무방향 연결의 관계를 재현했다. 일부 `×`를 `x`로 전사하여 기존 완전 일치 검사에서는 노드 5/8, 연결 0/7이다. 이 점수가 실제 연결 7개를 전부 놓쳤다는 뜻은 아니다. 반면 연결선 좌표에 폭·높이 0 또는 역순 좌표가 실제로 존재하여 공통 블록 변환은 거절됐다. 범례의 `≈` 전사도 원문 `=`과 차이가 있다.
- [Qwen3-VL 원응답](qwen3-vl-30b-a3b-instruct/units/D-069-vision-page1/response.json): 8개 라벨과 7개 무방향 연결을 재현했다. 하지만 모든 근거 좌표가 `[1,0,1,1]`로 되어 유효한 영역을 가리키지 못한다. 제목·작성일·설치 위치·범례를 텍스트로 추출하지 않았고, 내용 없는 `chart` 항목을 추가했다. 따라서 라벨·연결 점수가 높아도 전체 파싱 성공으로 볼 수 없다.

이 사례는 문자열 표기 차이, 연결 관계, 좌표, 주변 텍스트 누락을 따로 평가해야 함을 보여준다. 원문 대조에서 확인한 관계 해석은 사후 진단이며 기존 자동 점수의 변경이나 실패 결과의 승인으로 사용하지 않는다.

## D-044 계약서 2쪽 — Qwen3.6

[원본 이미지](../parsing-run-003/assets/D-044/page-2.png), [원응답](qwen3.6-35b-a3b/units/D-044-vision-page2/response.json).

4행×2열 표의 8개 셀 내용과 위치 인덱스는 초안 정답과 모두 일치했다. 그러나 8개 셀을 모두 `value_status: unreadable`로 표시하고 전체를 `complete`로 보고했다. 내용을 추출했어도 상태의 의미가 모순되므로 이 결과를 무검토 확정 자료로 사용하면 안 된다. JSON 규격 자체는 이러한 의미 모순까지 검사하지 못한다.

표 영역의 세로 위치도 원본과 다르다. 원본의 표는 정규화 y 약 0.23~0.31에 있는데 응답의 표 bbox는 y 0.42~0.62이다. 숫자 범위·순서 검사를 통과했다고 실제 근거 위치까지 맞는 것은 아니다.

응답 경고에 쓰인 “OCR”은 모델이 생성한 표현이다. 이번 파이프라인에서 별도 OCR 엔진을 실행한 것은 아니다.

## Qwen3.6의 출력 한도 도달

[D-102 2쪽](qwen3.6-35b-a3b/units/D-102-vision-page2/response.json)과 [H-020 1쪽](qwen3.6-35b-a3b/units/H-020-vision-page1/response.json)은 출력 16,384토큰에 도달하고 `finish_reason: length`로 끝났다. 응답 후반에 공백 반복이 있으며 완결된 응답으로 채택하지 않았다. 출력 잘림은 Qwen3-VL에만 있는 문제가 아니다.

## D-102 계약서 2쪽 — Qwen3-VL

[원본 이미지](../parsing-run-003/assets/D-102/page-2.png)의 표는 4행×2열이다. [응답](qwen3-vl-30b-a3b-instruct/units/D-102-vision-page2/response.json)은 왼쪽 열의 문구를 한 셀, 오른쪽 열의 문구를 한 셀로 합쳐 1행×2열로 만들었다. 글자를 상당 부분 읽었어도 행 구조를 복원하지 못한 사례다.

두 셀은 모두 `unreadable`이고 전체 상태는 `complete`다. 표·셀 좌표는 `[1,1,1,1]`이다. `texts`가 비어 있어 원본 위쪽 분쟁 해결 조항, 계약서 보관 문구와 2025년 10월 24일도 추출되지 않았다. 해당 날짜를 잘못된 다른 값으로 채운 것이 아니라 누락했다.

## Qwen3-VL의 중복·출력 한도 도달

D-001 표지 원본에는 거래처·날짜 문단이 한 번 있지만 [1쪽 응답](qwen3-vl-30b-a3b-instruct/units/D-001-vision-slide1/response.json)은 같은 내용을 두 번 추출했다. `㈜`와 `(주)`의 표기 차이는 별도로 보고, 문단 중복 자체를 문제로 기록한다.

[6쪽 응답](qwen3-vl-30b-a3b-instruct/units/D-001-vision-slide6/response.json)은 표를 추출한 후 같은 표 내용을 텍스트로 반복하여 16,384토큰에 도달했다. 응답은 보존했지만 공통 블록에 받아들이지 않았다. 다른 페이지에도 같은 원인이 있는지는 각 원응답을 확인해야 하며, 모든 잘림을 동일한 원인으로 단정하지 않는다.
