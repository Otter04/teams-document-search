# OpenRouter 비전 모델 결정 방법

작성일: 2026-10-16. 사용자 결정: 먼저 네이티브 파싱·평가를 마치고, 비전 모델은 결과를 확인한 뒤 **OpenRouter에서 시험**한다. 이번 실행에는 외부 모델 호출이나 API 비용이 발생하지 않았다.

## 지금 결정할 것

운영 모델을 지금 확정할 필요는 없다. 실제 비전 실행 전에 **비교할 후보와 시험 조건**을 정하면 된다. 파서는 공통 블록을 기준으로 연결하므로 모델을 바꿀 때 파일 형식별 파서를 다시 만들 필요가 없도록 설계했다. OpenRouter 응답을 검증·변환하는 어댑터 구현은 다음 단계에 남아 있다.

공개 벤치마크의 종합 점수는 후보를 줄이는 참고 자료다. 이 프로젝트에는 한국어 사업 문서, 표의 셀 대응, 모델명·숫자·IP, 구성도의 선 연결, 근거 없는 단정 방지가 중요하다. 이번 실제 자료에서 측정해야 선정 근거가 된다.

## 비교 시작 후보

모델 규모가 다른 두 후보로 비교를 시작하는 방안을 제안한다. 최신·최고 성능이라는 주장이나 운영 선정이 아니다.

| 후보 | 비교 목적 | OpenRouter 식별자 |
|---|---|---|
| Qwen3-VL-8B-Instruct | 작은 규모로 요구 품질을 충족하는지 확인 | `qwen/qwen3-vl-8b-instruct` |
| Qwen3-VL-30B-A3B-Instruct | 규모와 구조가 다른 후보가 표·관계 정확도를 개선하는지 확인 | `qwen/qwen3-vl-30b-a3b-instruct` |

두 모델의 이미지 입력과 공개 가중치는 [Qwen 8B 공식 모델 카드](https://huggingface.co/Qwen/Qwen3-VL-8B-Instruct), [Qwen 30B-A3B 공식 모델 카드](https://huggingface.co/Qwen/Qwen3-VL-30B-A3B-Instruct)에서 확인했다. API 등록은 [OpenRouter 8B](https://openrouter.ai/qwen/qwen3-vl-8b-instruct/api), [OpenRouter 30B-A3B](https://openrouter.ai/qwen/qwen3-vl-30b-a3b-instruct/api)를 확인했다. 사용 가능 제공업체·지원 옵션·요금은 실제 실행 시 다시 확인한다. 현재 두 모델 모두 이 데이터셋에서 실행하지 않았으므로 우열은 미확인이다.

## 같은 입력으로 비교

준비한 `vision-pilot-inputs.json`은 원본 렌더링 이미지·해시·위치·네이티브 문맥만 담고 있다. 정답 문자열·해석 예시를 모델 입력에 포함하지 않는다.

| 자료 | 장수 | 확인할 것 |
|---|---:|---|
| D-044 스캔 계약서 | 2 | 본문·기간·숫자·갑/을 4행 2열 표 |
| D-102 스캔 계약서 | 2 | 다른 계약서에서도 같은 처리가 되는지 |
| D-069 스캔 구성도 | 1 | 장비·IP·상자·연결선, 없는 화살표/운영 사실을 만들지 않는지 |
| D-007 PPTX 구성도 | 1 | 네이티브 도형의 관계와 주변 문맥 |
| D-022 텍스트 PDF 견적 표 | 1 | 이미지 해석이 셀 관계를 보존하는지, 네이티브 결과와 대조 |

144 DPI 렌더링 원본을 고정하고 양쪽 모델에 같은 문맥·프롬프트·출력 형식을 준다. 모델 서버가 내부적으로 이미지를 줄일 수 있으므로 API 이미지 옵션도 기록한다. 초기 출력 토큰 한도는 동일하게 잡고, 잘림이 발생하면 한쪽 결과만 임의로 고치지 말고 조건을 변경한 새 실험으로 양쪽을 다시 평가한다.

단일 응답만으로 안정성을 판단하지 않는다. 첫 7장으로 오류 유형을 파악한 후, 중요한 자료를 같은 조건으로 반복해 JSON 실패·결과 변동을 확인한다. 조정에 사용하지 않은 별도 자료로 마지막 검증을 수행한다.

## 기록할 조건

- 모델 ID, 실제 제공업체와 엔드포인트, 실행 시각, 알려진 모델 버전.
- 이미지 해시·크기·해상도, 문맥과 프롬프트 버전, 공통 블록 규격 버전.
- 온도 등 생성 옵션, 출력 한도, 응답 잘림·재시도, 입력/출력 사용량과 실제 비용.
- 제공자가 공개한 양자화. 확인되지 않으면 unknown으로 남기며 Spark와 같은 조건이라고 부르지 않는다.

OpenRouter는 모델 하나에 여러 제공업체가 있을 수 있다. 비교할 때 제공업체를 고정하고 자동 대체를 끄며, 필요한 옵션을 지원하는 경로를 선택한다. 제공업체와 양자화 필터는 [공식 Provider Routing 문서](https://openrouter.ai/docs/guides/routing/provider-selection)에 설명되어 있다. 특정 조건의 엔드포인트가 없으면 다른 조건을 쓴 실험으로 명확하게 분리한다.

## 결정 순서

1. **품질 기준을 먼저 확인한다.** 유효 JSON, 원문 보존, 핵심 값, 셀 구조, 선 연결·방향, 관찰 주장과 근거를 평가한다. 중대한 허위 단정은 비용이 저렴해도 탈락 사유다.
2. **통과한 후보의 비용·속도를 비교한다.** 페이지당 실제 비용, 전체 처리 시간, 지연 분포, 재시도율을 본다. 명목상 모델 크기만으로 저렴하거나 빠르다고 가정하지 않는다.
3. **운영 환경에서 다시 확인한다.** OpenRouter 성적은 사내 DGX Spark의 메모리·처리량 검증이 아니다. 최종 후보의 실제 런타임·양자화·동시 처리 조건으로 같은 자료를 다시 실행한다.

초기 수치 기준은 [공통 블록 평가 설계](../common-block-design/EVALUATION.md)에 있다. 현재 D-069와 스캔 표 정답은 검수 전 개발용 주석이며 사진·복잡한 표·차트 자료도 더 필요하다. 이 대표 시험만으로 전체 시각 자료를 검증했다고 판단하지 않는다.

후속 실행에 필요한 사용자 설정은 OpenRouter 키의 로컬 환경 변수 설정과 시험 비용 한도다. 키는 문서·로그·채팅에 기록하지 않는다. 이번에는 키 설정이나 과금 호출을 진행하지 않았다.
