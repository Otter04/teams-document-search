# 메타데이터 기준과 날짜 역할 보강

2026-10-18 · rules-0.2.0 · 모델/API 호출 없음.

원본, 공통 블록, 기존 정답과 이전 실행을 보존한다. 16건 라벨 불일치와 13건 초안 날짜 보류의 원인은 별도 감사 자료에서만 조사한다. 추출기는 생성기·정답·문서별 보정표·파일 수정시각을 입력으로 사용하지 않는다.

- 문서일자: 현재는 문서에 명시된 대표 날짜다. 모든 문서에서 작성일·제출일·체결 완료일을 뜻하지 않는다. 적용 근거와 역할을 `date_context`에 기록한다.
- 명시적 문서 작성일/작성일/문서일자/견적일자/메일 Date를 우선한다. 같은 역할의 날짜가 여럿이거나 명시 날짜끼리 충돌하면 보류한다. 다른 역할인 계약 체결부 날짜와 계약기간은 별도로 보관한다.
- 명시적 문서 날짜가 없으면 기존 표지·로그 시작·점검일·구성도 머리말 등의 근거를 사용한다. 초안 체결부 날짜만 있으면 문서일자는 계속 `needs_review`다.
- `signing_block_printed_date`는 체결부에 인쇄된 날짜다. 초안/서명본 표시만으로 실제 기명날인 완료나 실제 계약 체결일을 확인했다고 간주하지 않는다.
- 표지 날짜에 하루를 더하거나 초안 체결부 날짜에서 12일을 빼지 않는다. 제출일/작성일의 별도 원본 근거 또는 확정된 업무 정의가 있어야 한다.
- 대상시스템은 문서종류와 무관하게 명시적 대상 표기 또는 제목·파일명의 알려진 시스템명을 사용한다. 메일은 맨 처음 From 헤더 블록의 Subject만 추가 근거로 사용한다. 본문·전달 메일의 임의 시스템 언급은 사용하지 않는다. 명시적 대상시스템 라벨을 우선하고, 제목과 파일명이 충돌하면 보류한다.
- 기존 20개 평가 필드의 값/상태와 추가 사업명은 유지한다. 날짜 근거의 역할과 선택 사유는 schema 1.1.0의 `date_context`로 확장하며 기존 점수 분모에는 추가하지 않는다.
- 상태가 미확정인 날짜는 검색 필터와 확정 날짜 문맥에 넣지 않는다. 새 날짜 역할을 별도 검색 필터로 자동 활성화하지 않는다.

평가: 기존 원본 정답으로 전후 2,200필드를 비교한다. 정답 수정이나 분모 제외로 성적을 올리지 않는다. 규칙 보완은 별도 변형 사례에서 검증하며 실제 110문서에서 값이 변했는지도 공개한다. 청크·색인을 다시 생성해 최신 검색 설정으로 61개 질문을 비교한다. 정답 라벨 검토 16건과 날짜 정의 판단 13건은 별도 목록으로 남긴다.
