4. 문서별 메타데이터 정답과 질문별 정답 문서·필요한 정렬 순서를 작성한다. 정답마다 원문 문구와 페이지·슬라이드·시트/셀·행 등 근거 위치를 남긴다. 명시되지 않은 작성일·제출일을 추정하지 않는다.
5. 원본·질문·정답을 분리하고, 원본 해시·문서군·출처·검수 상태를 기록한다. 검색 결과에 맞춰 정답을 만들거나 수정하지 않는다.
6. [기존 평가 입력 규격](outputs/independent-evaluation-prep-v1/PACKAGE_FORMAT.md)에 맞춘 패키지를 만든다. 원본과 근거를 대조하고 형식·참조·개발 자료 중복 검사를 수행한다. 검수되지 않은 항목은 정답 초안으로 표시한다.

## 유지할 조건

- 유료 API, OpenRouter, 비전·임베딩 모델은 호출하지 않는다. 비전이 필요한 본문은 처리 대기로 분리한다.
- 기존 원본·정답·실행 결과를 덮어쓰지 않는다. 새 자료는 별도 폴더와 버전으로 저장한다.
- 파이프라인과 평가 기준을 동결하고 새 자료를 만든다. 평가 후 개선할 경우 해당 자료를 개발 자료로 전환하고, 최종 확인용 자료를 별도로 유지한다.
- 같은 도구가 만든 합성 자료와 정답만으로 독립적인 사람 검수나 실제 운영 정확도를 주장하지 않는다. 검수자 기록을 임의로 채우지 않는다. 필요하면 실제 독립 검수를 위한 검토 패키지를 남긴다.
- 기존 `work/independent-evaluator-smoke/`는 평가기 작동 점검용 합성 입력이며, 이번 추가 평가 데이터셋의 완성본으로 재사용하지 않는다.

## 완료 기준

새 원본, 질문, 근거가 연결된 메타데이터·검색 정답, 검수 상태, 출처·중복 검사 결과, 실행 안내를 제공한다. 사람이 검수한 정답과 작성된 정답 초안은 명확히 구분한다. 실제 독립 평가 성적은 자료의 독립성과 정답 검수를 확인한 뒤 별도 실행 결과로 보고한다.

## 현재 완료 범위와 남은 인덱싱 작업

최근 완료한 범위는 네이티브 공통 블록 파싱, 규칙 기반 보강, 청킹·BM25 색인, 검색 조건 개선, 파일 수정시각 수집·날짜 역할 검색, 메타데이터 기준 정리, 독립 평가 실행기 준비와 새 합성 자료 제작·첫 평가·후속 규칙 개선이다. [최신 비교 결과](outputs/generalization-review-001/README.md)는 기존 전체 Hit@5 60/61·네이티브 60/60 유지, 새 네이티브 47/47이다. 두 자료 모두 독립 성적은 아니다.

| 구분 | 아직 남은 내용 | 현재 상태 |
|---|---|---|
| 추가 자료 검증 | 정답의 별도 사람 검수, 최종 확인용 자료의 독립성 확인 및 평가 | 새 합성 원본·질문·정답 초안과 첫 평가 완료. 별도 사람 검수 대기 |
| 규칙의 추가 범위 | 미지원 표현·새로운 실제 업무 양식에 대한 확인 | 요청한 주요 개선 완료. H-021 오류코드 1개 미추출, 임의 자연어 전체 지원은 아님 |
| 비전 파싱 | 스캔·이미지·도형 의미를 모델로 읽고 공통 블록에 연결·검증 | 264개 응답 수집·첫 비교 완료. 실패 출력·원문 검수·검색 통합 대기 |
| 모델 기준 청킹 | 선택한 임베딩 모델의 토큰 길이·입력 한도에 맞춰 청크 크기 검증 | 현재 1,200자 기준. 실제 모델 토큰 검증은 미실행 |
| 벡터 색인 | 임베딩 생성·저장 및 BM25와 결합한 검색 비교 평가 | 현재 키워드 색인만 구현 |
| 운영 연결 | Teams/SharePoint 원본 수집, 변경·삭제 자동 반영, 운영 저장소 연결 | 현재 로컬 파일과 스냅샷 색인으로 실행 |
| 선택 기능 | 문서 요약, 문서군·중복·최종본 판정의 채택 여부와 기준 | 미구현. 필요성을 결정한 뒤 진행하며 LLM 보강을 자동 추가하지 않음 |

메타데이터 라벨 불일치 16건은 원문 기준의 별도 정답 버전으로 정리했다. 초안 날짜 13건은 원문 근거가 없어 미확정으로 남겼다. 이를 해결하려고 파일 수정일을 작성일로 대체하지 않는다. 날짜 13건의 미확정은 위 작업 전체가 미구현이라는 의미가 아니다.

파일 최신 수정순 검색은 구현됐지만, 가장 최근 수정된 파일을 승인된 최종본으로 판정하는 기능은 아니다. 독립 평가는 인덱싱 품질을 확인하는 검증 작업이며 문서를 색인하는 처리 단계 자체와 구분한다.
