# 검색 방식의 발전 과정

인덱싱이 끝난 이후 질문을 어떻게 검색 입력으로 만들고 순서를 정했는지 설명합니다. 서로 다른 질문집·후보·정답 기준의 숫자를 연속 개선 성적으로 합치지 않습니다.

## 1. 질문 원문 검색

원문을 Nori/BM25와 임베딩 검색에 각각 전달했습니다. 사용자가 문서 표현을 몰라도 검색할 수 있어야 하지만, 우회적인 질문과 문서 용어 사이의 차이가 남았습니다.

## 2. 단일 재작성

Qwen으로 간결한 검색 문장을 만들었습니다. 불필요한 요청 표현을 줄였지만, 자동 증설 의도를 “증설 없이”로 바꾸거나, 완료 보고 찾기를 보고서 작성 방법으로 바꾸는 문제가 관찰됐습니다. 순위 향상이 의미 보존을 보장하지 않습니다.

## 3. 원문과 재작성 벡터 혼합

두 벡터를 정규화하고 가중 평균한 뒤 다시 정규화했습니다. 중앙값이나 순위 평균이 아닙니다. 원문 25/50/75%를 비교했으나 모든 질문에서 이득은 아니었습니다.

## 4. A·B 표현 벡터 결합

원문의 전체 요구를 유지한 두 표현을 만들고 50:50 결합했습니다. 요구를 A·B에 절반씩 나누는 것이 아닙니다. 원문 벡터를 정상 의미 검색에서 제외했지만 키워드와 리랭커에는 원문을 사용합니다.

2026-11-05 동일 조건의 의미 검색 비교:

| 방식 | 필수 근거 상위20 | 상위50 |
|---|---:|---:|
| 원문 단독 | 70/82 | 77/82 |
| A·B 결합 | 71/82 | 80/82 |

A·B만 성공한 질문뿐 아니라 원문만 성공한 질문도 있었습니다. 이후 새 API 재작성의 결과와 이 회차 숫자를 혼동하지 않습니다.

## 5. RRF 다음 전용 리랭커

키워드·의미 후보를 가중 RRF로 결합하고 상위 후보를 전용 리랭커에 전달합니다. Min-max와 비교 후 현재 기준에서 Min-max를 제외했습니다. 2026-11-11 전체 새 API 실행에서는 리랭커가 후보 안의 정답 근거를 상위로 올리는 효과를 확인했습니다. 후보에 없는 정답을 복구하는 기능은 아닙니다.
