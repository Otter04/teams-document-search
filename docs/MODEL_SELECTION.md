아래 선정 근거의 OpenRouter 시험은 **DeepInfra FP8**, Orin 검증은 **AWQ 4비트**이므로 동일한 실행 버전으로 취급하지 않는다. Orin에는 입력·출력 합계 **49,152토큰**, 평가 최대 출력 **16,384토큰** 설정을 적용했다. GPU 메모리 비율 인자는 80%로 유지하되, 캐시 할당 오류 처리 후 KV 캐시는 8GiB로 직접 지정해 자동 계산보다 우선한다.

정확한 경로·실행 설정과 과거 환경 점검은 [Orin 서빙 모델·환경 기록](ORIN_ENVIRONMENT.md), 검증 결과는 [Orin 전체 평가 기록](../outputs/orin-evaluation-run-001/README.md)을 참고한다. 이 추가 기록은 모델 선정 당시의 점수와 응답을 변경하지 않는다.

## 선정 이유

1. 전체 비전 시험에서 원문 정보를 보존하고 공통 JSON으로 전달하는 성과가 더 좋았다. 반복 출력도 적었다.
2. 같은 문서를 제공한 보강 시험에서 메타데이터 값 일치와 요약 핵심 사실 회수가 상대적으로 나았다.
3. 비전과 보강을 한 모델로 운영하려는 프로젝트 방향에 맞춰 두 단계의 근거를 함께 판단했다. 특정 문서·작은 재시험에서 VL이 더 나았던 결과도 보존한다.
4. 요약 평가의 엄격함과 프롬프트의 한계를 감안해도, 현재 근거로 공통 모델을 Qwen3.6으로 정하고 다음 설계 단계로 진행하기로 했다. 보편적인 모델 순위나 모든 업무에 대한 우월성 주장은 아니다.

## 근거 2: 문서 보강 시험

20문서 × 2모델 × 1회, 총 40회 호출했다. 두 모델에 동일한 공통 블록·사전·프롬프트·JSON 규격을 제공했다. 17개 네이티브 문서와 검수된 스캔 3문서의 공통 텍스트를 사용했으므로 비전 판독 성능이 섞이지 않은 보강 비교다. 메타데이터는 23필드 × 20문서, 추출 가능한 확정 값 190개, 사전 요약 핵심 사실은 61개였다.

보강 시험은 DeepInfra FP8, temperature=0.7, top_p=0.8, top_k=20, presence_penalty=1.5, repetition_penalty=1, min_p=0, frequency_penalty=0, seed=42, max_tokens=16384였다. Qwen3.6은 reasoning=false였고 제공자 fallback 및 자동 재호출은 없었다. 이 설정은 시험 조건이며 DGX Spark의 운영 설정을 확정한 것은 아니다.

값 일치와 요약은 전달 실패 응답도 읽은 내용 진단이다. VL의 JSON 제어문자 오류 1건도 내용만 확인했으며 JSON 성공으로 바꾸지 않았다. 정식 평가기는 문서 전체 검증 실패 시 해당 문서의 전달 가능한 값 점수를 0으로 두므로, 정식 근거 포함 회수는 22/190 대 0/190이었다. 위의 높은 값 일치를 정식 전달 성공률로 해석하지 않는다. 두 모델 모두 사전 보강 합격 기준에는 미달했다.

총 보고 비용은 $0.13030800이다. 응답 시간 중앙값은 약 16초 대 107초였으나 VL의 뒤쪽 요청 일부를 병렬 실행해 동시성 조건이 다르다. 순수 모델 속도나 Spark 성능 비교의 근거로 쓰지 않는다.

### 실제 사례

- **H-006 금형온도 제안서:** Qwen3.6은 200ms 수집과 읽기 전용 ERP 연동을 요약했다. VL은 상태·거래처·금액·합성 자료 고지를 요약하면서 업무 조건을 빠뜨렸다.
- **H-007 냉장입고 제안서:** Qwen3.6은 라벨/온도 연결, TMS 집계 교환, 센서 지연/단절 구분을 모두 담았고 VL은 세 핵심 사실을 빠뜨렸다.
- **D-102 서버 교체 계약서:** Qwen3.6은 고객 대신 공급자를 거래처에 넣었고, VL은 맞혔다. Qwen3.6이 모든 항목에서 더 좋은 것은 아니다.
- **H-021 점검 메모:** VL은 오류코드를 필드에 넣었고 Qwen3.6은 요약에 언급하면서 필드는 비웠다. VL도 근거·상태 검증에는 실패했다.

## 요약 점수의 해석과 설계 한계

현재 54.10%는 요약 전체 품질을 하나의 점수로 평가한 결과가 아니다. 사전에 선정한 핵심 사실의 조건·수치를 요약 본문이 완전히 보존한 비율이다. 예를 들어 H-006의 ‘금형 8기 대상이며 성형기 12대 사업과 별개’는 복합 항목이다. Qwen3.6이 금형 8기와 별도 사업을 요약했어도 ‘성형기 12대’가 빠져 그 항목을 0점으로 처리했다.

실제 요약 지시는 최대 3문장 안에 목적·범위·제외 사항·조건·관찰 결과 중 중요한 내용을 담으라는 포괄적인 문단이었다. 메타데이터 23필드 추출과 함께 요청했으며, 요약에서 메타데이터 반복보다 업무 조건을 우선하라는 구체적 순위와 좋은/나쁜 예시는 없었다. 따라서 모델 능력, 프롬프트, 복합 항목의 전부 충족 방식이 모두 결과에 영향을 주었다.

후속 설계에서는 요약 목적과 우선순위를 명확히 하고, 복합 사실을 나눠 부분 성과를 인정하되 의미를 바꾸는 수치·조건·부정 오류는 엄격히 볼 수 있다. 이는 **아직 적용하지 않은 개선 방향**이다. 기존 프롬프트·정답·점수는 변경하지 않았다.
