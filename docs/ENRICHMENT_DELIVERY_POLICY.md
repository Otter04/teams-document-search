# 문서 보강 전달 기준 v2 및 평가 결과 재사용

기록일: 2026-10-20. 사용자 요청에 따라 단순한 근거 표기 오류를 정리하고, **저장된 응답만 재평가**했다. 기존 Orin 생성 작업은 계속 진행하며, 이번 기준 변경을 위한 추가 모델 호출은 하지 않았다.

## 무엇을 수정했는가

LLM 프롬프트·모델·생성 설정은 그대로다. **LLM 응답 이후의 검증기에 제한적인 표기 정리 단계를 추가**했다. 원응답은 수정하지 않고, 정리된 사본과 변경 위치·전후 내용을 따로 기록한다.

예를 들어 실제 파일명이 `MES 생산수집 용역 계약서_초안.docx`인데 근거에 `file_name: MES 생산수집 용역 계약서_초안.docx`라고 쓴 경우, 설명용 `file_name:`만 제거한다. 다음 조건을 모두 만족해야 한다.

1. 정상 종료한 엄격 JSON 응답이고 기본 규격·문서 ID가 맞는다.
2. `kind=source`이며 참조가 `file_name`, `source.file_name`, `document.source.file_name` 중 하나다.
3. 허용된 파일명 설명 접두어를 뺀 인용이 입력의 **전체 파일명과 일치**한다. 유니코드 NFC와 양끝 공백만 정리하며 내부 공백·문장부호는 보존한다. 유사 문장 검색은 하지 않는다.
4. 값·상태·근거의 종류·본문 내용을 바꾸지 않는다. 참조 별칭만 실제 `file_name`으로 통일한다.

필드 근거, 보류 후보의 근거, 요약 근거에 같은 규칙을 적용한다. 본문을 찾아 다른 근거로 바꾸거나, 틀린 값을 정답으로 채워 넣지 않는다. 일부 파일명만 맞거나 다른 문구가 추가돼 있으면 정리하지 않는다.

## 계속 차단하거나 보류하는 항목

- 없는 출처, 다른 파일명, 실제 블록과 일치하지 않는 인용, 숫자·부정 표현이 바뀐 인용.
- 잘린 응답, HTTP 실패, JSON 문법 오류, 중복 JSON 키, 규격 오류.
- 작성일·표지일의 역할 혼동, 값과 읽기 상태의 모순, 필요한 보류 사유 누락.
- 오프라인 정답 대조에서 확인되는 잘못된 값, 의미가 미확정인데 임의로 채운 값, 값은 맞아도 지지 근거를 확인하지 못한 항목.

마지막 항목은 **검수 정답이 있는 평가 자료에서 수행하는 추가 검사**다. 표기 정리 함수에는 정답을 전달하지 않는다. 운영 자료에서는 정답을 미리 알 수 없으므로 규칙값과의 충돌 검사·근거 검토·의미 검수가 계속 필요하다. 모든 의미 오류를 자동으로 알아내는 기능을 구현했다고 주장하지 않는다.

## 점수 해석

값 일치는 필드별 내용 진단, 전달 기준은 문서 전체의 형식·인용·상태 검사다. 표기 정리가 안전하게 끝나도 다른 오류가 하나라도 남으면 문서 전체 전달은 계속 보류한다. 오류 필드를 삭제하거나 실패를 성공으로 재분류해 점수를 높이지 않는다.

이번 비교는 기존 v1 결과와 v2 결과를 함께 기록한다. 기존에 사용자에게 보고한 17문서는 별도 고정 범위로 비교하고, 작업 중 추가 저장된 문서는 별도 전체 범위로 제시한다. 전체 평가가 끝나기 전 결과는 중간 결과다.

요약 문장의 사실성·핵심 내용 포함률은 별도 원문 검수 대상이다. JSON과 메타데이터 검사를 통과해도 요약 검수 완료나 운영 자동 반영 승인을 뜻하지 않는다.

## 지금 하는 평가와 인덱싱의 관계

인덱싱의 전체 흐름은 **수집 → 파싱 → 문서 보강 → 청킹 → 검색 색인 저장**이다. 현재 Orin 작업은 이 중 LLM이 맡는 **비전 파싱 132장, 문서 보강 20문서**를 시험한다. 기존 네이티브 처리·검색 개발 결과는 따로 있으나, 이번 Orin 결과를 모두 연결한 전체 인덱싱은 아직 실행하지 않았다.

두 단계는 독립 비교다. 보강에는 기존 검수된 공통 입력을 넣었으며, 이번 Orin 비전 결과를 바로 넣지 않았다. 특히 스캔 입력 3문서는 원본을 대조해 AI가 검수한 공통 입력이며, 독립된 사람의 정답 검수나 이번 Orin 모델의 자동 파싱 결과로 가장하지 않는다.

## 같은 자료를 나중에 인덱싱할 때 재사용하는 기준

이미 생성한 결과를 재사용해 중복 모델 계산을 줄이는 방향이 적절하다. 다만 **검색 색인을 재사용하는 것이 아니라, 색인을 만들기 전 단계의 파싱·보강 결과를 재사용**하는 것이다.

| 대상 | 재사용 조건 | 다음에 해야 할 일 |
|---|---|---|
| 네이티브 파싱 결과 | 원본 내용·파서·규격 동일 | 기존 공통 블록 사용 |
| 비전 결과 | 같은 렌더 이미지·네이티브 문맥·모델/양자화·프롬프트·생성 설정·응답 규격, 검증 통과 | 보류 단위·경고를 확인하고 공통 블록에 연결 |
| 문서 보강 결과 | 실제 공통 입력과 사전·프롬프트·모델/양자화·설정이 동일, 검증 통과 | 규칙 메타데이터와 충돌을 확인하고 병합 |
| 실패·경고 결과 | 저장은 유지하되 검수 필요 | 규칙 보정 또는 검수 후 사용; 불명확하면 계속 보류 |
| 청크·검색 색인 | 위 단계 결과를 실제로 연결한 뒤 생성 필요 | 이번 LLM 평가 완료만으로 만들어졌다고 간주하지 않음 |

기존 파일에 새 비전 블록을 추가하면 **보강 입력이 달라진다**. 이전에 만든 보강 결과를 그대로 최신 결과라고 쓰면 새 표·그림 내용이 빠질 수 있다. 입력 해시가 같을 때만 전체 응답을 재사용하며, 달라진 문서는 영향 검토 후 재보강 대상으로 남긴다. 모델·프롬프트·규격이 바뀐 경우도 동일하다.

수집된 파일 수정시각·경로·접근 권한은 실제 수집 시점에 갱신하고, 오래된 평가 환경의 메타정보를 운영 정보로 복사하지 않는다. 내용이 같은 파싱 결과를 재사용하더라도 보강 입력에 포함되는 값이 달라졌다면 입력 동일성 검사를 다시 해야 한다.

예비 데이터셋과 **다른 실제 회사 문서**에는 예비 문서의 추출값을 가져다 쓸 수 없다. 그 경우 재사용하는 것은 파서·프롬프트·검증 규칙·실행기다. 같은 원본을 다시 인덱싱하는 경우에만 해당 문서의 검증된 결과가 재사용 대상이다.

현재 저장된 요청·응답 해시와 원본 기록은 재사용 판단의 기반이다. 운영용 자동 캐시 조회·병합·색인 연결 기능은 아직 이 작업에서 구현하지 않았으며, 위 조건을 적용해 후속 연결해야 한다. 이번 작업은 검증 기준 보완과 기존 응답 재평가까지다.

## 110문서 대상 선정·시간 계산 후속 기록

2026-10-20 사용자 선택은 **검색 메타데이터 우선, LLM 요약은 필요한 문서만**이다. [110문서별 분류와 시간 재산정](../outputs/indexing-plan-110-001/README.md)에 현재 원문·규칙 결과·저장 응답을 대조한 결과를 기록했다. 같은 설정의 요청 캐시 재사용과, 기존 OpenRouter의 검수 후보를 출처를 보존한 별도 산출물로 재사용하는 경우를 구분했다. 후자는 Orin 평가 응답을 대체하지 않으며 운영에 실제 반영한 것도 아니다.

## OpenRouter 비전 재사용 채택·교정 후속 결과

같은 날 사용자 요청에 따라 기존 67장을 재사용 대상으로 채택하고, 남은 54장을 추가 모델 호출 없이 처리했다. 규칙 교정 49장, 원본 이미지 대조 교정 4장, 누락 내용 직접 복원 1장이다. 원문 문구·표·노드·원문 기준 연결 관계에 대해 **121장 공통 JSON 준비본**을 별도로 저장했다. 알려진 추출·전달 오류 해결을 위한 필수 재호출은 현재 0장이다.

이것은 평가 정답을 바꾸거나 원래 모델 실패를 성공으로 재분류한 작업이 아니다. 특히 잘린 D-102 2쪽의 추가 내용은 원본 직접 복원임을 기록했다. OpenRouter FP8 원응답과 모델 성적은 보존했으며 Orin AWQ4 비교 평가에 대체하지 않았다.

모델의 자유 설명 103문장은 보존하되 사실 색인에서는 검수 전 제외하도록 별도 정책과 목록을 만들었다. 예를 들어 서버 4대를 4계층으로 설명한 문구는 원문·구조가 맞아도 자동 승인하지 않는다. 재사용 수치는 모든 설명의 사실 검수를 마쳤다는 뜻이 아니다.

[재사용 검수 보고서·54장 목록·필수 재호출 목록](../outputs/vision-reuse-review-001/README.md)을 후속 연결의 기준으로 사용한다. 이전 54장 전부 재호출 시 약 3.4시간 계산은 역사적 가정으로 남긴다. 이번 준비본을 채택하면 해당 재호출은 필요 없지만, 규칙 보강 재적용·청킹·색인 연결과 의미 검수 시간은 별도다. 전체 인덱싱은 아직 실행하지 않았다.
